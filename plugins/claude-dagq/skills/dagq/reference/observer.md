# Findings: what the observer saw, and deciding them with the user

The observer is a headless job the supervisor starts every `--observe-interval` seconds (default 3600; 0 disables it) and once a day for the last 24 hours (`--observe-daily`). It reads `stats` since its cursor, the `open` / `proposed` findings, the latest notes, the open asks and the graph, and records what goes wrong as **findings** (ADR-0044 decision 18). It writes no note, goal or task, and it never changes a run, task or goal; the queue refuses that from `DAGQ_ROLE=observer`. When nothing but its own events happened since its last successful observation, it starts no agent and records a `skipped` observation. Run it by hand with `"$DAGQ" observe [--since CURSOR] [--daily]`, or print its prompt with `--dry-run`.

## What a finding is

One record per problem: `kind` (a slug: `stall`, `failure`, `wait`, `capacity`, `threshold`, `conflict_hotspot`, ...), a target (`run`, `task`, `goal` or `queue`) and a `subject` within it, `summary` and `detail`, `impact` (`high` / `normal` / `low`), `first_seen` / `last_seen`, `occurrences`, `evidence` (event IDs), `status` (`open` / `proposed` / `resolved` / `dismissed`, with `status_reason`), the linked proposal, and the mark asking for one (`propose_reason`). The same kind, target and subject recorded again updates the finding instead of adding one: new evidence adds an occurrence and moves `last_seen`, a `resolved` finding becomes `open` again (the remedy did not work), and a record that changes nothing writes nothing.

## Read

- `"$DAGQ" findings` lists the `open` and `proposed` findings, biggest impact first (impact, occurrences, last seen), each with `proposal_status` and `open_asks`. `--all` or `--status S,...`, `--kind K,...`, `--task ID` / `--run RUN_ID` / `--goal ID` / `--queue` narrow it; `findings ID` shows one in any status; `--full` adds the evidence events whole (`evidence_events`).
- `"$DAGQ" events --all --full --run RUN_ID` (or `--task`, `--goal`, `--kind KIND`, `--since` / `--until`) reads the events around a finding; `"$DAGQ" timeline RUN_ID` shows where a run's time went, with a reason for each gap (`reference/inspect.md`).
- `"$DAGQ" observe --history [--limit N]` lists the observations, newest first: `outcome`, `skipped`, `input: {since, through}` (the events it read), the findings it recorded or updated, its asks, `duration_secs` and its `dir` under `<queue dir>/observer/` (`prompt.md`, `input.json`, `output.log`). An outcome other than `succeeded` left the cursor, so the next observation reads the same window again.

## Where a finding goes

1. **A proposal, without a person.** The observer marks a finding that needs a remedy (`finding record --propose '<why>'`: it recurs or costs much). The supervisor then opens a runtime planner for it, which checks `search` / `related` for work already queued or done and either submits tasks on an open goal or a new draft goal (`submit ... --finding ID`: the finding becomes `proposed`), dismisses it, or asks the person with a `planner_question`. Plan review checks the proposal like any other and asks the person only on a `concern`. When the proposal ends the runtime marks the finding `resolved` (a task completed) or `open` again without its mark (everything was canceled). After three runtime planners left it undecided, the inbox gets `decide the finding in a planner`.
2. **An ask, for a person now.** The observer raises `ask --kind blocked --finding ID --because <reason>` (why a person is needed, ADR-0047 decision 41) when a person must decide now, one open ask per finding. The runtime adds the options `propose` (make it a proposal: the runtime marks the finding and a runtime planner takes it as in 1) and `dismiss`, and applies those answers itself; the inbox shows the ask. A `stalled` ask carries `propose` too, which records a finding for the stalled run first.
3. **Decided in a person's planner.** With the user, read `findings` and decide the ones that matter: submit a proposal for it yourself (write the goal or tasks, `lint`, `submit ... --finding ID`), leave it to the observer's mark, or drop it with `"$DAGQ" finding dismiss ID --reason '...'`. `finding resolve ID --reason '...'` closes one that no longer happens. Do this for a `decide the finding in a planner` attention too.

A note (`note` / `notes`) stays the person's and planners' free-text memo; nothing waits on it. Observers of older binaries wrote notes and draft goals; those remain as records: decide such a draft goal with the user like any draft (`submit --goal ID`, or `goal close ID --verdict abandoned`).
