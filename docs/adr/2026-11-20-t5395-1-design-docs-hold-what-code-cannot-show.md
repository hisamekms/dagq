# ADR-t5395-1: 設計文書にはコードを読んでもわからないことだけを書く

## Context

細部の置き場を設計文書から doc comment に移すだけでは、コードの書き写しが残る。
設計文書のために実装を差し戻す基準と、その判定をどこまで機械で行うかを定める。

## Decision

1. **書く基準。** 設計文書にはコードを読んでもわからないことのうち、次の三つだけを書く。
   - (a) 複数の集約や係をまたぐ順序・一貫性・受け渡し・途中の失敗。集約どうし、集約と係、係どうしを含む。
   - (b) 複数の BC をまたぐ受け渡しと持ち主。queue・supervisor・service・worker の境目を含む。
   - (c) コードからわからないインフラ。process の配置、disk 上のファイルと置き場、外部（GitHub・Claude・Codex・podman）との境目、更新と引き継ぎの手順、壊れ方と復旧を含む。

   コードの単位は一つの集約か、集約に属さず、command・job・役割から直接呼ばれる入口と自分の状態または出力を持つ一つの係である。
   store の行から帳簿を作り直す係や、統計・指標・報告をそれぞれ作る係も一つずつ数える。
   その単位からだけ呼ばれる補助の部品は、いくつ登場しても同じ単位に含む。集約の一覧は集約と BC の境目を確かめる補助であり、一覧にない係にも同じ判定を当てる。
   三つの基準のいずれにも当たらない単位内部の状態の移り方・欄・規則・関数名・処理の手順・部品間の順序や受け渡しは書かない。
   経緯は ADR と git の履歴だけに置く。
2. **初期値。** 迷ったら書かない。
3. **コードの細部。** 型・名前・enum・構造でコードを宣言的にする。名前・欄・既定値の意味はコードの型・名前・test が持つ。コードを見てわかる事実を doc comment に書き写さず、設計文書から消した記述もそこへ移さない。
4. **範囲。** 文書の規則が当たるのは設計文書の置き場（`docs/design/`）に限る。開発規則・利用者向けの skill・運用と手動スモークの手順・ADR には、書き写しと経緯に関するそれぞれの規則を引き続き当てる。
5. **検査と review。** 機械の判定を主とし、機械で見られない箇所を AI が判定する。集約と BC の一覧は、集約の型の目印と BC を引く所有の表から生成し、手で書かない。
   - 識別子と参照の実在の unit test は、本文の inline code に書かれたコードの識別子（関数名・型や event の欄・enum の値・const の名前）を落とす。名指した module の path・集約・BC・型は、実在しない名前への参照を落とす。既存分は文書ごとの許容数と許容一覧を引き継ぎ、前の版との比較で値の引き上げや項の追加を落とす。
   - 大きさの検査は本文の byte 数と一行の長さの上限を見て、文書ごとの上限は下げるだけとする。従来の許可の一覧と層を直した文書の一覧は退役する。
   - 大きさの検査は本文のタスク番号も落とす。frontmatter・fenced code block・inline code・リンクの行き先（`](` から次の `)` までと、行頭の参照リンク定義 `[名前]: ` の後ろ）を除き、task かタスクに番号が続く形を数える。リンクの表示文言は数え、数字の直後が件・つ・個・本・回の形は除く。
   - 一文一行の検査は、本文の一行に複数の文が続く形を落とす。
   - cargo を流せない review の前ふるいは、差分が足した・変えた行の inline code が閾値以上の行（A）と、行自体か字下げした続きの行に inline code を含む足した・変えた箇条が閾値以上続く塊（B）を落とす。定義と閾値は引き継ぐ。
   - 直し対象の印の検査は、直すタスクの番号がない印を落とす。直すタスクの検証は、自分を指す印が残っていれば落とす。

   設計の review の agent が DS-1 で判じるのは、差分が足した・変えた行が決定1の一つのコードの単位で閉じる話を書いたかだけである。
   識別子・大きさ・本文のタスク番号・印・経緯・差分が消した行は DS-1 の判定外とする。消した行の判定は決定6 (v) が持つ。
   機械の検査も DS-1 も拾わない経緯は全体の review が指摘する。「以前は」「〜から変えた」の文や、goal・request・ADR の番号、日付・件数で書く変遷を含む。
6. **文書を理由に差し戻す条件。** コード・accepted の ADR・test を正とし、設計文書はまたがる話の地図として読む。run の review が文書を理由に差し戻すのは次の場合に限る。
   - (i) 差分が変えた文書が差分・コード・accepted の ADR・test と食い違う。
   - (ii) 差分が accepted の ADR・test・コードの持つ不変条件・約束・境界を破る。
   - (iii) 差分が設計文書に足した・変えた行が機械の検査か DS-1 に当たる。
   - (iv) 差分が足した・変えた行に、この repository の従来の規則が禁じる設計文書以外でのコードの書き写し、または同じ規則が当たる文書での経緯がある。設計文書の書き写しは (iii) が受け持ち、機械が拾わない経緯は全体の review が指摘する。この repository が何を文書の欠陥とするかを決める ADR-t2352-1 決定1の (a) を保つ。
   - (v) 予算に収めるために、差分と関係のない既存の地図の事実（知りたいことからコードへの入口、コードから読めない約束と落とし穴、規則、他に記述のない事実）を設計文書から消し、同じ事実が他の文書にも既存の doc comment にも残らない。従来の予算のための削除の禁止を条件のまま引き継ぎ、全体の review が消した行・削除の目的・事実が残る場所を確認する。

   (v) では、予算に収める目的のない削除、言い換えや参照先への短縮で事実が残る変更、既存の doc comment に同じ事実が残る削除を対象外とする。一つの単位で閉じる記述・重複・経緯・コードから読める列挙の削除や、直し対象の印を置くために食い違う句や節を削る変更も対象外とする。
   差分が設計文書とだけ食い違うときは設計文書の直しを `docs_drift` の follow_up にする。
   plan review は同じ基準を使う。受け入れ条件が設計文書に必須とする記述をまず機械の検査の境界に当て、該当すれば revise にする。
   機械が拾わなくても、一つの集約か集約に属さない一つの係で閉じる状態の移り方・欄の意味・規則・手順や内部の部品間の順序・受け渡しを必須にするなど、DS-1 に明確に当たれば revise にする。識別子を使わない地の文も含む。
   DS-1 に当たるか迷う記述は revise の理由にせず、設計文書とだけ食い違うことは revise・concern の理由にしない。
7. **形。** 設計文書の本文は一文一行とし、同じ段落への追記の衝突を減らし、検索で文を拾えるようにする。
8. **当たり始め。** 新しい文書の決まり（文書の規則と run の review の規則）と機械の検査は、それぞれが main に着地した後に始まる review と plan review にだけ当てる。
   worker の prompt はこの当たり始めの対象外とし、新しい決まりへの対応は後続の変更に委ねる。
   それより前に review を通った run、着地待ちの run、動いている worker、置き換わっていない review の agent と旧い worker の prompt の扱いは決めず、食い違いを受け入れて review し直さない。
   既登録のタスクを一件ずつ書き直したり移行の分類を設けたりする手間と、一時の不揃いの害を比べ、人は BETA の間は一時の不揃いを受け入れると決めた。

## 置き換えとAmendsの判断

- **ADR-t1942-1。** 決定1（文書の層）・2（書かないもの）・3（細部の置き場）・4（今の姿の持ち方）・6（予算）・7（許可の一覧）を改めるため、全体を置き換える。決定5の一文一行は本 ADR の決定7に引き継ぐ。
- **ADR-t598-1。** 決定3・4は、細かい事実を型・名前・enum・構造でコードに持たせ、設計文書は決定1の (a)(b)(c) に限る形に改める。他の決定は保つ。
- **ADR-t1942-2 決定2。** worker への二つの指示を改める。設計文書を更新するのは決定1の (a)(b)(c) に当たる変更と食い違いの解消に限る。意味を定義のそばの doc comment に書く指示は撤回し、名前・欄・既定値の意味はコードの型・名前・test が持つ。
  担当範囲内の候補文書の食い違いは直し、範囲外では `docs_drift` の follow_up にする。名前がないだけならずれとせず、名前・欄・既定値を足すために設計文書を追記しない。経緯を書かず、日付だけの差分を強いず、照合の時点と更新した文書・節または更新不要の理由を summary に記録する規則も保つ。
- **ADR-t1942-2 決定4。** 指摘の担当のうち、設計文書の書き写しだけを機械の検査と DS-1 に移す。経緯の指摘は保ち、本文のタスク番号は決定5の境界で大きさの検査が落とし、残りは全体の review が指摘する。設計文書以外の書き写しは全体の review に残す。
  両方向の照合、文書の差分だけで正しいとしないこと、欠けの指摘、名前の欠けだけをずれとしないこと、書き写しや経緯のうち差分が入れたものだけを指摘することは保つ。決定1・3も保つ。
- **ADR-t2352-1。** 決定1 (b) の差し戻しを本 ADR の決定6 (ii) に改める。(a) の repository による文書の欠陥の定義は保ち、設計文書以外の書き写しと文書への経緯の混入は決定6 (iv) が引き継ぐ。決定2〜4の、触っていない文書の古い記述を follow_up にし、runtime が draft にし、汎用の部分だけを runtime が持つ方針を保つ。
- **ADR-t2389-1 決定2。** 書き写しと経緯の混入を `docs_drift` として指摘する repository の run の review の規則のうち、設計文書の書き写しの担当を改める。経緯の指摘と、汎用の照合を runtime が持つことは保つ。
- **ADR-t2389-1 決定3。** 第1文のうち設計文書の書き写しの指摘を機械の検査と DS-1 に移し、最後の文の機械の検査の範囲を決定5に改める。全体の review は書き写しの判定を繰り返さない。
  全体の review に残すのは、summary の探した名前の確かめ、名前の欠けだけをずれとしない規則の当て方、A-153・A-261・A-260、設計文書以外の書き写しと経緯、設計文書の経緯のうち大きさの検査が本文のタスク番号として拾わない形、決定6の差し戻しの条件である。
  設計の照合専用 agent の退役と文書の照合用の規則の統合、決定1の照合を全体の review だけで行う方針と決定4を保つ。
- **ADR-t1992-1。** 決定6の直後にある番号のない文だけを改める。出力の欄名・フラグの綴り・JSON の形はコードの型・名前・test が持ち、設計文書にも doc comment にも書き写さない。決定6の読み取りの境界と他の決定は保つ。

ADR-t1428-1 決定4・5は、後の ADR が改めた決定を上記の範囲で引き継ぐ。
生成する集約と BC の一覧は BC ごとの集約の型の名前と module の path だけを持つ。主となる table は test 側の所有の表だけに置き、table の持ち主から集約の BC を引くために使う。表や store の module の context を一覧に載せないため、ADR-t2287-1 決定1 と ADR-t2391-1 の境界の記録の置き場は保つ。

## Alternatives

- **経緯も DS-1 で判じる。** 本文のタスク番号は機械で判じられ、残りの経緯は全体の review が指摘するため、DS-1 に含めると同じ指摘を繰り返す。
- **予算に収めるための削除を設計の agent に残し、別の規則コードを割り当てる。** 削除の目的と、同じ事実が別の場所に残るかは差分全体との照合が要るため、全体の review に任せる。

## Consequences

- 設計文書からは単位をまたぐ約束とコードからわからないインフラを辿れ、単位の内部を変えるときはコードと test で確かめられる。
- 機械の検査を整える作業が要り、既存の識別子・参照の許容枠と文書の上限は、記述の整理に合わせて下げていく。
- 全体の review には、機械が拾わない経緯と、予算のために消した事実が他の場所に残るかの確認が残る。
