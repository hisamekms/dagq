# ADR-t2892-1: 着地の絞ったITは、足したsrcのファイルと広い表の項目をCIに任せる

## Context

[ADR-t1925-1](2026-10-07-t1925-1-landing-verifies-unit-tests-and-selected-integration-tests-and-ci-is-the-final-gate.md)決定2は、着地の検証のITをCIの夜間の対応表（ファイル→IT）と差分から選び、絞ったITの見込みが上限を超えるとき・共通のファイル（多くのITに当たるファイルと、表が判断できないファイル）に触れたとき・表が取れないか古すぎるときにITを全部流すとした。
表が判断できないファイルには、表のcommitのtreeに無いsrcのファイル（差分が足したファイル）を含めていた。

切り替えの後の7日では、着地の検証の93%がITを全部流し、verifyは短くならなかった（[前後比較](../plans/landing-verify-switch.md)）。
代替案をその記録に当てた比較（[代替案の比較](../plans/landing-it-alternatives.md)）では、足したファイルの扱いだけを変えても、同じ差分が多くのITに当たる表の項目にも触れていて、理由が上限超えに移るだけだった。
表はファイルの粒度で、srcのファイルの過半がITの大きな割合に当たる。
効いたのは、多くのITに当たる項目から選ばないことだった。

見逃しはCIが最終関門で拾い、事故は許容する（goal 157の人の決定、ADR-t1925-1決定5）。
amendsにするのは、ADR-t1925-1の8つの決定のうち決定2の全部流す条件だけが変わり、他の決定（unit test全件・既に落ちているtestを外すこと・設定での置き換え・CIを最終関門にすること・workerの手元の検証）は変わらないため（[ADR-t1091-1](2026-09-30-t1091-1-amend-or-replace-by-number-of-decisions.md)）。

## Decision

ADR-t1925-1決定2の「ITを全部流す条件」を次のとおりにする。必ず含める2つ（差分で足した・変えたtestのファイルが定めるITと、表に無いIT）は変えない。

1. **表のcommitのtreeに無いsrcのファイルは、ITを全部流す理由にせず、表から何も選ばない。**
   そのファイルを通るITのうち、差分のtestと表に無いITに入らないものはCIに任せる。
2. **表が多くのITに当てるファイル（広い項目）は、表から何も選ばない。**
   その項目のITのうち、差分の他のファイルの項目・差分のtest・表に無いITに入らないものはCIに任せる。
   広いかどうかは、表のITの本数に対するその項目のITの本数の割合で測る。上限の値と根拠は測定の「決めたこと」に拠る。
3. **ITを全部流す条件は、絞ったITの見込みが上限を超えるとき、共通のファイルに触れたとき、表が取れないか古すぎるときの3つになる。**
   共通のファイルは表が判断できないbuildの入力と共通のfixtureの一覧で、srcのファイルを含めない。上限と古さの上限の物差しはADR-t1925-1決定2のまま。
4. 着地の検証は、CIに任せたファイルを理由とともに出力に残す。

## Alternatives

- **今の規則のまま**: 見逃しは最も少ないが、記録では93%がITを全部流し、切り替えの狙い（verifyの短縮）が実現しない。
- **足したファイルを、そのmoduleを宣言する親のmoduleか同じdirectoryのファイルの項目で選ぶ**: 親の項目もたいてい広く、全部流す割合はほとんど減らなかった。規則を足す得が無い。
- **広い項目の上限を高くする**: 全部流す回の大半が上限超え（上限の少し下の項目の和）のまま残り、絞った回でCIに任せる割合は変わらない。
- **広い項目の上限をもっと低くする**: 全部流す回はわずかしか減らず、まだ選び方の手がかりになる項目まで捨てる。
- **表を行の粒度にする**: 当たりの精度は上がるが、夜間のjobと表の形を変える別の変更になる。この決定はそれを妨げない。
- **全部流す上限の割合を動かす**: 上限超えの回は上限の約2倍の見込みで、割合を多少動かしても全部流す回は減らない（前後比較の結論1）。

## Consequences

- 着地の検証の大半はunit test全件と少ないITになり、多くのITはCIで初めて流れる。CIで分かる壊れが着地の後に見つかる回は増えうる。それを直す経路はCIの見張りと修正task（ADR-t1920-1）で、その経路が修正taskを作れていない問題は別に扱う。
- 記録の上では、変更による壊れの見逃しは0件だった（新たに赤くなったITは不安定な2本だけ）。見逃しの多さは、入った後の窓で測り直す。
- 置き場: 上限の値と根拠は[着地のITの絞り込みの測定](../plans/landing-it-selection.md)の「決めたこと」、選び方の今の姿は[Validation](../design/supervisor-lifecycle/validation.md)とscriptの冒頭が持つ。
