# ADR-t4118-1: providerの組の比較の主・切り替えた層・副

## Context

人はrequest 226で、workerも使えないproviderから別のproviderへ切り替え、A/Bの集計の主を実際に動いた組にするよう指示した。
これは、このrepositoryでworkerの切り替えを止めた2026-10-06の人の判断の見直しでもある。
[ADR-t4005-1](2026-11-02-t4005-1-production-ab-of-worker-and-review-provider-pairs.md)は主を割り当てた群、副を実際に動いた組としたが、workerの切り替えを許すと主から外れるrunが増える。
主から外すだけでは、同ADRが懸念した控えと切り替えの費用が見えなくなる。

変更は決定6のworkerの切り替えを許す場合の扱い、決定7の集計、決定10の止める条件に限るので、丸ごとの置き換えでなくこの3つをamendsにする。
切り替えの定義、群の割り当て、reviewの起動、見る数値を含む他の決定は変えない。

## Decision

### 1. 主は実際に動いた組で、切り替えたrunは別の層に置く（決定7）

主には、割り当てた群の組のまま実際に動いたrunだけを、その割り当てた群に数える。
判定は決定6の切り替えの定義を保ち、workerの実際のproviderがclaimの割り当てのままで、どのreviewのjobもそのjobの予定providerから切り替えていないこととする。
群の上書きと設定どおりの混在（AでClaudeを名指すsubagent）は切り替えではなく、主に入る。

workerかreviewのjobが切り替わったと記録から判ったrunは、主のどちらの群にも入れず、割り当てた群ごとの「切り替えたrun」の層に主と同じ項目で並べる。
控えと切り替えの費用をここで見せ、切り替えたrunの数はworkerとreviewの別に数える。
両方が切り替わったrunは両方の件数に数えるが、層の中では1つのrunである。
結果が他方の群の組と同じでも、相手の群の主に移さない。
使えなくなったproviderに応じて群を移すと、taskへの無作為の割り当てを保てず、割り当てによる比較を壊すためである。

### 2. 判定できないrunは副だけに入れる（決定7）

workerのclaimの後の最後のproviderが分からないrun、または台帳の行にproviderの使用の記録が無いrunは、もう片側の切り替えが判っていない限り、切り替えたかどうかを判定できないrunとする。
これらは主にも切り替えた層にも入れず、worker・reviewの切り替えたrunの数にも数えない。
副にだけ入れ、割り当てた群ごとに判定できない件数を見えるようにする。
主に入れると実際に動いた組であることを確かめられず、切り替えた層に入れると切り替えの証拠の無いrunで費用と割合が膨らむためである。

片側の切り替えが記録から判ったrunは、もう片側が分からなくても判定できたrunとし、決定1の切り替えた層に置いて、判った側の件数にだけ数える。
切り替えの証拠があるので主には入らず、費用と割合が証拠なしに膨らむこともない。
判定できないrunに回すと、控えと切り替えの費用が証拠のあるrunの分まで見えなくなるためである。

副は、切り替えたrunと判定できないrunも含め、割り当てた群で数える（intention-to-treat）。
主から切り替えたrunを除くことによる偏り、例えば使用量の上限に当たりやすいtaskがBの主から抜けることを確かめる比較として残す。

### 3. workerの切り替えはrepositoryの設定に従う（決定6）

workerの切り替えを止めたrepositoryではBのworkerはCodexの控えが解けるのを待つ、という汎用の規則は保つ。
切り替えを許したrepositoryでは、BのworkerがCodexの上限に当たればClaudeに移り、そのrunは割り当てたBの切り替えた層に入る。
[ADR-t1857-1](2026-10-06-t1857-1-provider-fallback-can-be-turned-off-for-workers-and-jobs.md)の仕組みは変えず、設定の値は各repositoryの`dagq.toml`が持つ。

### 4. 止める条件は主の品質と比較できる件数で判断する（決定10）

主でBの着地の後のCIの失敗かrevertの率がAを明らかに超える、またはBの切り替えたrunの割合が大きく主のBの件数が溜まらないなら、plannerか人が止める判定をする。
切り替えたrunの割合の分母は、割り当てた群のうち切り替えを判定できたrunとし、判定できないrunは入れない。
切り替えを許すrepositoryでは、workerの控えの待ちが着地を止めるという条件をこの件数の条件に置き換える。
workerを待たせるrepositoryでは、従来の控えの待ちの条件も残す。
runtimeは自動では止めず、広げる・入れ替える判定も引き続きplannerか人が別に行う。

## Alternatives

- **主を割り当てた群のままにする**: 人が実際に動いた組を主にすると判断したため採らない。
  ADR-t4005-1が「集計の主を実際に動いた組にする」を退けた理由は控えと切り替えの費用が見えないことだったが、今回は切り替えた層に主と同じ項目を出して見せ、副で実運用全体も比較する。
- **両方切り替わったrunを相手の群の主に移す**: providerの可用性で群の構成が変わり、無作為の割り当てを保てない。
- **判定できないrunを切り替えた層に入れる**: 記録の欠けを切り替えとみなす根拠がなく、切り替えの費用と割合を膨らませるため採らない。
- **片側の切り替えが判っても、もう片側が分からなければ判定できないrunにする**: 判っている切り替えの費用を切り替えた層から落とすため採らない。

## Consequences

主の件数は割り当てた件数より少なくなりうるので、副と判定不能の件数を合わせて読む必要がある。
層の所属と理由はこのADRが持ち、層の接頭辞の綴りとkpiの項目・欄の名前は実装の定義のそばで決める。
