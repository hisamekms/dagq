# ADR-t1489-1: 区分をまたぐagingは効く優先度を越えず、同じ効く優先度の中でだけ、待ちが閾値を超えた区分（実装かSpike）を先に出し、区分の中の順は保つ（ADR-t1487-2決定2をamends）

## Context

[ADR-t1487-2](2026-10-04-t1487-2-spikes-share-the-worker-slots-under-a-cap-with-cross-class-aging.md)決定2は、claimできる候補の順の先頭と違う区分に待ちが閾値を超えた候補があれば、その区分の順で最初の閾値超えのものを先頭に入れるとした。
同じ決定は区分の中の順を変えないことと、両方の区分の餓死を防ぐことも約束する。
実装してみると、この3つは両立しない場面がある。
先頭に入れる候補が優先度の低いものなら、高い優先度の候補を越え、再開・復旧jobとの列（[ADR-t1850-1](2026-10-06-t1850-1-resumes-recovery-jobs-and-claims-share-one-line-by-effective-priority.md)決定1）でどの優先度で比べるかが決まらない。
入れ替えた先頭の優先度を借りると、ADR-t1850-1決定1・6（各taskの効く優先度で比べ、待ち時間で優先度を上げない）に反する。
「区分の最初の閾値超え」は同じ区分の前の候補を追い越しうる（後から並んだSpikeが前のSpikeを追い越す）。
先頭の区分の待ちを数えないと、Spikeが並び続ける間は先頭の実装が待ち続ける。
人は2026-10-11に、agingは優先度を越えないと判断した（ask 723）。

## Decision

1. **agingは効く優先度を越えない。** 候補は各自の効く優先度の順のまま並び、agingは同じ効く優先度の候補の中だけを並べ替える。
   claimは再開・復旧jobとの列で自分の効く優先度で比べ、agingで他のtaskの優先度を借りない（ADR-t1850-1決定1・6を保つ）。
2. **同じ効く優先度の中で、待ちが閾値を超えた区分を先に出す。**
   ある優先度に実装とSpikeの両方の候補があり、片方の区分の待ち（その優先度の候補のうち、claimできる候補になってから閾値を超えて待った最も長いもの）が、もう片方の待ちより長いなら（もう片方に閾値を超えた候補が無いときを含む）、その区分の候補をその優先度の中で先に出す。
   どちらの区分も閾値を超えていないとき、待ちが同じとき、1つの区分の候補しか無いときは規則の順（解放数 → ID）のまま。
3. **区分の中の順は規則の順のまま。** agingは区分の候補をまとめて前に出すだけで、同じ区分の候補を追い越させない。
4. **interruptはagingで並べ替えない。** interruptの候補は規則の順のままで、他の候補がその前に出ることもない（決定1から従う）。

ADR-t1487-2決定2のうち、待ちの測り方（claimできる候補になった時刻から、外れて戻ったら測り直す、控えや上限で除かれていた時間も数える）、閾値の設定とagingを切る値を持たないこと、控えや上限で除かれた候補を前に出さないことは変えない。
閾値は厳密に超えたときだけ効く。

## Alternatives

- **ADR-t1487-2決定2の字句どおり、先頭と違う区分の最初の閾値超えを先頭に入れる**: 優先度の低い候補が高いものを越え、列での比べに借りる優先度が要る。区分の中の追い越しと、先頭の区分が数えられない餓死が残る。
- **入れ替えた先頭の優先度を借りて列で比べる**: 待ち時間で優先度を上げることになり、ADR-t1850-1決定6に反する。
- **優先度をまたいで、待ちの長い区分の代表を先頭に入れる**: 先頭の区分の後ろの低い候補が代表になると他の区分を止め、優先度の意味も変える。

## Consequences

- 人のpriorityと効く優先度の意味、再開・復旧jobとの列は変わらない。
- 高い優先度の実装が並び続けると、それより低いSpikeは待ち続けうる（逆も同じ）。急ぐSpikeは優先度で表し、interruptで代用しない（ADR-t1487-2決定3）。
- 同じ優先度の中では、どちらの区分も待ちが閾値を超えてもう一方より長くなれば先に出るので、並び続ける側に待たされ続けない。
- claimの記録と`candidates`・`graph`は、agingで前に出たtaskを示すだけで、優先度は各自の値のまま出す。
