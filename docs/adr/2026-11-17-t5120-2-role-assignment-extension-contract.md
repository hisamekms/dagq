# ADR-t5120-2: 役割の割当の追加契約

## Context

人はproviderだけでなくmodel・effort・実行条件を含むagentを、役割別にも役割の組としても比較したい。
個別の試しを役割ごとに増やすと、設定・抽選・起動・集計の特例が増え続ける。

この決定時点ではADR-t1692-1は存在しない。
前提はgoal 114のtask 1692の計画方針であり、受理済みの決定としては扱わない。
実験の宣言と置き場、実験名と対象による決定的な群の割当、宣言内容の版、開いた属性での群の記録、同じ仕組みの実験の競合、最初の割当記録からの復元、収集の終了と決着、数値の正本は共通契約が持つ。
値の上書きがworkerのrunとresume等にだけ届き、reviewとintegrateに届かないことも同方針を前提にする。
このADRはそれらを確定も改訂もせず、役割の割当の追加分だけを決める。

## Decision

1. **役割と割当先を分ける。**
   役割はplanner・plan review・worker・reviewという仕事、割当先はprovider・model・effort・実行の設定を束ねた名前付きのagentである。
   実験は共通契約の比較の単位、群はその条件、割当は対象と実験の版・群・解決した役割の対応を結ぶものとする。
   割当先の選択は「どのagentが役割を担うか」であり、環境・prompt・名前付きフラグ・指示の節の値の上書きとは別の種類にする。
   権限、reviewの検査内容、隔離、integrateの責務は割当先から変更できない。

2. **IndependentとCombination。**
   Independentは一つの役割について複数の群の割当先を重み付きで選ぶ。
   Combinationは一つの群に複数の役割の割当先をまとめ、群を一度選ぶ。
   群が省略した役割は通常の設定に従い、別の群の値を補わない。
   重みは多群の割当確率であり、少ない件数で件数比を保証しない。
   同じprovider同士の組も一般模型では表現できるが、既存の異種providerの試しの制限は移行まで保つ。

3. **優先順位より先に競合を検査する。**
   共通契約の「同じ仕組み」は、役割の割当では同じ役割と読む。
   実験が触る役割は全群に現れる役割の和集合で、省略した群もその役割を予約する。
   同時に有効な実験同士が同じ役割を予約するなら、IndependentとCombinationの別や割合に関係なく拒む。
   Combinationの明示した役割はその組を優先し、省略した役割には、その実験が予約していない役割のIndependent、次に通常の設定を使える。
   予約したがその群で省略した役割は通常の設定を使い、競合するIndependentを穴埋めに使わない。
   数値の優先度や設定の記述順で競合を隠さない。

4. **固定単位は仕事の生存期間に合わせる。**
   runは一回の実行に自然だがretryで変わるため抽選単位に採らず、workerとreviewは共通契約のtask単位を初期の単位にする。
   goal単位は依存taskをまとめられる反面、所属の変更と大きさの偏りがあり、共通契約で宣言した場合だけ使う。
   taskより前のplannerはrequest、plan review単独はproposalを単位にする。
   plannerとplan reviewのCombinationはrequestを共有し、同じrequestのproposalと差し戻しも群を保つ。
   requestの解決は既存のcreation originの規則に従い、requestの無いplannerは対象外とする。
   requestに結べないplan reviewはproposal単位の単独実験だけを使える。
   下流taskは計画の割当を出どころとして参照し、taskの群をrequestの群で置き換えない。
   計画側と実行側を跨ぐ一括のCombinationは初期には受け付けず、全役の共通の固定境界を設ける追加契約に拡張点を残す。

5. **固定する意図と起動の実態を分ける。**
   共通契約の最初の記録からの復元を、役割の割当先と省略役割の解決済みの起動条件にも適用する。
   resume・revise・retry・supervisor再起動、重みや候補の変更・停止・削除で、既存の群と意図した割当先を引き直さない。
   段上げや人の明示の介入は既存の規則に従う実態の変更として理由を残し、群の付け替えにしない。
   使えない割当先は既存のfallbackの許可と待ちの規則に従い、再抽選しない。
   起動ごとに意図・予定・実際とずれの理由を残し、不明を一致とみなさない。
   reviewにはreview自身の割当先の選択だけを渡し、worker用の値の上書きを渡さず、integrateにはどちらも渡さない。
   抽選の再現はLLMの出力の完全再現を保証しない。

6. **宣言の無いrepositoryと既存の試し。**
   新しい実験を宣言しないrepositoryの選択・段上げ・fallback・試しの振る舞いは今と同じにする。
   既存のworkerのmodel・effortの試しはIndependent、workerとreviewのproviderの試しはCombinationとして、共通契約の宣言へ接続できる形にする。
   既存の群・対象外・重ね方を新しい抽選で遡って読み替えない。
   ADR-0079、ADR-t3957-1決定1〜7、ADR-t4005-1決定1〜11、ADR-t4118-1決定1〜4は個々の試しの決定として保つ。
   ADR-t1662-1〜3、ADR-t1728-1、ADR-t3948-1、ADR-t2257-1も保つ。
   移行で変わる個別の決定は移行の実装の段で別のADRが変更し、このADRは既存のADRをamendsにしない。

## Alternatives

- **役割を値の上書きの一種にする。** reviewにも届く起動の選択とworker限定の上書きの境界を失う。
- **Combinationを別々のIndependentの抽選に分解する。** 群として指定した組を保証できない。
- **重複はCombinationや後に書いた実験を勝たせる。** 同じ役割の二つの実験が有効なまま、宣言と実効条件がずれる。
- **件数を揃える輪番にする。** 並行や再実行の順に依存し、共通の決定的割当を二重化する。
- **全役をrunかtaskに固定する。** task作成前の計画を割り当てられず、runならretryで比較条件が変わる。
- **全役をgoalかrequestに固定する。** 作成前のgoalやrequestの無い仕事を扱えず、下流taskの独立した実験を妨げる。
- **fallback先を新しい群にする。** 可用性による選別を抽選に混ぜるため採らない。

## Consequences

役割の追加と評価方針の変更を、抽選や専用のkpiの分岐の追加から切り離せる。
計画と実行の割当は参照で結び、下流の件数をそのままplannerの独立標本数とはみなさない。
具体の構文・検査・重みの式・記録は実装前の契約が持ち、実装と同時に定義のそばへ正本を移す。
