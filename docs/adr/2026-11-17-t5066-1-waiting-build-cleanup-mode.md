# ADR-t5066-1: 待ちのビルド成果物の削除方針を予約の方式から独立させる

## Context

待ちのrunがビルド成果物を保持すると、新しいclaimに使える容量が減る。
一方、早く消すほど次のturnや着地の検証で作り直す機会が増える。
予約量を固定するか実測から予測するかに、この保存方針を結び付ける理由はない。

## Decision

1. 待ちのrunの重いビルド成果物を通常の掃除で消す、claimの容量不足時だけ消す、消さずに残す、の方針を予約の方式と独立に選べるようにする。
   既定はclaimが空き容量で止まるときだけ、待ちに入った古い順に必要量まで消す方針とする。
   人の答え待ちもこの方針に従い、既定では通常の掃除で消さない。
2. ADR-0047決定44の「足りないとき」の掃除の対象に、方針が選ぶ待ちのrunのビルド成果物を加える。
   待ちの候補はleaseのない停止中のrunと、leaseを持つsupervisor自身が渡す、何も動いていない人の答え待ち・着地slot待ちのrunである。
   他のsupervisorのleaseと、turn・review・着地の検証・e2e・parkの最中のrunには触れない。
3. runが終わったらビルド成果物を消し、taskが終わったらworktreeを消す責務と、掃除後に容量を確かめ直してclaimを進める流れは保つ。
   askのdone / wait、ADR-t1521-2決定2の引き継ぎ確定までの保存、ADR-t4473-1の必要量、ADR-0071の待ちとslotの定義も変えない。
   古いincrementalのsessionの削除は方針と独立に続ける。
   待ちの種類ごとの経過時間・削除対象・再開後のturnの上限はこの決定で広げず、測定に基づく別の決定に委ねる。

## Alternatives

- 人の答え待ちだけ常に消す: 保存方針が待ちの種類に隠れ、容量に余裕があるときにも作り直す。
- 予約の方式ごとに方針を固定する: 予約の見積もりと保存の代償を独立に選べない。

## Consequences

既定では容量に余裕がある間の作り直しを避けられる。
容量不足時は古い待ちから削除して前進するが、そのrunが再開すればビルドが必要になる。
全て残す方針では、人が容量を空けるまでclaimが控えられうる。
