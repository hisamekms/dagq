# ADR-t5292-1: 新しく始めるものをAdmissionで一度だけ判断し資源と優先度と表示を揃える

## Context

2026-11-18、goal 317の5283はinterruptで候補の先頭にあり、workerのslotが3つ、diskが60 GiB空いていたが、21:15〜21:53 JSTの38分間claimされなかった。
holdされた着地待ちも着地先行の条件に入り、着地とclaimが互いを待った。
claimを控える表示には理由が無く、候補の標本の記録では控えている扱いになった。
戻り・claim・着地を別の関門で決め、進めないrunを数える定義と表示の読みも別だったことが原因である。
人はgoal 318の小さい直しを閉じ、goal 319で判断・数える集合・表示を統合する方針を選んだ。
今回の直接の原因であるhold中のrunの数え方は先に修正された。
残る課題は、開始と表示が別々の関門を読み、着地とclaimの両方を始められる回も資源と優先度で選べないことである。

ADR-0071決定8はADR-t1591-1決定7、ADR-t5107-1決定5まで辿っても戻りの無条件先行を保つ。
ADR-t5107-1決定5を改めたADR-t5265-1とADR-t5283-1は承認された着地の選択とe2eの枠の境界を扱い、戻りの先行は変えていない。
ADR-t4473-1決定6の今の必要量と着地先行はADR-t5064-1決定1・3・4に、期限つきの緩め中の着地先行はADR-t4727-1決定4にある。
これらの該当部分とADR-t1850-1決定1・2・4の列・関門、ADR-0051決定3の候補の標本の出どころをamendsする。
ADR-t1992-1決定3のclaimを止めた回には判断しない境界と、決定6の標本の読みを変えない境界も、同じ判断から表示と標本を作る範囲だけamendsし、他の決定は変えない。

## Decision

1. **新しく始めるものは、Admissionという1つの副作用の無い判断で決める。**
   対象はclaim・resume・人の待ちからの戻り・復旧job・着地の開始である。
   入力はその回のrun・候補・資源・効く優先度の写しだけとし、資源にはworkerのslot・disk・load・着地のturn・CIとenvとlanding branchの可否・claimの間隔を含める。
   出力は始めるものの順の並びと、始めない候補ごとの理由とする。
   戻り待ち・標本の無いdiskの直列化・load・hold・claimの間隔・CIなどの関門はこの判断の中の規則にし、supervisorの回はこの出力だけに従って開始する。
   holdなど開始直前に変わった入力は新しい写しで判断し直し、古い許可で始めない。
   着地の列（ADR-t5283-1）が選んだ候補を受け取り、着地を始める可否とclaimとの兼ね合いを決める。
   列の順番と先頭を飛ばせる条件は着地の列が持つ。
   着地の検証はqueue全体で同時に1つのままにし、slotを要しない既存の後始末や走っている工程の駆動はこの開始判断の対象にしない。
2. **「今進めるrun」を、holdされておらず、答え待ちのaskが無く、CI・env・landing branchで止まっていないrunと定める。**
   着地待ち・戻り待ち・diskで動いているrunと残りの予約を数える対象は、全てこの集合に限る。
   この集合に入ることだけで待ちに予約を足すのではなく、予約する段階と残りの量は既存の段階ごとの規則に従う。
   holdしたrunは今のdiskの大きさだけを占め、未使用の予約を持たない。
   holdした着地待ちのrunだけを理由にclaimを止めない。
3. **戻り待ちもslotを渡す1本の列に入れ、効く優先度の高い順にする。**
   同じ効く優先度では戻り・resume・復旧job・claimの順とし、戻りどうしは待ちが終わった古い順、他の同種内は既存の順を保つ。
   新しいclaimを戻り待ちのために止めるのは、そのclaimより効く優先度が低くない戻り待ちがあるときだけとする。
   低い優先度の戻りは高い優先度のclaimやresumeを止めず、保留条件により進めない候補はslotを予約しない。
   drain中とclaimを止めている回でも戻りは進める。
   drainは待ちのrunの終わりを待つため、答えの来たrunが戻れない状態でdrainを終われなくしてはならない。
4. **着地とclaimの同時開始は、容量を一度だけ数えて決める。**
   同時に始めるのに要る容量は、動いているrunが無いときに予備だけで1本通す例外を当てる前の、共有の予備・動いているrunの残りの予約・新しいworkerの予約・着地の候補の残りの予約から一度だけ数える。
   既に動いている着地の残りと、空いている着地枠の予約は既存の段階ごとの規則で扱い、候補がその枠を使う分と二重に足さない。
   claim用と着地用にそれぞれ出した必要量を足してはならない。
   その和では、例外で下げた値を足すと両方の予約が収まらない回を通し、通常は共有の予備と着地の枠を二重に数えるためである。
   diskがこの同時開始の必要量を受け入れ、他の開始条件も満たすなら、同じ回に両方始める。
   両方を受け入れられないときだけ効く優先度の高い方を先にし、interruptのclaimはhighの着地より先、同じ効く優先度では着地を先にする。
   動いているrunが無く空きが予備以上なら、予約の想定にかかわらず1本通す保証を保ち、その例外で2本を同時に始めない。
   予測の標本が無いときは1本ずつ進める規則を保つ。
   期限つきでdiskの必要量を緩めている間もこの兼ね合いを使い、緩める権限・期限・最低ライン・容量不足のやり直しは変えない。
5. **進める候補があり資源が足りるのに何も始めない状態を不変条件の違反として検出する。**
   その状態が続く回数が設定された回数を超えたら、始めない理由を添えて人へのattentionを出す。
   閾値はprojectの設定で与え、runtimeにこのrepositoryの値を固定しない。
   判断がその状態を作れないことを、候補・run・資源・優先度の組合せに対する性質のtestで確かめる。
6. **statusのclaimを控える理由と候補の一覧、候補の標本の記録を、同じ判断の出力から作る。**
   claimを始めない回には必ず理由を見せ、候補が無い場合もその旨を見せる。
   表示や標本のために別の関門を当て直さず、slotが無い回やclaimを止めている回にも判断の理由を残す。
   CLIはsupervisorの最新の判断の記録を読み、自分で開始可否を推測しない。
   依存グラフと候補の順位の規則は変えない。
   ADR-0051決定3は候補の標本の出どころだけを改め、標本を記録する条件とKPIの集計規則は変えない。
   claimの間隔の待ちも始めない理由として見せるが、claimを控える記録にはせず、observerとstatsの控えの数え方に混ぜない。
   この区別はADR-t1479-1決定1とそのAlternativesを保つものであり、ADR-t1479-1は改めない。

## Alternatives

- **goal 318の小さい直しとして戻り待ちの関門だけを変える、または譲りだけを足す**: 関門が散らばったままでは、2026-11-18の5283の38分と同じ形の食い違いと行き詰まりが次にも出る。
- **diskのLandingFirstだけを直す**: holdした着地待ちによる停止を解いた後も、戻り・slot・load・CI・表示の判断が別に残り、同じ形の行き詰まりを防げない。
- **戻り待ちを常にclaimより先にする**: 低い戻りがinterruptの新しい仕事を止める。
- **戻り待ちをclaimと同じ順で並べる案を引き続き退ける**: ADR-0071のAlternativesが守った「人の答えから結果までを延ばさない」理由は、同じ優先度では戻りを先にすれば保てる。
  効く優先度をまたぐ無条件先行はその目的に必要ないため、共通の列に並べる案をこの条件つきで採る。
- **claimと着地の必要量を個別に足す**: 例外の適用順で安全側にも危険側にもずれ、同時開始の資源の写しにならない。

## Consequences

開始と見え方が同じ理由を持ち、資源がある回は着地とworkerを並行させられる。
実装は判断と配線と性質のtestを分けて示す必要がある。
今の実装の地図とpluginの案内は、後続の実装で振る舞いと一緒に合わせる。
