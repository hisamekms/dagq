# ADR-t4644-1: 読み手の要らないqueue行を省き、窓の端だけを補う

## Context

台帳はeventを読み直さずに統計を速く出すための集計だが、値を読む読み手の無い単発のeventもqueue行になり、その流入が書く枠と追いつきを押さえている。
[Spikeの判定](../plans/ledger-queue-rows-readers-spike.md#判定)では、窓の端だけを点の読みで補えば値を戻せる3 kindがholdsで、標本の流入の9割余りを占める。
人は2026-11-09に、同じ入力で値を比べること（ask 1606）、省く対象をqueue行だけに限ること（ask 1607）、新しい入力と固定した3 kindだけを扱うこと（ask 1615）、書き込みの上限で切れた周回の先行の範囲（ask 1616）を決めた。

## Decision

### 1. 除外の原則と境界（決定10をamends）

値を読む読み手が無く、存在が窓の端にしか効かない単発のkindのeventは、新しくqueue行に写さない。
写さないkindは[Spikeの判定](../plans/ledger-queue-rows-readers-spike.md#判定)がholdsの3 kindに固定し、一覧に無いkind（新しいkindを含む）は今どおり写す。
その3 kindのうち元々queue行に属するものだけを、以下「写さないqueueのevent」と呼ぶ。
run・task・sessionに属する同じkindのevent（runに記録されるtelemetry tokenのeventなど）は今どおりその行の記録で、以下の到達点・要約・補いの対象にしない。
省くのはqueue行だけで、run・task・session・nodeの行の記録と、走っているrunを読みで畳む行は今どおりにする。

### 2. 被覆の始まり・到達点・要約

写さないqueueのeventは行を要らないので、台帳を作る係が読んだ時点で記録済みとみなす。
係は、要約の無いstoreで最初に読み始めた位置を被覆の始まりCとして一度だけ書く（最初のeventから作るstoreでは最初から）。
C以下の写さないqueueのeventは今どおりqueue行のままにする。
Cより後に読んだ写さないqueueのeventについて、到達点S（係が読んだ位置）と、CからSまでの要約をR・Wと同じ書き込みで、Sと要約が常に同じ範囲(C, S]を覆う形で下げずに書く。
要約はkindごとの最後のidと時刻の読める最後のid、id順の時刻の最大の推移、時計の戻りの最大D、そのkindのeventをどの行のものも一定数ごとに区切る点を持つ。
時刻の読めないeventは今の窓と同じく最新のidにだけ効き、時刻からの位置と最初の時刻の候補にならないので、最後のidと時刻の読める最後のidを分ける。
版の更新・Wによる切り戻し・Rの無い周回でもC・S・要約を下げず消さない。
Sを知らない版の係がRをSより先へ進めたstore（前の版に戻した後）と、保存された写さないkindの組が今の版の組と違うstoreでは、係はC・S・要約を据え置き（下げず進めず）、Sより後の写さないqueueのeventを今どおりqueue行にする。
この停止は、要約が途切れずに(C, S]を覆うことを守る。

### 3. 窓の端の補い（決定12をamends）

共通の読み取り関数は、同じ読みの状態の中でC・Sと要約を読み、保存された要約のkind（今の版の組ではない）について、(C, S]の写さないqueueのeventだけをEventStoreから補い、窓の端を決める。
要約の無いstoreは補わず、run・task・sessionに属する同じkindのeventも補わない。
ほかのkindの端・Rより後に保存済みの行の記録・走っているrunの記録・C以下の写さないqueueのeventの行は今どおり行と読みから取る。
行と補いの両方にあるeventは端の最大・最小・そのevent自身で合わさり、値は変わらない。
最新は要約の最後のid、id指定は1件の読みで得る。
時刻からの位置と範囲の最初の時刻は、要約の点で端の近くから読み始め、時刻の読める写さないqueueのeventを含まない点の間は読まずに飛ばす。
id順の時刻の最大が下がらないこととDから、それより後のeventが答えを変えないと決まった所で止める。
読むのは端の時刻からDの幅の中の写さないqueueのeventを含む点の間の、一定数までのeventだけで、窓の外の履歴（同じkindのrun・task・sessionのeventを含む）を増やしても増えない。
時計の戻りがDを広げたときだけ幅が広がる。
読み手は今どおり共通の読み取り関数だけを通し、独自にEventStoreを読まない。

### 4. 保つ保証と値の比較

決定9（上の層は下の層だけを読む）・13（台帳は制御に使わない）とR・Wの約束を保つ。
写さないkindのeventも読んだ入力としてRを進め、入力を飛ばさず、台帳に残る行の中身は全件のfoldと同じにする。
読み取り関数の変更だけでは、どの台帳（Rより後の保存済みの行・走っているrun・Rの無い台帳を含む）でも値は変わらない。
写さないようにした後は、どの周回の後でも、同じ台帳に(C, S]の写さないqueueのeventの行を全て足した今の形の台帳を、今の読み取り関数で読んだ値と同じにする。
今の係の台帳と字義どおり同じ値を求めるのは、書き込みの上限で切れずに終えた周回だけである。
これには係が追いついた状態（残った印が無くRが読んだ位置）と、今の係が写さないqueueのeventの行だけを書き、上限で切れずに読んだ所まで書き終えた周回も含む（R=100でevent 101だけを読み、その行を書いた場合など）。
上限で切れた周回は、今の係が写さないqueueのeventの行だけを書いて切れた場合も、今の係との直接の一致を求めず、同じ入力を記録した今の形の台帳を今の関数で読んだ値で比べる。
例えばC=100から同じ頁の101・102を読み上限が1行なら、今の係は101の行だけを書いて最新が101、新しい係は読んだ位置S=102まで要約するので最新が102になる。
違い得るのは、新しい係が写さないqueueのeventを行にせず要約で覆う分（そのevent自身と、空いた枠で早く書いたほかの行）だけ今の係より先の入力まで値に入る場合だけで、これは許す。
run・task・sessionに属する同じkindの記録されていないeventを補って値を進めることは許さない。
停止の間も、据え置いた(C, S]の要約とSより後の行を合わせた入力で同じ保証が成り立ち、Sが今の係のRに届くことは求めない。
goal 273の受け入れ2「値は変更の前と同じ」は、この同じ入力を記録した今の形の台帳を今の関数で読んだ値との一致で満たす。
新しい係が今の係より遅れることと、同じ入力で値が食い違うことは無い。
前の版のバイナリが読む値は、その読み手が補いを知らないのでこの保証の外である。

## 決めないこと

一覧の出し入れ（kindを足す・外すこと、空からの切り替え）、既にあるqueue行の削除とそれに要る要約の埋め戻し、停止からの再開は、goal 277の後のADRに任せる。
Rの分割と書く量の上限はこのADRでは決めない。

## Alternatives

- 全ての単発のkindを外す: 値や範囲の前の入力を読む読み手があり、Spikeでholdsでないkindの値を保てない。
- 各読み手が窓の端を補う: 読みが分かれ、共通の読み取り関数だけを通す約束を失う。
- 窓の端のために履歴を全て読む: 台帳で統計を速く出す目的に反する。
- 行の版を上げて全行を書き直す: 新しいqueue行を減らすために大量の書き直しを生むので使わない。

## Consequences

新しいqueue行の流入を抑え、窓の端を保ったまま補う読みを端の近くに限れる。
そのために、入力を覆う要約を原子的かつ単調に保ち、互換でない書き手の後では省略を止める必要がある。
今の姿とコードへの入口は[計測](../design/measurement.md)が持ち、識別子の一覧と読み・保存の細部は定義のそばのdoc commentが持つ。
