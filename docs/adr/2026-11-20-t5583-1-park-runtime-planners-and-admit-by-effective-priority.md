# ADR-t5583-1: 外の条件を待つruntimeのplannerは枠を返し、枠は効く優先度の順に渡す

## Context

人が後回しにした手直しと、依存先の審査通過を待つ手直しがplannerの枠を占めた。
runtimeが時間切れのたびに同じ仕事を開き直したため、待たれている依存先の手直しに枠が渡らず、急ぐgoalも止まった。
request 378で人が承認した方針に従い、[ADR-t1704-1](2026-10-05-t1704-1-human-answer-wait-releases-runtime-planner-slots.md)の終了と引き継ぎを外の条件の待ちに広げる。

枠の決定は、上限で空きを待つ[ADR-0047](0047-irregularities-in-three-layers-recovery-job-ask-reasons-and-goal-review.md)決定12から、依頼にも同じ枠を使う[ADR-t1394-1](2026-10-03-t1394-1-abolish-person-planners-and-route-planning-through-inbox-requests.md)決定4を経る。
ADR-t1704-1は両者をamendsし、人の答え待ちで返した枠に答えが来た仕事を戻す経路を定めた。
同じ枠で立つdraftとfindingの種別内の順はADR-0047決定16・19が定め、[ADR-0051](0051-kpi-time-series-report-and-push.md)決定25も改善の上限が空いた後の順に決定19を参照する。
その決定25をamendsした[ADR-t2928-1](2026-10-20-t2928-1-only-the-ci-watchs-ci-failure-findings-are-repairs-outside-the-improvement-limit.md)決定4は、revise・答え・依頼の後、draft・改善の前にCIの修理を置いた（置き換え済みのADR-t2893-1決定2を継承）。
[ADR-t2971-1](2026-10-22-t2971-1-the-agent-watchs-step-findings-are-outside-the-improvement-limit.md)決定3がこれをamendsし、agentの見張りの手順のfindingも同じ位置に置き、改善の上限の算入・待ちと枠の順を一つの判定にした。
ADR-t1404-1決定10は枠を使うsessionをwrapperで読む変更、ADR-t1487-1決定5とADR-t1521-2決定3は同じgoalの再計画の直列化と依頼への接続であり、いずれも枠を渡す順を追加していない。

このADRは汎用の待ちと枠の順を定め、共通の待ち方はgoal 328の5587がpluginに写す。
goal 206の2939（ADR-t2939-1）は、このADRの後に、宣言の無い `depends_on_draft` だけの待ちをruntimeが推してparkするかと、parkした仕事がproposalをまたいで互いのdraftを待つ循環の検知・解消を決める。

## Decision

1. **待つ仕事と条件の型。** runtimeのplannerが外の条件を待つだけの仕事をqueueに残して枠を返すことをparkとする。[ADR-0071](0071-runs-waiting-in-revise-and-resume-leave-the-slot.md)決定7を、待ちを実行枠の外に置く前例として保つ。
   条件はqueueの記録で判定できる閉じた集合とし、依存先taskの提出、依存先taskのplan review通過、指定のholdの解除、指定のaskへの回答、指定のtaskの着地、指定のgoalのcloseをそれぞれ別の型にする。人の答えだけの待ちはaskへの回答の型に含め、集合にない待ちは既存の経路で扱う。
   lintの `depends_on_draft` だけで出し直せないときは提出を待ち、依存先の中身が審査で定まるまで手を付けられないときは審査通過を待つ。lintの対象集合の外にあるdraftによる指摘は提出で解け、取消は別の指摘になる。成立は過去の達成で固定せず、今の状態で判定する。

   | 依存先taskの今の状態 | 提出の条件 | 審査通過の条件 |
   | --- | --- | --- |
   | 提出だけ（submitted） | 成立 | 未成立 |
   | 差し戻しでdraftに戻った | 未成立 | 未成立 |
   | 審査通過（ready以降で着地前） | 成立 | 成立 |
   | 着地済み | 成立 | 成立 |
   | 取消 | 対象消失 | 対象消失 |

   宣言のないlintの待ちをruntimeが推してparkするかと、proposalをまたぐ循環の検知・解消はADR-t2939-1に委ねる。

2. **宣言の受理と枠の返却。** runtimeのplannerは、自分が担当するreviseのproposal・依頼・draft・findingについて、進められる仕事を済ませて条件を宣言する。同じ束の他のdraftで決められる仕事も済ませる。決めたこと、未決の点と理由、条件が満ちたらすることを対象のnoteに残し、draftの編集を保存してturnを終える。
   宣言はqueueに記録した時に受理する。従来どおり自分の未回答の問いだけが残るplannerについては、その問いの記録を回答待ちの宣言として扱う。supervisorは、turnが終わり、未処理の続きの依頼・配送済みで未読の答え・providerの控えが無いpassで、ADR-t1704-1決定1の終了手順を始める。
   宣言を受理しても枠は引き続き占有する。記録を残して終了を依頼し、wrapperの終了を確かめて行を閉じたpassで枠を返す。終了手順は[ADR-t1404-1](2026-10-03-t1404-1-headless-wrappers-run-as-detached-background-processes.md)決定3と[ADR-t1433-3](2026-10-03-t1433-3-headless-wrappers-run-only-in-the-background.md)決定1・3を保ち、未回答のaskは開いたままにする。
   終了依頼から行を閉じるまでにsupervisorが止まっても、次のsupervisorがqueueに残る宣言・終了の記録・引き継ぎから同じ手順を続ける。
   終了を依頼する前のpassで条件の成立を確認したら、終了手順を始めず、生きている持ち主に成立と待ちの間に届いたrevise・答えを次のturnとして届ける。枠の追加取得はない。終了を依頼した後に成立したら、そのplannerへの配送は止めたまま行を閉じ、決定3で立てたplannerに渡す。いずれの行き先でも成立と届いたrevise・答えは一度だけ渡す。

3. **再開、排他、中断からの復元。** supervisorはpassごとにqueueの記録を読み、副作用の無い関数で条件を判定する。行が閉じ、今も条件が満ちている仕事は決定6の候補になり、枠が取れたpassで新しいplannerを立てる。ADR-t1704-1決定3の引き継ぎに従い、条件・前のplannerのnote・編集済みのdraftを初期promptに載せる。
   - **対象ごとの排他。** proposal・依頼・draft・findingの各仕事に、生きているか起動中のplannerを高々一つにする。draftの束でも各draftに当てる。持ち主のいないrevise、答えを運ぶ起動、依頼・draft・findingの通常の起動と、parkからの再開で同じ予約・再検査を使い、二つの経路に同じ仕事が現れたpassでも起動は一つにする。
   - **待ちの間の入力。** 新しく届くreviseや答えをqueueに蓄え、宣言した条件の成立まで待つ。通常の経路でも同じ条件を尊重し、成立した仕事の起動はparkからの引き継ぎを使う。指定のaskへの答えなら、それ自体が条件を満たす。引き継ぐrevise・答えは初期promptか次のturnの片方だけに載せる。
   - **確定と受け取り。** wrapperのhandleの記録、仕事の宛先と持ち主の権限の確定、待ちと引き継ぎ（届いたrevise・答えを含む）の消費を一つのtransactionで確定する。reviseではそのplannerを宛先にし、配送の記録も同時に残す。wrapperはhandleが記録された時点から最初のturnを始められる。wrapperが初回の入力でagentを起こす前に残す最初のturnの開始記録を、入力の受け取りの印とする。印があればparkからの再試行はせず、その後の終了は既存の経路で扱う。
   - **受け取り前の中断。** 起動行を作ってhandleを記録する前に止まった行と、handleを記録した後でも受け取りの印の前にwrapperが終わった行は、決めずに終わった回数に数えずに閉じる。ask 2049で人が求めたとおり、仕事と答えを失わず、待ちと引き継ぎをqueueの記録から同じ入力に復元する。次のpassで枠を取れるなら、条件を確かめ直して同じ仕事に一つだけ立て直す。この立て直しには回数の上限を置き、使い切ったらinboxに知らせ、蓄えた入力を保って仕事を通常の経路に戻す。
   - **初回のproviderの壁。** 最初のturnが[ADR-t2930-1](2026-11-19-t2930-1-headless-codex-runtime-planner.md)決定5の起動時の切り替えに当たる壁で終わった場合、切り替えの経路（goal 88の5576）が予約・起動・宛先の確定・受け取りの確認を引き受ける。再開の記録は条件・引き継ぎ・届いたrevise・答えをqueueから復元できる形で残し、切り替えの経路が同じ入力を復元する。parkからの経路はその仕事を拾い直さず、どちらが引き受けても対象ごとの排他は共通とする。
   - **対象の消失。** 条件の参照先が取消・proposalの取り下げ・goalのabandonedなどで成立し得なくなったら、成立とは扱わず待ちを終え、理由を記録してinboxに知らせる。待っていた仕事がまだ計画を要するなら蓄えた入力を残して通常の経路に戻し、仕事自体が消えたなら起動せず既存の不要になった配送の片付けを行う。

4. **人が後回しにしたrevise。** 計画承認のask（`approve_plan`）に人が手直し（`send_back`）を求め、条件が満ちるまで後回しと指定したとき、答えを記録するinboxか人が決定1の型の条件も記録する。自由文だけの理由は従来どおり届け、runtimeはそこから条件を推定しない。
   supervisorが答えを適用する時に条件を判定する。その時に成立済みなら成立を記録し、条件のない差し戻しと同じく、生きている持ち主へ届け、居なければ新規起動の候補にする。
   未成立なら答えの適用と同じtransactionで条件をreviseに結び、満ちるまで起動も持ち主への配送も止める。生きている持ち主は決定2と同じ手順で閉じ、枠を返す。終了を依頼する前に満ちれば持ち主へ、依頼した後に満ちれば行を閉じてから決定3で立てるplannerへ、reviseを一度だけ届ける。参照先の消失は決定3に従う。

5. **計時。** 外の条件を待つ間のplanner・reviseは、応答しないplannerの検出、上限でplannerを待つreviseの通知と枠を空けるための待ちの期限、決めずに終わった回数のいずれにも数えない。宣言しただけで作業中のturnの失敗まで除外する扱いにはしない。
   条件が満ちて再び枠を待つ時間は、queueの記録が示す今の成立の時刻から数える。park中の時間は繰り越さない。差し戻しなどで未成立に戻った後に再び満ちたら、新しい成立の時刻から数え直す。条件が長く未成立であることだけではinboxに知らせない。

6. **空いた枠は効く優先度で配る。** [ADR-t5292-1](2026-11-18-t5292-1-admission-unifies-starts-resources-and-reasons.md)決定1・3の効く優先度の規則を保ち、supervisorは新しく立てるplannerの候補を一つの列に入れ、interrupt → urgent → high → normal → lowの順に枠を渡す。枠の数は共有の `runtime_planners` の設定で決める。生きていて受け取れる持ち主へのrevise・答えの配送は枠の追加取得がないので列の外で続け、上限でもADR-0047決定12とADR-t1704-1決定2の経路で届ける。

   | 候補（同じ優先度での種別順） | 効く優先度の出どころ |
   | --- | --- |
   | 持ち主のいないrevise | proposalのtask（ADR-t2951-1決定1）の効く優先度の最大 |
   | 人の答えを運ぶ新しいplanner | askの対象（proposal・依頼・draft・finding）に対応するこの表の優先度 |
   | 依頼 | 依頼の優先度 |
   | CIの修理のfinding | mainと着地先のbranchを止めるため、着地を待つrunの効く優先度の最大。なければnormal |
   | agentの見張りの手順のfinding | 紐づくgoalの効く優先度。なければnormal |
   | draft | taskの効く優先度。束は候補に含むdraftの最大 |
   | 改善のfinding | 紐づくgoalの効く優先度。なければnormal |
   | 成立してparkから戻る仕事 | 元の仕事の効く優先度と種別を継ぐ |

   同じ優先度では上の種別順、同じ種別では待ち始めが古い順とする。通常の候補は仕事が起動を待ち始めた時、parkから戻る候補は決定5の成立の時を使う。
   起動を確定するときに条件を再検査し、他のsupervisorが取った、対象が進んだ、適用される回数や改善の上限に達したなどで起動できない候補は枠を使わずに飛ばす。同じpassで後ろの起動できる候補に枠を渡す。人の答えを運ぶ起動が決めずに終わった回数の上限を越えられる既存の扱いは保つ（ADR-t1704-1決定5）。
   ADR-t2971-1決定3の判定を、改善の上限に数えるか・上限で待つかの判定と、枠を渡す順の判定に分ける。CIの修理と見張りの手順のfindingの免除はADR-t2928-1決定3・ADR-t2971-1決定2のまま保つ。答えを運ぶfindingのplannerにも従来どおり改善の上限を当てない。
   優先度は空いた枠の配分に使う。上限で待つ高い優先度の候補がいることだけで低い優先度のidleなplannerを終了させず、上限で長く待つreviseのために既存の条件で枠を空ける復旧も、優先度による選び方には切り替えない。

## Alternatives

1. **閉じた型を選ぶ。** 自由文の条件は現在のqueueの状態から同じ判定を再現できない。提出と審査通過を同じ型にすると、lintが解けた修正を止め続けるか、審査の前に中身を前提にしてしまう。
2. **turnの境界で既存の終了手順を使う。** 宣言と同時に枠を返すと、まだ動くwrapperや未読の続きが残る。終了依頼前に成立しても新しく立てる方式は、生きている持ち主に渡せる入力を起動し直す。
3. **対象単位で予約し、受け取りまで同じ入力を復元する。** 別経路で起動を競わせたり、新しい入力のたびに待ちを破ったりすると二重起動や同じ待ちへの往復を招く。行を作っただけで消費すると中断で入力を失い、受け取り後も全面的に再試行すると処理を重ねる。切り替えとparkの両方で復元すると予約が競う。参照先が消えた条件を成立扱いにすると前提が崩れたまま進めてしまう。
4. **人の条件を答えの適用時に結ぶ。** 記録時に判定すると適用までのqueueの変化を見落とす。最初のplannerに宣言させると、人が後回しにした仕事に一度枠を使う。自由文の解釈に任せると人が指定した条件を確実に再現できない。
5. **今の成立から計時する。** park前の時間を継ぐと、枠を再び求めた直後に長く枠を待った扱いになる。未成立の長さだけを知らせると、人が意図した待ちまで警報になる。
6. **空き枠を優先度の一列で配る。** 種別を第一にすると急ぐgoalの仕事が低い優先度の別種別に負ける。先頭の候補が起動できるまで枠を取っておくと、進める仕事が止まる。優先度だけでidleなplannerを追い出すと、短い待ちや優先度の変化で終了と起動が繰り返される。

## Consequences

待つ仕事の続きはqueueから引き継げ、空いた枠を進められる仕事に渡せる。受け取る前の中断とprovider切り替えの両方で、同じ仕事と入力を復元できる記録を保つ必要がある。
