# ADR-t5064-1: 空き容量の予約はrunの段階で付け替える

## Context

人は固定と予測のどちらでも、workerの作業・待ち・着地の検証に同じ予約の考え方を求めた。
待ちのrunを数えないという説明では、既にdiskを使っていることと、これから使う分の予約を区別できない。
着地待ちが現れたときだけ着地の想定を足すと、それまでのclaimが着地のための容量を使える。

## Decision

1. **予約を段階ごとに付け替える。** runのworktreeでbuildする段階はWを予約する（claimからreceiptまでの作業、revise・resume・差し戻しの作り直し、hostのe2eとその開始待ちを含む）。review中・着地の順番・人の答え・providerの控えの待ちは今の大きさだけを占め、未使用の予約を持たない。INTEGRATORは着地の検証とそのやり直しでIを予約する。
2. **まだ使っていない予約だけを空きと比べる。** Uは各runの予約量から信頼できる今の大きさを引き、負なら0とした和とする。量れないrunは段階の予約量そのままを数える。待ちのrunの実際の大きさは空きに既に反映されるため、その項は0である。
3. **着地のslotの枠を常に取る。** 空いているslotごとにIを取る。INTEGRATORがいればその残りがUの中でslotを占め、Iを二重に足さない。claimの必要量は予備＋U＋新しいW＋空いているslotのI、着地は予備＋そのrunの残りのIとする。ただし開始と容量不足後の検証のやり直しは同じ必要量を使い、他に動くrunが無ければ共に予備だけで進める。一度のclaimの本数は、空きから予備・U・空いているslotのIを引いた量をWで割って切り捨て、設定の並列度と空きslotを上限にする。
4. **方式の違いはWとIの出どころだけ。** 固定はprojectが値を与え、着地の値を省略すればworkerと同じ値を使う。予測は段階ごとの標本が入るまで両方に今の共通の見込みを使う。係数なし・最低ライン・前進の保証・着地の先行・予測に標本が無いとき1本ずつ進めることは保つ。動いているrunが0本で空きが予備以上なら、着地枠を足しても最低1本の前進を妨げない。
5. **期限つきの緩めを保つ。** ADR-t4727-1の想定の上書きはWとIの両方に効き、着地の想定を足さない緩めは空いているslotの項だけに効く。残りを数えない緩めはUに効く。最低ラインは緩めない。

6. **段階はphaseの性質から一か所で決める。** runのworktreeでbuildするか、着地のレーンにいるかを各phaseの性質として網羅的に定義し、新しいphaseは性質を決めないとcompileできない。buildはW、着地のレーンはI、それ以外は今の大きさだけを占める。reviewのプログラムとagent評価はbuildしない。hostのdiskを使わないcontainer内のbuildは、その配置の性質で未使用のhost予約を0にできる。
7. **全員が一つの判定結果を読む。** 各passは段階を持つ未完了のrunを、slotの内外や着地を頼んだ経路で分けずに量り、候補ごとの必要量・空き・可否を一度だけ決める。開始・やり直し・控えの記録・diskのask・statusはこの結果を読み、独自の必要量や別の全体判定を並べない。量れない値はどのrunも同じく不明として安全側に数える。

ADR-t4473-1決定1・2・5とADR-t4727-1の権限・期限・記録は変えない。
掃除の対象と、走っているrunとleaseを持つrunを消さない境界も変えない。

## Alternatives

- **待ちのrunにWを保つ**: まだ使わない量でclaimを控える。
- **着地待ちがあるときだけ枠を取る**: 先に始めたworkerが着地の容量を使える。
- **固定だけ別の式にする**: 方式の切り替えで段階と前進の扱いまで変わる。

## Consequences

- reviewや待ちに入ると未使用の予約が解放され、作業を再開すると再び予約する。
- 着地待ちが無くても通常のclaimは着地枠を残すため、claimの本数は減りうる。
- 固定の値を超えるrunは残りを0と数えるが、実際の空きと最低ラインで歯止めを掛ける。
