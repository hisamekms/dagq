# ADR-t4291-1: チームの版でeventの本文を置き場へ出す形（行に残す欄・後から足す欄の行き先・読み戻しの経路・古いeventを移す経路との関係）

## Context

[ADR-t3981-1](2026-11-02-t3981-1-team-version-control-side-on-containers-postgres-and-object-store-with-app-side-write-serialization.md)決定1はチームの版で大きなeventをS3互換の置き場に置くと決めた。[ADR-t3982-1](2026-11-02-t3982-1-store-adapter-shares-ports-row-mapping-and-standard-sql-and-splits-dialect-by-functions-and-per-adapter-statements.md)は、置き場をstoreと別のportにし、行が鍵を持つのは置き終えた本文だけで、portはtransactionに加わらないこと（決定5）と、閾値を超えるeventの本文をportに通すこと（決定6）を決め、行に残す欄を後のADRに残した。

今の形では、portが外に置くと行の本文の列は鍵だけのJSONの文字列になる。これには3つの穴がある。

- SQLはeventの欄を本文の列から読み、絞り込み・結合・索引の式・triggerに使うが、鍵だけの行からは何も読めない（棚卸しは[計画](../plans/team-version-write-leader.md)の「(g)」）。
- 本文に欄を足す本番の更新が、鍵だけの行では何も変えず、足した欄は黙って失われる。
- 鍵を読み戻す経路が無い。

ローカルの既定のadapterは外に置かないので、今はどれも起きない。本文が64 KBを超えるeventは本番で13件で（ADR-t3981-1のContext）、鍵を持つ行はごく少ない。SQLが読む欄の大半はIDと短い印である。

## Decision

ADR-t3982-1決定5・6とADR-t3981-1決定1を保つ。置くのは閾値を超えたeventの本文で、行が鍵を持つのは置き終えた本文だけで、portは鍵で置き・読み・消すだけを持ってtransactionに加わらず、孤児を許して後で片付け、外に置かなかった本文はそのまま行に入れる。ローカルの既定の動きは変えない。このADRはどのADRもamendsも置き換えもしない。

1. **本文の全文を置き、行はobjectのまま欄を残して鍵を持つ（論点a）。** 閾値を超えた本文は全文を不変の物として置く。行の本文の列は同じ本文のobjectから欄を除いたものにし、予約した欄で鍵を持つ。SQLが読む欄は値の長さによらず行に残す。残りの欄を値の長い順に除き、行が閾値以下になったところで止める。SQLが読む欄はSQLを変えずに今の式で読め、方言の関数も索引の式もそのまま働く。SQLが読む欄だけで閾値を超える本文、除く欄が無い本文、objectでない本文は外に出さず、行のまま持つ。行を小さくできないのに置き場への依存だけを作ることを避けるためである。
   どの欄をSQLが読むかは、kindを問わない欄の名前の集合としてコードの定義に置く。今のschemaとsrcのSQLが読む欄がその集合に無ければ、境界のtestで落とす。新しいSQLが欄を読み始めるときに、集合への追加を忘れて黙って失う経路を残さない。
2. **置いた物は不変にし、後から足す欄は行に足す（論点b）。** 鍵を持つ行に足す欄は、その行のobjectに足す。置いた物は読み直さず置き直さないので、新しい鍵も孤児も増えない。行の更新は欄を足す元のtransactionの中で確定し、同じtransactionで書く他の記録と揃う。`session_exited`の作業の内訳とtoken、`ci_checked`と`ci_scheduled_checked`のfindingのID、`ci_turned_red`のfindingのIDの一覧は、どれもこの形で行に入り、失われない。行が鍵を持つのは置き終えた本文だけで、portがtransactionに加わらないこと（ADR-t3982-1決定5）はそのまま保つ。足した後に行が閾値を超えても、鍵を持つ行では判定し直さない。まだ鍵を持たない行が足した欄で閾値を超えたときは、決定1の形で初めて外に出す。鍵を持つ行から欄を除く更新は持たない。
3. **読み戻しはqueue serviceの中で行い、全文を既定にする（論点c）。** 鍵を持つ行の本文はqueue serviceのプロセスだけが置き場から読み、置いた全文に行の欄を重ね、予約した欄を除いて完全な本文を答える。同じ名前の欄は行を正にする。client modeとrunnerは本文の置き場の資格を持たず（[ADR-t3990-4](2026-11-04-t3990-4-team-version-control-side-observability-by-stdout-logs-otlp-and-existing-ssot-commands.md)決定3の、資格を渡さない線）、[HTTPのAPI](2026-11-04-t3990-1-team-version-http-api-carries-use-cases-with-dagq-tokens-and-an-api-version-range.md)の答えも完全な本文になる。eventの本文を読む読み取りは、書き込みのtransactionの中のものを含めて全文に戻す。戻さない読みは一覧や集計で、集合の欄だけを型で取り出す形にし、本文のobjectを渡さない。行の本文の列を、戻さないまま完全な本文として読む経路は、型か境界のtestで作れないようにする。行の本文は欠けていても正しいobjectなので、エラーにならず黙って欄を失うからである。
4. **読みは欠けを隠さず、置くときは書き込みを止めない（論点c）。** 全文の読みは、置き場に届かないときも物が無いときも失敗にする。行の欄だけを完全な本文として答えない。無い欄を無いと読んだ判断が状態を誤らせるからである。例外は人のprincipalに見せる読みで、行の欄と、戻せなかったことの明示の印を答える。planner・inbox・observerなどのactorには印付きの答えを返さず失敗にする。書き込みのtransactionの中の全文の読みが失敗すれば、そのtransactionは何も書かず、呼び出し元が送り直せる答えで拒む。書き込みの係の列を止める時間には、1回の呼び出しとtransactionの両方に上限を置き、障害を覚えている間は置き場を待たずに諦める。置くときは、置き場に届かないか拒まれれば、上限の内で諦めて本文をそのまま行に入れ、鍵を持たせず、置けなかったことを記録する（ADR-t3982-1決定6の「置かなかったとき」に当たる）。
   物が無いのは行が鍵を持つのに参照先が消えた整合の破れなので、届かないときと分けて記録する。人だけが使えるユースケースでその物を失ったと確定でき、確定した行は欠けを既知の印付きで読め、状態の判断も古いeventの移しも進む。本文の置き場に期限（lifecycleのexpiration）を付けないことは配置する側が守ることにする。
5. **古いeventの写しは本文を戻した完全な行にし、鍵を持つ行を読む経路と混ぜない（論点d）。** [ADR-t3986-1](2026-11-03-t3986-1-write-leader-fencing-trigger-placement-postgres-migration-series-archive-local-import-and-store-tests.md)決定8が古いeventを置き場へ移すとき、鍵を持つ行は決定3の形で本文を戻し、完全な本文を写しに書く。写しは鍵を持たず、DuckDBなどが写しだけで読める。本文を戻せない行を含む区切りは移さず、後で試し直す。読む側は1つの読み取りの入口だけを見て、その下でDBの行は鍵で戻し、写しの行は鍵を辿らない。閉じたtaskの開き直しで写しをDBに読み戻す行は、普通のeventの書き込みと同じ判定を通り、IDを保ったまま新しい鍵を持つ。ローカルからのimport（ADR-t3986-1決定9）も同じ判定を通るので、その中身の照合は本文を戻して正規化した形で行い、照合の間は置き場を読む。
6. **片付けは参照されない物だけを消し、portを広げない。** 孤児の片付けは、DBのどの行からも参照されず、書き込みのtransactionより十分長い猶予を過ぎた物だけを消す。確定しなかった本文と、決定5で写しに移った行の物は、同じ片付けで消える。物の一覧はS3互換の置き場を持つ保守の役が読み、行の書き込みと読みが使うport（置き・読み・消すだけ）には足さない。本文の物の置き場（prefix）はqueueごとに分け、別のDBと共有しない。別のDBの行から参照される物を消さないためである。写しが完全なので、この片付けはADR-t3986-1決定8の「dagqは写しを消さない」に触れない。

## Alternatives

- **kindごとに行に残す欄を宣言する**（決定1）: 行を小さくできるが、kindを絞らない式（索引の式を含む）があり、kindと欄の表を書き込みと読みの両方で保つことになる。忘れれば黙って欄を失う。鍵を持つ行は少なく、行が少し大きいことの害は小さいので、名前の集合にする。
- **SQLが読む欄をeventの表の列にする**（決定1）: 型は正しくなるが、多くの欄を2つのmigrationの系列で持ち、全部のSQLを書き直し、ローカルのschemaと動きを変える。
- **鍵を行の専用の列に持つ**（決定1）: 欄の名前の衝突は無くなるが、本文の列だけを読む文を全部直し、ローカルのschemaを変えることになる。予約した欄なら、本文の列だけを読む文も鍵を受け取れ、ローカルの行の形も変わらない。
- **行に残さない欄だけを置く**（決定1）: 同じ欄を2か所に持たずに済むが、ADR-t3982-1決定6の「本文を通す」から外れてamendsが要り、置いた物だけでは本文が分からない。本文を丸ごと置き、重なりは「行を正」で解く。
- **チームの版でも当面は外に置かない**（決定1）: 仕組みが要らず、ADR-t3982-1決定6でも許される。ただしADR-t3981-1決定1が大きなeventを置き場に置くと決めており、この判断は外へ置くadapterを足す時の材料である（Consequencesの測定）。形を決めないまま足せば欄を黙って失うので、形はここで決める。
- **鍵を持つ行に足すとき、置いた本文を読み直して置き直す**（決定2）: 本文を1か所に保てるが、足すたびに置き場の読みと書きが書き込みの係の列を止め、古い鍵が孤児になる。置き場の障害が足す元の記録を止める。
- **足す欄を最初の書き込みに含める**（決定2）: 更新が要らなくなるが、作業の内訳とtokenは後で閉じるspanから求まる。findingのIDは、そのeventを根拠に持つfindingを書いた後に決まり、最初の書き込みには間に合わない。
- **読む側が鍵を読み戻す**（決定3）: client modeとrunnerに置き場の資格を配ることになり、読み手ごとに戻し方と障害の扱いが分かれる。
- **行の本文をそのまま渡す読みを宣言で許す**（決定3）: 置き場の読みは減るが、読む側が除かれた欄を無いものとして読み、今回直す穴と同じ型になる。集合の欄だけを取り出す形にする。
- **書き込みのtransactionの中では置き場を読まず、行の欄だけで判断する**（決定3）: 書き込みの列は止まらないが、判断が読む欄を全て集合に載せる必要があり、Rustの読みは機械で確かめにくい。漏れれば黙って判断を誤る。鍵を持つ行は少ないので、上限の内で止まる害より黙って誤る害を重く見る。
- **どの読みでも、置き場に届かなければ行の欄だけを答える**（決定4）: 止まらないが、無い欄を無いと読む判断が状態を誤る。人に見せる読みにだけ、印を付けて許す。
- **置き場に届かないとき書き込みを失敗させる**（決定4）: 行と置き場の役割は分かりやすいが、本文の置き場の障害が状態の遷移を止める。行に入れれば行が大きくなるだけで、古いeventの移しで後に解消する。
- **portに物の一覧を足して片付ける**（決定6）: 1つのportで済むが、ADR-t3982-1決定5の「置き・読み・消すだけ」を変える。片付けだけの役に分ければ、行を書き読む経路は一覧の能力を持たない。
- **写しに鍵のまま残す**（決定5）: 写しは小さくなるが、集計が写しだけで読めず（ADR-t3986-1決定8）、物を消せなくなる。

## Consequences

- ローカルの既定のadapterは今までどおり外に置かないので、行の形・schema・読める値は変わらない。
- 外へ置くadapterを足す段は、行の形、足す欄の更新、全文の読みの戻し、欄の集合と境界のtest、失ったと確定するユースケース、片付けを実装する。鍵だけの行を固定している今のtestと`docs/design/`の記述は、その段が直す。
- 長い欄が集合に入るeventは外に出ないので、queue DBは小さくならない。本番の大きなeventの長い欄が何かは測っていない。外へ置くadapterの実装の前に測り、効果が小さければ後回しにするかを決める。
- 本文を置く間と、書き込みのtransactionの中で読む間は、書き込みの係の列が止まる。鍵を持つ行が少なく、上限があるので受け入れるが、着地の後に実際の頻度と時間を見る。
- 置き場の障害の間は、鍵を持つ行の全文を読む書き込みが拒まれる。状態の判断が鍵を持つ行に当たれば、障害が直るまでその判断は進まない。関係のない書き込みは進む。
- 置いた本文と行で短い欄を二重に持つ。鍵を持つ行は少ないので、大きさの害は小さい。
- 決めていないもの: runのファイルをportに通す時点（ADR-t3982-1のとおりrunnerの側）、置き場のbackupと復元。閾値・上限・猶予の値はコードの定義のそばに置く。
