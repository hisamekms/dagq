# ADR-t3920-1: 着地の絞ったITは古い表も使い、表が知らないファイルを広げる

## Context

[ADR-t1925-1](2026-10-07-t1925-1-landing-verifies-unit-tests-and-selected-integration-tests-and-ci-is-the-final-gate.md)決定2は、ITを全部流す条件の1つを「表が取れないか古すぎるとき」とし、古さの上限は測定の「決めたこと」の3（生成から48時間）に拠った。
CIの対応表の作り直しが2日続けてrunnerの都合でcancelledになると、表が48時間を超え、着地の検証は全てITを全部流した。
検証は3〜8分から31〜38分に伸び、着地は1時間に約1件まで落ちた。
表の古さは崖で、48時間を1秒超えると選び方の手がかりを全部捨てていた。

[測定](../plans/landing-it-selection.md)の「表の古さの追加の測定」では、古い表で漏れるテストはどの古さでも中央値・p90とも0本で、48時間をまたいで漏れが急に増えることは無かった。
古さは主に表に無いIT（表の後に足されたtest）を余分に流す側に効き、それは必ず流している。
一方「古さの材料」では、表の後に変わったsrcのファイルの割合は7日でほぼ1.0で、7日の表はファイルとITの対応の根拠にならない。

amendsにするのは、ADR-t1925-1の決定のうち決定2の全部流す条件の古さの扱いだけが変わり、他の決定（表に無いITを必ず流すこと・閾値・共通のファイル・CIが最終関門）は変わらないため（[ADR-t1091-1](2026-09-30-t1091-1-amend-or-replace-by-number-of-decisions.md)）。
[ADR-t2892-1](2026-10-20-t2892-1-landing-it-leaves-added-sources-and-broad-entries-to-ci.md)の決定1（表のtreeに無いsrcのファイルからは何も選ばない）と決定3（全部流す条件の列挙）も、古い表のときだけ変わる。

## Decision

1. **表の古さに2つの段を置く。**
   古い表の段（生成からの時間が短い方の段を超え、上限以内）の表は使い続け、古さだけをITを全部流す理由にしない。
   上限を超えた表は、ファイルとITの対応の根拠にならないとみてITを全部流す。
   ITを全部流す古さの理由は、表が取れない・読めない（形の版の違い・壊れ）・上限を超えて古いときだけになる。
   2つの段の値と根拠は測定の「決めたこと」の3に置く。
2. **古い表では、表が知らないファイルを近くの項目のITに広げる。**
   表が知らないファイルは、差分のsrc・cratesの`.rs`（unit testだけのファイルを除く）のうち、表のcommitのtreeに無いものと、表のcommitの後にmainで変わったものである。
   広げる先は、同じdirectoryのsrc・cratesの`.rs`の項目と、そのdirectoryを宣言するmoduleの項目のITの和で、広い項目（ADR-t2892-1決定2）は和に入れない。
   ファイルのコードはそれを宣言するmoduleを通って使われ、同じdirectoryのファイルが最もよく使うので、その項目のITが最もそのファイルに当たりやすい。
   表に載っているファイルは自分の項目のITも今どおり選ぶ。
3. **広げたITも閾値に数える。** 絞ったITの見込みが閾値を超えればITを全部流す（ADR-t1925-1決定2の閾値のまま）。
4. **着地の検証の出力は、古い表を使ったことと、広げたファイルとその理由・広げたITの数を名指す。**

古くない表（短い方の段以内）の扱いは変えない。表のtreeに無いsrcのファイルは今どおり何も選ばずCIに任せる。

## Alternatives

- **48時間の上限のまま全部流す**: 漏れは最も少ないが、表の作り直しが止まった間の全ての着地が全件の検証になり、着地が1時間に約1件まで落ちた。測定は48時間を超えても漏れが増えないことを示し、全件の代価に見合わない。
- **古い表もそのまま使い、何も広げない**: 全件にならず速いが、表の後に変わったファイルの対応の変化を拾わない。古さとともに変わったファイルは増える（2日で約0.55）ので、古いときだけ選ぶ範囲を広げる。
- **広げる先を親のmoduleだけにする**: 狭く速いが、同じdirectoryのファイルどうしの使い合いを外す。
- **広げる先をcrate全体にする**: 漏れは少ないが、rootのcrateではほぼ全部のITになり、全件と変わらない。
- **上限を設けない**: 7日を超えると対応の変化がほぼ全部のファイルに及び、表は選択の根拠にならない。

## Consequences

- 表の作り直しが2日止まっても、着地の検証は全件に落ちず、表に無いITと広げたITの分だけ長くなる。
- 古い表を使った着地は出力に古さを残すので、表が古くなったことを着地の記録から拾える。表の古さそのものの見張りは別の仕組みが受け持つ。
- 表のcommitの後に変わったファイルの数え方は、表のcommitと着地の基点のmainの差分で、表のcommitがrepositoryに無ければ今どおり全部流す。その差分が取れないとき、古い表では広げる先が分からないのでITを全部流し、古くない表では使わないので選び方を変えない。
- 広げる規則は名と位置だけで決めるので、別のdirectoryから使われる経路は外す。外れはCIが最終関門で拾う。
- 置き場: 2つの段の値と根拠は[着地のITの絞り込みの測定](../plans/landing-it-selection.md)の「決めたこと」、選び方の今の姿は[Validation](../design/supervisor-lifecycle/validation.md)とscriptの冒頭が持つ。
