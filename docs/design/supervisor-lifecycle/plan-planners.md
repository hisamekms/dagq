# `plan` / `planners`

> **goal 92**: runtimeのplannerの対話の経路は廃止し（[ADR-t1433-2](../../adr/2026-10-03-t1433-2-abolish-the-interactive-route.md)決定3）、runtimeのplannerは非対話でbackgroundのwrapperだけで動く（[ADR-t1433-3](../../adr/2026-10-03-t1433-3-headless-wrappers-run-only-in-the-background.md)）。`[roles.runtime_planner]`の経路の欄は受け付けて無視し、runtimeのplannerのworkspace、その画面からのidleの推定（ADR-t803-1）と打ち込み、`planner screen` / `planner send`の画面の読み取りと送信は無くなった（task 1441、[runtimeのplannerの経路](#runtimeのplannerの経路)）。廃止前から開いている人のplannerの行は、supervisorがcmuxを呼ばずに閉じた扱いにし（ADR-t1433-2決定5、下の「人のplannerの終わり」）、どのplannerの画面も読まず、どのplannerにも打ち込まない。末尾の予定の節はこれらの決定に合わせてある。

> 人が開くplannerは[ADR-t1394-1](../../adr/2026-10-03-t1394-1-abolish-person-planners-and-route-planning-through-inbox-requests.md)で廃止し、計画の入口をinboxからの依頼にする。依頼の記録・CLI・依頼ごとのruntimeのplanner・結末・`planner_question`の行き先は実装した（[inboxからの計画の依頼](#inboxからの計画の依頼)）。`dagq plan`は案内を付けて拒む（task 1399、下の`dagq plan`）。人のplannerを前提にした行き先の読み替えは実装した（末尾の[予定: inboxからの依頼と非対話のplanner](#予定-inboxからの依頼と非対話のplanner)の2）。廃止前から開いている人のplannerの行は、ADR-t1433-2決定5（ADR-t1394-1決定1・7・9をamends）のとおり、supervisorがcmuxを呼ばずに閉じた扱いにする（下の「人のplannerの終わり」と末尾の予定の1）。runtimeのplannerの経路（対話・非対話）は[ADR-t1394-2](../../adr/2026-10-03-t1394-2-runtime-planner-route-interactive-or-headless.md)の決定1・2・3・5と、区間と`stats` / `kpi`の経路ごとの集計の決定4を実装し、その後ADR-t1433-2決定3で対話の経路を廃止して非対話だけにした（task 1441、下の[runtimeのplannerの経路](#runtimeのplannerの経路)）。ADR-t1228-1のCLIの非対話の扱い（続きの依頼の`planner request`と、非対話のplannerの`planner screen` / `planner send`の答え方）は[ADR-t1533-1](../../adr/2026-10-03-t1533-1-follow-up-requests-go-to-headless-planners-by-planner-id-and-no-planner-close.md)のとおり実装し、task 1441でその答え方をworkspaceのplannerにも広げた（下の[続きの依頼と非対話のplannerのCLI](#続きの依頼と非対話のplannerのcli)）。plannerを閉じるCLIは作らない（同ADR決定2。runtimeのplannerはsupervisorが閉じる）。

[ADR-0044](../../adr/0044-findings-proposals-from-findings-and-quiet-observer.md)の決定1・6・12・13。plannerは常駐せず、proposalごと（と依頼・draft・findingごと）にオンデマンドで非対話のwrapperをbackgroundに起動する（workspaceは開かない）。use caseは`src/application/planner.rs`、entry pointは`compose::planners` / `compose::planner_session`（`dagq plan`は`main.rs`で拒む）。

- **記録**: planner 1つが`planners`表（schema v23、[persistence](../persistence.md)）の1行。`session_workspaces`はroleが主キーでplannerを1つしか持てないので使わない。行は`origin`（`person` / `runtime`）、runtimeが立てたときの`proposal_id`、session（`workspace_id`、UNIQUE。runtimeのplannerはbackgroundのwrapperのhandle`background:<pid>:<start>`、廃止前の人のplannerと古いバイナリが開いた対話のruntimeのplannerはworkspaceのUUID）、session wrapperの`wrapper_pid` / `agent_pid` / `heartbeat_at` / `exit_code` / `exited_at`、終わった印の`closed_at`と`error`、agentの経路の`route`（schema v60、`migrations/0060_planner_route.sql`。`headless`か、NULLの`interactive`。runtimeのplannerは開くときに`set_planner_route`で常に`headless`を書き、`interactive`は過去の行の履歴として読む）を持つ。plannerのディレクトリは`<queue dir>/planners/<planner-id>/`で、初期prompt（`prompt.txt`）、wrapperとして動くバイナリの写し（`runner`。runの`runner`と同じく、ビルドし直しても動いているplannerは変わらない）、runtimeのplannerではturnの依頼と出力（`turns/`）・turnのClaudeのsettings（`claude-headless-settings.json`）・backgroundのwrapperの出力（`session.log`）、Claudeのdebug log（`claude.log`、`PLANNER_DEBUG_LOG`）、idle marker（`idle.json`）とその履歴（`idle.log`。runと同じhookやwrapperが書き、`running`の処理を載せないmarkerで切り詰める。[stats](stats.md#stats)）、supervisorの入力の印（`supervisor-input.json`）を置く。人のplannerではClaudeのsettings（`claude-settings.json`）、入力の印（`prompt-submit.json`）も置く（画面のidleの区間の`screen-idle.json`は、人のplannerの画面を読まなくなったので書く処理が無く、前のバイナリが書いたものが残るだけ）。
- **`dagq plan`**（[ADR-t1394-1](../../adr/2026-10-03-t1394-1-abolish-person-planners-and-route-planning-through-inbox-requests.md)決定1、task 1399）: 何も開かず、行も作らず、cmuxもClaudeも呼ばずに失敗し、errorに案内（`application::planner::PLAN_REFUSED`）を出す: 人が開くplannerは廃止したこと、計画はinboxに人の言葉で頼み、inboxが計画の依頼として記録する（`dagq request add --text '...'`。`DAGQ_ROLE`の無いterminalの人も打てる）と、supervisorがruntimeのplannerを立ててsubmitか理由付きの却下まで進めること（`dagq requests`で追う）、開いているplannerは終わるまで動くこと（`dagq planners`）、plannerは開かなかったこと。前の`plan`の引数（`--plugin-dir` / `--repo` / `--cmux` / `--claude`）は受け付けて無視し、同じ案内を出す。権限の検査（`planner.open`）は前のままなので、打てるactor（人・inbox・planner・supervisor）は案内を、打てないactor（observer・worker・job）は今までどおりの`authorization_denied`を受ける。人が`DAGQ_ROLE`の無いterminalで打つ`add` / `goal add` / `submit`は今までどおり通る（決定8）。

- **runtimeが立てるplanner**: `open_runtime_planner(launch, proposal, tasks, reasons)`がproposalの存在を確かめ、`origin: runtime`・`proposal_id`付きの行でplannerを開く（workspaceのtitleは無い）。初期promptは`runtime_planner_prompt`で、proposal、そのtask（ID・状態・title）、plan reviewの指摘（reasons）と記録を読むCLI（`prompt::RECORD_READING`、ADR-0044の決定22、task 420: `dagq events --full --task ID`と絞り込み（`--run` / `--goal` / `--kind` / `--since` / `--until`。`--kind`が無ければattentionだけなので、全種類は`--all`を足す）と`dagq timeline RUN`）と、verify・paths・evidenceを決める順（`prompt::repository_rules`。[Prompt](prompt.md#repositoryの規則を読む順)）を載せ、直して`dagq submit --proposal <id>`で出し直すこと、計画の意図を変える修正はinboxにaskして答えを待つことを指示する。reasonsとtaskの行は上限の中に収め（全体`RUNTIME_PLANNER_PROMPT_LIMIT`。task 1571、値と理由は[Prompt](prompt.md#goal-reviewrunのreview復旧jobruntimeのplannerの上限)）、省いたreasonは`dagq events --full --task <anchor> --kind plan_review_finished`（`open_runtime_planner`が最新の`plan_review_finished`の`proposal_id`または`reopened[].proposal_id`から記録先のtask IDを取り、promptに具体的なIDを書く。reopenでは元のreviewのanchorを使う。該当eventが無ければanchorが不明で全文を読む既知の方法は無いと書き、コマンドを案内しない）、省いたtaskは`dagq proposal show <id>`で読むと書く。promptのbyte数は`planner_prompt_written`（`prompt: runtime`。[Session prompts](session-prompts.md)）に記録する。`DAGQ_PLANNER_ORIGIN=runtime`で出し直すので、そのplannerがproposalの持ち主になる。supervisorはplan reviewのrevise（持ち主のplannerが生きていないとき）とreopenでこれを呼ぶ（[Plan review (supervisor)](plan-review.md#plan-review-supervisor)の9）。follow_upの経路はgoal 29の後続taskが足す。
- **session wrapper（`planner-session`、hidden）**: runの`session`と同じく、自分を`register_planner_wrapper`で登録する（1つのplannerに1回だけ。閉じたplannerは拒む）。runtimeのplannerのwrapperは下の「非対話のplannerのwrapper」で動く。以下の対話のagentは廃止前の人のplanner（origin `person`）のwrapperだけのもので、`AgentProvider::planner_command`（Claudeでは`claude --debug-file <dir>/claude.log --add-dir <dir> --settings <dir>/claude-settings.json [--plugin-dir PATH] -- '<prompt>'`をrepository rootで。settingsは`stop_hook_settings`で、`Stop` hookが`<dir>/idle.json`を書き、入力欄のサジェストは止めない（画面の無いruntimeのplannerとworkerのturnにはサジェストの設定が当たらない）。[Agent provider lifecycle](../provider-lifecycle.md)）でagentを起動し（argvに`--model` / `--effort`があれば`AgentProvider::select_model`で渡す）、`register_planner_agent`し、agentが終わるまで`wait_interval`ごとに`heartbeat_planner`し、終了コードを`planner_exited`で記録する。terminalには何も出さない（ADR-t1300-1のworkspaceを閉じる予告と猶予はADR-t1433-2決定5で対象が無い。workspaceはruntimeもwrapperも閉じず、人が自分のterminalで閉じる）。logは`<queue dir>/logs/planner-session-*.jsonl`。**登録を断られたwrapper**: 閉じた行か、別のwrapperが登録済みの行で`register_planner_wrapper`が断ると、wrapperは断られたことをlog（`warn`）に書いてerrorで終わる（`application::session::wrapper_refused`）。workspaceの中で動く古いwrapperも、そのworkspaceを閉じない（cmuxを呼ばない。hiddenの`--cmux`は古いargvのために受け付けて使わない）。
- **非対話のplannerのwrapper**: `route`が`headless`の行のwrapper（runtimeのplannerのすべて。`planner-session --headless --background`）は、agentを1つ起動する代わりに非対話のworkerと同じ`Turns`でturnを動かす（下の[runtimeのplannerの経路](#runtimeのplannerの経路)、[非対話のworker](headless-worker.md#非対話のruntimeのplanner)）。端末は要らず（`--headless`の無いwrapperだけが端末を確かめる）、終了の依頼で0、sessionを終わらせたturnの後は1で`planner_exited`を記録する。
- **生存とidleの判定**（`planner_view`、`PlannerSession::state`）: runtimeのplanner（非対話）は画面を読まず、turnとmarkerで判定する。閉じた行か、sessionが居なければ`closed`（runtimeのplannerのsessionはbackgroundのhandleで、居るかはそのプロセス（`exists`。pidと記録した起動時刻）で見る）。cmuxのworkspaceを記録した行（古いバイナリが開いたruntimeのplannerの対話の行と`[headless] wrapper = "workspace"`で開いた非対話の行、廃止前の人のplannerの行。`workspace_id`がbackgroundのhandleでないもの）は、originに依らずcmuxに問わず`closed`と読む（`retired_workspace`。ADR-t1433-2決定3・5）。sessionかwrapperの登録がまだなら`opening`、行を作ってから120秒（`PLANNER_STARTUP_SECS`）たってもそのままなら`lost`（wrapperが起動できなかった、開いたプロセスがsessionを記録する前に死んだ）。agentの終了が記録されていれば`exited`。wrapperのPIDが死んでいれば`lost`（heartbeatの古さで`lost`にするのはworkspaceのwrapperの行だけ）。wrapperが生きていてもagentのPID（`agent_pid`）をまだ記録していなければ、markerに依らず`opening`（agentの居ないplannerに依頼や文面を送らない。originに依らない）。それ以外は動いているsessionで、runtimeのplannerは、wrapperがturnの終わりに書くidle markerが最後の入力より新しく`turns/`に取られていない依頼が無ければ`idle`、そうでなければ`working`（下の[runtimeのplannerの経路](#runtimeのplannerの経路)の「状態」）。どのplannerの画面も読まない（人のplannerの行は`closed`と読まれるので、画面からのidleの推定もplannerの`idle_inferred`の記録も無い）。`alive`は`opening` / `working` / `idle`。`idle_since`はidleのときのmarkerの書かれた時刻（Unix秒）で、送った文面より後にidleになったかの比較に使える。runtimeのplannerに届けた`planner_question`の答えを読み終えたかは、その答えの依頼を取ったturnのevent（`turn_started`と、Claudeの壁で失敗していない`turn_finished`）で判じ（依頼の記録が無ければ`idle_since`と配送を取った時刻の比べ）、askが閉じた時刻とは比べない（askの`closed_at`は配送の後に書くので、その前にidleになったplannerを待ち続けて枠をふさいだ。task 884。下の「状態」）。上限で持ち主の居ないreviseが期限を過ぎて待つときは、何も待たないidleのruntimeのplannerに終了の依頼を置いて枠を空ける（`planner_released`。[Plan review (supervisor)](plan-review.md)の9）。人が開いたplannerには終わりを頼まない（行は下の「人のplannerの終わり」で閉じる）。
- **runtimeのplannerの時間切れ**: 画面からの推定も効かない対話のruntimeのplannerのbackstopだった`tell_of_silent_planners`（task 805。最後に動きが見えた時刻から`--planner-timeout`を過ぎたものに`planner_unresponsive`（`subject: "planner"`）を出した）は、対話の経路の廃止で削除した。runtimeのplannerはturnの`[stall]`の上限で時間を切られ、wrapperが上限で止めたturnを`tell_of_stopped_planner_turns`がplannerごとに1回`planner_unresponsive`（`subject: "planner"`）で知らせる（下の[runtimeのplannerの経路](#runtimeのplannerの経路)の「状態」）。`--planner-timeout`（既定3600秒、`PLANNER_TIMEOUT`）は、plannerに渡したreviseとplannerを待つreviseの時間切れ（`planner_unresponsive`、proposalのもの）と、枠をふさぐidleのplannerの解放（`release_runtime_planner`）に今までどおり使う。kind `planner_unresponsive`の`subject: "planner"`の知らせはqueueのevent（task・goal・runに付かない）で、`status`のattention（`silent_planners`）にはそのplannerの行が閉じるまで出て、draftのplannerならdraftのtaskに付く。人が開いたplannerは対象にしない。
- **人のplannerの終わり**（`close_person_planners`、`PlannerSession::person_retired`、[ADR-t1433-2](../../adr/2026-10-03-t1433-2-abolish-the-interactive-route.md)決定5。ADR-t1394-1決定1・7・9をamends）: 人が開いたplanner（origin `person`）で閉じていない行を、生きていても終わっていても（wrapperの有無・agentの終了・workspaceの有無に依らず）閉じ、`planner_closed`（`code: person_retired`、`workspace_closed: false`。ADR-t1300-1決定2のevent）を1回記録する。
  cmuxは呼ばない: そのworkspaceを一覧で探さず、`send`も`close`もせず、画面も読まない。
  残ったworkspaceは人が`DAGQ_ROLE`の無い自分のterminalで閉じる（理由の文にもそう書く）。
  行うのはsupervisorの`tend_planners`の各passの初め（`--no-claude`でも。`tend_planners`そのものを行わない回、つまり止める途中・claimを止めた間・queueの控え（`queue_hold`）の間は行わない）。
  行を閉じた後は、そのplannerが持っていたproposalのreviseと`planner_question`のanswerは、持ち主のplannerが閉じているときの経路（runtimeが新しい非対話のplannerを立てる。ADR-0047決定12、ADR-t1394-1決定7）で届く（reviseの持ち主の探し方は閉じていない行だけを見る。answerの行き先`planner_answer_route`はもともとruntimeのplannerだけを選ぶ）。
  ADR-t1300-1の猶予・cmuxの一覧と`close`・wrapperの予告と、人のplannerへの打ち込みは無い。

## runtimeのplannerの経路<a id="runtimeのplannerの経路"></a>

[ADR-t1394-2](../../adr/2026-10-03-t1394-2-runtime-planner-route-interactive-or-headless.md)の決定1・2。

goal 92で[ADR-t1433-2](../../adr/2026-10-03-t1433-2-abolish-the-interactive-route.md)決定3により対話の経路を廃止し、[ADR-t1433-3](../../adr/2026-10-03-t1433-3-headless-wrappers-run-only-in-the-background.md)決定1・2によりwrapperはbackgroundだけになった。

- **経路の欄の廃止**: 選ぶ経路は無く、runtimeのplannerは非対話だけ。supervisorはplannerを開くたび（reviseの`open_runtime_planner`、draft・finding・依頼の`open_draft_planner`）に行の`route`へ`headless`を書く（`launch_planner`。書けなければ行をerror付きで閉じる）。前の欄`[roles.runtime_planner]`の`route`は値に関わらず（`interactive`も）受け付けて無視し、supervisorがplannerを開くときに無視することを1回`warn`でlogに書き（`src/infrastructure/run_env.rs`、[Actor model](actor-model.md#runtimeのplannerの経路)）、ほかの`[roles.<role>]`の`route`は`route is a key of [roles.runtime_planner] only (and ignored there)`のerror、2度の定義は`defined twice`のerror。`[headless] wrapper`はplannerには読まない（workspaceの中かbackgroundかの選択は無く、backgroundだけ）。`dagq doctor`の`roles.runtime_planner`は常に`route: "headless"`を出し、`route_source`は無い。`planners.route`は過去の対話のplanner（NULLの`interactive`）を読むために残す。人が開いたplannerの行は対話（`interactive`）のままで、supervisorがcmuxを呼ばずに閉じる（上の「人のplannerの終わり」）。
- **非対話のplanner**: plannerのディレクトリに`turns/`（[非対話のworker](headless-worker.md#run-dirのturns)と同じ`request-NNNNNN.json`・`.taken.json`・`exit`・`limits.json`・`turn-NNNNNN.jsonl` / `.err`）を置き、wrapperが非対話のworkerと同じ`Turns`（`TurnOwner::Planner`）で動く。初期prompt（`prompt.txt`）が最初のturn。`turn_started` / `turn_finished` / `turn_session_identified`と、supervisorが書く`turn_requested`はqueueのevent（`planner_id`付き）。reviseの配送（`plan_revise_sent`）、`planner_question`のanswer（`ask_delivered`）、Claudeが使えなかったturnの続き（`tend_planner_walls`、下の「使えないとき」）、`end_runtime_planners`と`release_runtime_planner`の終わりの依頼は、`headless::send_to_planner`が次のturnの依頼（`what`は`revise` / `answer of ask <id>` / `provider retry`）と終了の依頼（`turns/exit`）にし、`submit_input`の打ち込み・Stop hook・画面からのidleの推定を使わない。wrapperはworkspaceを持たずbackgroundだけで動く（[ADR-t1404-1](../../adr/2026-10-03-t1404-1-headless-wrappers-run-as-detached-background-processes.md)、ADR-t1433-3。`[headless] wrapper`は読まない）。backgroundのhandleは`workspace_id`に入り、`dagq submit`はplannerの記録からそのhandleを持ち主にする。
- **状態**: `planner_view`は非対話のplannerで、wrapperがturnの終わりに書くidle markerが最後の入力（supervisorの入力の印を含む）より新しく、`turns/`に取られていない依頼が無ければ`idle`（`idle_since`はmarkerの時刻）、そうでなければ`working`（ただしmarkerのturnがClaudeのログイン切れ・利用上限・起動の失敗で終わっていれば、取られていない依頼が待っていても`idle`。wrapperはその依頼を`provider retry`の後まで取らないので、下の「使えないとき」の`tend_planner_walls`が見る。task 1596）、wrapperが死ねば`lost`。届けたanswerを読み終えるまでと、answerを届ける前（`question_wait`）は終了の依頼を置かない（人の答えだけを待つものは下）。届けたanswerを読み終えたかは、idle markerの秒と配送を取った秒の比べでなく（秒の比べでは、同じ秒のうちに終わったturnの後も待ち続けて`/exit`されなかった）、そのanswerの依頼（`turn_requested`の`what`が`answer of ask <id>`）を取ったturnが終わり、そのturnがClaudeのログイン切れ・利用上限・起動の失敗（`failure`が`authentication` / `usage_limit` / `launch`）で失敗していなければ読み終えたとし、壁で失敗したturnだけでは読み終えたとせず、wrapperが次に取る`provider retry`のturn（そのanswerを載せる）が壁で失敗せずに終わるまで追う（`headless_answer_taken`、判断は`src/domain/turn.rs`の`request_read`。壁で失敗したturnの後にplannerを終わらせると、answerが読まれずに失われるため。task 1596）。依頼の記録が無いときは、配送を取った秒（`planner_answer_claimed`）とidle markerの秒の比べ（人のplannerと同じ）。`planner_unresponsive`（`subject: "planner"`）は`--planner-timeout`でなく、wrapperがturnを`[stall]`の上限（`turn_silence_secs`の沈黙か`turn_limit_secs`）で止めたとき（idle markerの`outcome`が`silent` / `timed_out`）に、plannerごとに1回出る（`tell_of_stopped_planner_turns`。payloadは`subject`・`planner_id`・`origin`・`route`・`workspace_id`・`draft_task_id`・`finding_id`・`request_id`・`state`・`turn`・`outcome`・`reason`で、`proposal_id`・`last_activity`・`waited_secs`は持たない。廃止した対話の時間切れ`tell_of_silent_planners`の代わり）。止めたturnでsessionは終わるので、plannerは`runtime_exited`で閉じられ、決めずに終わったplannerに数える。掃除がpassより先に行を閉じたときも、掃除が同じ知らせを出す（ADR-t1394-2決定3）。idleで仕事が終わらないまま期限を過ぎるものは、reviseを渡されたplannerのreviseの時間切れ（`planner_unresponsive`、proposalのもの）が見る。
- **人の答えだけを待つplannerの終わり**（[ADR-t1704-1](../../adr/2026-10-05-t1704-1-human-answer-wait-releases-runtime-planner-slots.md)決定1・2・6）: idleの非対話のplannerを引き止めるものが、自分の未回答の`planner_question`と、それと並んで渡されたreviseだけなら、その場で判じ直し、askがまだ未回答であることと同じトランザクションで行の`answer_wait_at`とqueueのevent `planner_answer_wait`を書いてから終了の依頼を置く（askは閉じない）。
  `planner_answer_wait`の欄は`planner_id`・`workspace_id`・`asks`（待つaskのID）・`proposal_id`・`draft_task_id`・`finding_id`・`request_id`・`revise`（reviseを持っていたか）・`idle_since`・`reason`。
  行は`planner_closed`の`runtime_answer_wait`で閉じ、枠が空く。
  answerの依頼を書けなかったplanner（`ask_delivery_failed`）も、最後のturnの後に書いた依頼と読み終えていないanswerが無くなってから、そのaskが回答済みで閉じていないことと同じトランザクションで同じ印を付け（`asks`はそのaskと未回答の質問）、終了の依頼を置く。
  終了の依頼も書けなければ、`exit_timeout`の後にwrapperを止めて行を閉じる。
  印の付いた行はanswerの行き先から外れ、answerは行が閉じてから新しいplannerの初期promptで1回だけ運ばれ、前のplannerのnoteと作った・編集したdraftも載る（sessionはresumeしない。[Prompt](prompt.md#goal-reviewrunのreview復旧jobruntimeのplannerの上限)）。
  閉じた行は応答しないplannerの検出から外れ、決めずに終わった回数に数えない。
- **終わり**: 終了の依頼でwrapperが終わると、backgroundではhandleも無くなる。agentの終了が記録された行は、`end_runtime_planners`と行の片付けのどちらが閉じても`runtime_exited`。行の片付け（`close_abandoned_planners`）はbackgroundのhandleをcmuxの一覧でなく`exists`（pidと起動時刻）で判じ、生きているwrapperの行はheartbeatが遅れても閉じない。wrapperが殺されて残ったturnは、handleを閉じるときに止める（[非対話のworker](headless-worker.md#非対話のruntimeのplanner)）。
- **区間**: kind `runtime_planner`の区間を最初のturnから開いて`planner_closed`で閉じ（[非対話のworkerの区間](../provider-lifecycle.md#非対話のworkerの区間)と同じくturnから稼働時間とtokenを取る）、区間に`route: headless`を持たせる。`stats`の`sessions.by_route`・`planner_routes`と`kpi`の`session_*`の`route=`の層・`health.planner_routes`で経路ごとに読む（task 1398。runのclaim時の経路の`--by route`とは別に常に出す）。goal 92の後は新しい区間はすべて`headless`で、`route`は過去の対話の区間と比べるために残す。

## inboxからの計画の依頼<a id="inboxからの計画の依頼"></a>

[ADR-t1394-1](../../adr/2026-10-03-t1394-1-abolish-person-planners-and-route-planning-through-inbox-requests.md)の決定2〜7と10。人がinboxに計画を頼むと、inboxは人の言葉を依頼として記録し、supervisorが依頼ごとにruntimeのplannerを立て、plannerがsubmitか理由付きの却下まで進める。人が要る判断は`planner_question`だけでinboxに上がる。use caseは`src/application/supervise/request_planner.rs`、CLIの判定は`src/application/commands/requests.rs`、storeは`src/infrastructure/plan_requests.rs`（[Persistence](../persistence.md#planning-requestsplan_requestsrs)）、規則は`src/domain/plan_request.rs`（[Domain model](../domain-model.md#planning-requests)）、promptは`application::prompt::request_planner_prompt`、依頼の言葉の受け渡しは`application::planner_handoff`。run slotは使わず、`tend_planners`の中で、reviseの配送と`planner_question`のanswerの配送の後、[Draft planners](draft-planners.md)と[Finding planners](finding-planners.md)の前に進める（人が待っているので先にする）。

## 予定: inboxからの依頼と非対話のplanner<a id="予定-inboxからの依頼と非対話のplanner"></a>

[ADR-t1394-1](../../adr/2026-10-03-t1394-1-abolish-person-planners-and-route-planning-through-inbox-requests.md)（goal 87）の予定のうち、**まだ実装していない**もの（依頼の記録から結末までは上の[inboxからの計画の依頼](#inboxからの計画の依頼)、非対話のplannerは上の[runtimeのplannerの経路](#runtimeのplannerの経路)）。綴りと数値は実装のtaskが決める仮のもので、実装したらこの節を今の姿に書き直し、上の節の人のplannerの記述を消す（廃止前から開いている人のplannerは下の1のとおり行を閉じた扱いにする）。runtimeのplannerはgoal 92の[ADR-t1433-2](../../adr/2026-10-03-t1433-2-abolish-the-interactive-route.md)・[ADR-t1433-3](../../adr/2026-10-03-t1433-3-headless-wrappers-run-only-in-the-background.md)で非対話とbackgroundだけになるので、この節もその形で書く。

### 流れ

1. `dagq plan`の拒否は実装した（上の`dagq plan`）。廃止の時点で開いている人のplanner（origin `person`）は、[ADR-t1433-2](../../adr/2026-10-03-t1433-2-abolish-the-interactive-route.md)決定5のとおり、supervisorが行を閉じた扱いにして[ADR-t1300-1](../../adr/2026-10-02-t1300-1-runtime-closes-exited-person-planners-after-a-grace.md)決定2の`planner_closed`（`code: person_retired`、`workspace_closed: false`）を残し、そのworkspaceにはsendもcloseもしない（cmuxを呼ばない。上の「人のplannerの終わり」）。持ち主の居なくなったproposalへのreviseと`planner_question`のanswerは、持ち主のplannerが閉じているときの経路で、新しい非対話のplannerが受ける。残ったworkspaceは人が`DAGQ_ROLE`の無い自分のterminalで閉じる。人が`DAGQ_ROLE`の無いterminalで打つ`add` / `submit`は今までどおり通り、持ち主の居ないproposal（`owner_origin: person`、workspaceなし）のreviseはruntimeのplannerが受ける。
2. 人のplannerを前提にした行き先の読み替え: observerの古いdraft goal・goal closeの人の判断は、inboxがそのdraft・goalを参照にした依頼を記録するか、人が自分のterminalで決める。`draft_planner_exhausted`・`finding_planner_exhausted`・`dependency_stranded`のattention（`request a plan for the draft`・`request a plan for the finding`・`request a plan for the waiting tasks`）と`keep_draft`のdraftは、inboxがそのdraft・finding・taskを参照（`--ref task:N` / `--ref finding:N`）にした依頼を記録するか人が自分のterminalで決める案内に変えた（実装済み、[Draft planners](draft-planners.md)の4・5、[Finding planners](finding-planners.md)の8）。`keep_draft`のdraftには、この依頼の経路と並べて再検討の時刻の経路がある（実装済み、task 1540、[ADR-t1540-1](../../adr/2026-10-05-t1540-1-a-kept-draft-returns-to-runtime-planners-at-its-revisit-time.md)）: runtimeのplanner・人・inboxが`dagq revisit ID --at <時刻>`で時刻を付けたdraftは、その時刻にruntimeのplannerの対象に戻る（[Draft planners](draft-planners.md#再検討の時刻)）。時刻の無い`keep_draft`のdraftは今までどおり依頼を待つ。同じdraftに依頼と時刻の両方が来たら、`open`の依頼のplannerが先で、時刻はその後もdraftなら効く（上の3）。
3. `status`のinbox向けの欄（仮: `requests`）に、plannerを待っている`open`の依頼を出す（`--no-claude`の間に待っている依頼を人に見せるため。ADR-t1394-1のConsequences）。今は`dagq requests`で読む。
4. 開いているruntimeのplannerへの続きの依頼のCLI（`planner request`）は実装した（[ADR-t1533-1](../../adr/2026-10-03-t1533-1-follow-up-requests-go-to-headless-planners-by-planner-id-and-no-planner-close.md)、上の[続きの依頼と非対話のplannerのCLI](#続きの依頼と非対話のplannerのcli)）。宛先は生きている非対話のplannerだけで、対話のplannerには拒む。
