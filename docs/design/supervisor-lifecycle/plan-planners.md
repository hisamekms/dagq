# `plan` / `planners`

> **予定（goal 92）**: runtimeのplannerの対話の経路は廃止し（[ADR-t1433-2](../../adr/2026-10-03-t1433-2-abolish-the-interactive-route.md)）、非対話のplannerはbackgroundのwrapperだけで動く（[ADR-t1433-3](../../adr/2026-10-03-t1433-3-headless-wrappers-run-only-in-the-background.md)）。`[roles.runtime_planner]`の経路の欄と画面からのidleの推定（ADR-t803-1。置き換え済み）、plannerのworkspace、対話のplannerの`planner screen` / `planner send`の記述は、後続のtaskが実装するまでの今の姿である（[runtimeのplannerの経路](#runtimeのplannerの経路)の予定の注記も見る）。廃止前から開いている人のplannerは、新しいバイナリが行を閉じた扱いにし、そのworkspaceにcmuxを呼ばない（ADR-t1433-2決定5）。末尾の予定の節はこれらの決定に合わせてある。

> 人が開くplannerは[ADR-t1394-1](../../adr/2026-10-03-t1394-1-abolish-person-planners-and-route-planning-through-inbox-requests.md)で廃止し、計画の入口をinboxからの依頼にする。依頼の記録・CLI・依頼ごとのruntimeのplanner・結末・`planner_question`の行き先は実装した（task 1395、[inboxからの計画の依頼](#inboxからの計画の依頼)）。`dagq plan`は案内を付けて拒む（task 1399、下の`dagq plan`）。人のplannerを前提にした行き先の読み替えは実装した（末尾の[予定: inboxからの依頼と非対話のplanner](#予定-inboxからの依頼と非対話のplanner)の2）。廃止前から開いている人のplannerは、今はADR-t1394-1決定9のとおり終わるまで動き、下の「人のplannerの終わり」で閉じる（ADR-t1433-2決定5の、行を閉じた扱いにすることは**まだ実装していない**。末尾の予定の1）。runtimeのplannerの経路（対話・非対話）は[ADR-t1394-2](../../adr/2026-10-03-t1394-2-runtime-planner-route-interactive-or-headless.md)の決定1・2・3・5（task 1396・1397）と、区間と`stats` / `kpi`の経路ごとの集計の決定4（task 1398）を実装した（下の[runtimeのplannerの経路](#runtimeのplannerの経路)）。ADR-t1228-1のCLIの非対話の扱い（続きの依頼の`planner request`と、非対話のplannerの`planner screen` / `planner send`の答え方）は[ADR-t1533-1](../../adr/2026-10-03-t1533-1-follow-up-requests-go-to-headless-planners-by-planner-id-and-no-planner-close.md)のとおり実装した（task 1533、下の[続きの依頼と非対話のplannerのCLI](#続きの依頼と非対話のplannerのcli)）。plannerを閉じるCLIは作らない（同ADR決定2。runtimeのplannerはsupervisorが閉じる）。

[ADR-0044](../../adr/0044-findings-proposals-from-findings-and-quiet-observer.md)の決定1・6・12・13。plannerは常駐せず、proposalごとにオンデマンドのworkspaceを開く。use caseは`src/application/planner.rs`、entry pointは`compose::planners` / `compose::planner_session`（`dagq plan`は`main.rs`で拒む）。

- **記録**: planner 1つが`planners`表（schema v23、[persistence](../persistence.md)）の1行。`session_workspaces`はroleが主キーでplannerを1つしか持てないので使わない。行は`origin`（`person` / `runtime`）、runtimeが立てたときの`proposal_id`、workspaceのUUID（`workspace_id`、UNIQUE）、session wrapperの`wrapper_pid` / `agent_pid` / `heartbeat_at` / `exit_code` / `exited_at`、終わった印の`closed_at`と`error`、agentの経路の`route`（schema v60、`migrations/0060_planner_route.sql`。`headless`か、NULLの`interactive`。開くときに`set_planner_route`で書く）を持つ。plannerのディレクトリは`<queue dir>/planners/<planner-id>/`で、初期prompt（`prompt.txt`）、wrapperとして動くバイナリの写し（`runner`。runの`runner`と同じく、ビルドし直しても動いているplannerは変わらない）、Claudeのsettings（`claude-settings.json`）・debug log（`claude.log`、`PLANNER_DEBUG_LOG`）・idle marker（`idle.json`）とその履歴（`idle.log`。runと同じhookが書き、`running`の処理を載せないmarkerで切り詰める。[stats](stats.md#stats)）、入力の印（`prompt-submit.json`）、supervisorが打った文の印（`supervisor-input.json`）、画面のidleの区間（`screen-idle.json`。[画面からのidleの推定](receipt-and-session-exit.md#画面からのidleの推定)）を置く。

- **runtimeが立てるplanner**: `open_runtime_planner(launch, proposal, tasks, reasons)`がproposalの存在を確かめ、`origin: runtime`・`proposal_id`付きの行で`[<repo>]planner#<id> - proposal <proposal-id>`を開く。初期promptは`runtime_planner_prompt`で、proposal、そのtask（ID・状態・title）、plan reviewの指摘（reasons）と記録を読むCLI（`prompt::RECORD_READING`、ADR-0044の決定22、task 420: `dagq events --full --task ID`と絞り込み（`--run` / `--goal` / `--kind` / `--since` / `--until`。`--kind`が無ければattentionだけなので、全種類は`--all`を足す）と`dagq timeline RUN`）と、verify・paths・evidenceを決める順（`prompt::repository_rules`。[Prompt](prompt.md#repositoryの規則を読む順)）を載せ、直して`dagq submit --proposal <id>`で出し直すこと、計画の意図を変える修正はinboxにaskして答えを待つことを指示する。reasonsとtaskの行は上限の中に収め（全体`RUNTIME_PLANNER_PROMPT_LIMIT`。task 1571、値と理由は[Prompt](prompt.md#goal-reviewrunのreview復旧jobruntimeのplannerの上限)）、省いたreasonは`dagq events --full --task ID --kind plan_review_finished`、省いたtaskは`dagq proposal show <id>`で読むと書く。promptのbyte数は`planner_prompt_written`（`prompt: runtime`。[Session prompts](session-prompts.md)）に記録する。`DAGQ_PLANNER_ORIGIN=runtime`で出し直すので、そのplannerがproposalの持ち主になる。supervisorはplan reviewのrevise（持ち主のplannerが生きていないとき）とreopenでこれを呼ぶ（[Plan review (supervisor)](plan-review.md#plan-review-supervisor)の9）。follow_upの経路はgoal 29の後続taskが足す。
- **session wrapper（`planner-session`、hidden）**: runの`session`と同じく、自分を`register_planner_wrapper`で登録し（1つのplannerに1回だけ。閉じたplannerは拒む）、`AgentProvider::planner_command`（Claudeでは`claude --debug-file <dir>/claude.log --add-dir <dir> --settings <dir>/claude-settings.json [--plugin-dir PATH] -- '<prompt>'`をrepository rootで。settingsはworkerと同じ`stop_hook_settings`で、`Stop` hookが`<dir>/idle.json`を書く。runtimeが立てたplanner（origin `runtime`）はworkerと同じく入力欄のサジェストを止める`promptSuggestionEnabled: false`も持ち（`runtime_session_settings`、[Agent provider lifecycle](../provider-lifecycle.md)）、人が開いたplannerは持たない。wrapperはoriginを`planners`の行から読んで`PlannerCommand`に渡す）でagentを起動し（argvに`--model` / `--effort`があれば`AgentProvider::select_model`で渡す）、`register_planner_agent`し、agentが終わるまで`wait_interval`ごとに`heartbeat_planner`し、終了コードを`planner_exited`で記録する。人が開いたplanner（origin `person`）では、記録の後にterminal（stderr）へ`dagq closes this workspace in 60 seconds (planner <id>, exit code <code>, log at <planner dir>/claude.log)`の1行を出し（`exited_notice`。書き先は`PlannerWrapper::terminal`で、`planner-session`ではstderr）、結果のJSONにも`notice`として載せる。workspaceを閉じるのは下の「人のplannerの終わり」のsupervisorで、wrapperは閉じない（ADR-t1300-1）。logは`<queue dir>/logs/planner-session-*.jsonl`。**登録を断られたwrapper**（task 806）: 閉じた行か、別のwrapperが登録済みの行で`register_planner_wrapper`が断ると、wrapperは断られたことをlog（`warn`）に書き、自分のworkspace（cmuxが渡す`CMUX_WORKSPACE_ID`）を行が記録していなければ（`workspace_id`が無いか別のもの）そのworkspaceを`cmux workspace close`で閉じてから（`application::session::wrapper_refused`）errorで終わる。createが失敗扱いになって行が閉じた後にcmuxが作ったworkspaceは、UUIDがどこにも無いので他に見つける手段が無いため。行が記録している自分のworkspace（同じplannerの2つ目のwrapperなど）は閉じない（そのplannerのものなので、終わらせる側に任せる）。行が読めなければ閉じない。閉じるcmuxはhiddenの`--cmux`（既定`cmux`、PATHで解決。launcherはargvに付けない）で、`CMUX_WORKSPACE_ID`が無ければ（cmuxの外）閉じずにlogだけ書く。
- **非対話のplannerのwrapper**: `route`が`headless`の行のwrapper（`planner-session --headless`、backgroundなら`--background`も）は、agentを1つ起動する代わりに非対話のworkerと同じ`Turns`でturnを動かす（下の[runtimeのplannerの経路](#runtimeのplannerの経路)、[非対話のworker](headless-worker.md#非対話のruntimeのplanner)）。端末は要らず（`--headless`の無いwrapperだけが端末を確かめる）、終了の依頼で0、sessionを終わらせたturnの後は1で`planner_exited`を記録する。
- **生存とidleの判定**（`planner_view`、`PlannerSession::state`）: 非対話は turn と marker、対話は planner の画面でも判定する。worker の画面の監視は廃止したが planner の対話は task 1441 まで残る。非対話のplannerは画面を読まず、idle markerが最後の入力より新しければ`idle`、そうでなければ`working`（下の[runtimeのplannerの経路](#runtimeのplannerの経路)）。対話のplannerは次のとおり。閉じた行か、workspaceのUUIDが`cmux workspace list`に居なければ`closed`。workspaceかwrapperの登録がまだなら`opening`、行を作ってから120秒（`PLANNER_STARTUP_SECS`）たってもそのままなら`lost`（cmuxがwrapperを起動できなかった、開いたプロセスがworkspaceを記録する前に死んだ）。agentの終了が記録されていれば`exited`。wrapperのPIDが死んでいるかheartbeatが30秒（`HEARTBEAT_TIMEOUT_SECS`）より古ければ`lost`。wrapperが生きていてもagentのPID（`agent_pid`）をまだ記録していなければ、markerや画面に依らず`opening`（agentの起動前の画面をidleと推定して、agentの居ないplannerに文面を送らない。originに依らない。task 1329）。それ以外は動いているsessionで、idle markerがplannerの最後の入力（`prompt-submit.json`、`supervisor-input.json`、行の`created_at`の遅い方）より新しければ、画面（`capture`）が作業中（`AgentSignals::working`）なら`working`、markerにbackgroundの作業が残っていなければ（`AgentSignals::idle_hook`）`idle`、残っていれば`working`。markerが無いか最後の入力より古ければ、画面からの推定（[画面からのidleの推定](receipt-and-session-exit.md#画面からのidleの推定)、ADR-t803-1）でidleで、画面にbackgroundの処理の表示（Claude Codeのstatus lineの`1 shell`など、`AgentSignals::screen_background`）が無ければ`idle`、そうでなければ（captureの失敗と、markerの`running`と同じく扱うbackgroundの表示を含む。task 823）`working`。`alive`は`opening` / `working` / `idle`。`idle_since`はidleのときのmarkerの書かれた時刻か、推定した区間の最初のcaptureの時刻（Unix秒）で、送った文面より後にidleになったかの比較に使える。推定でidleのときと、推定の区間にbackgroundの表示があって`working`のときは`idle_inferred`（`source`・`marker`・`since`・`observed_secs`・`captures`・`background_running`）も持つ。supervisorの`planner_views`は区間を持ち、区間ごとに1回queueのevent `idle_inferred`を記録する。これでStop hookが印を書けなかったruntimeのplannerも、仕事を終えれば`end_runtime_planners`が`/exit`を送り、終われば行を閉じる。backgroundの処理を残してturnを終えたplannerには、表示が消えて新しい区間が`screen_idle_secs`続くまで`/exit`を送らない（「Background work is running」の確認で止めてexit timeoutで閉じることを避ける）。`planner_question`の答えを打ち込まれたplannerは、`idle_since`が配送を取った時刻（`planner_answer_claimed`）より後なら答えを読み終えたとみなし、askが閉じた時刻とは比べない（askの`closed_at`は打ち込みの後に書くので、その前にidleになったplannerを待ち続けて枠をふさいだ。task 884）。上限で持ち主の居ないreviseが期限を過ぎて待つときは、何も待たないidleのruntimeのplannerを`/exit`して枠を空ける（`planner_released`。[Plan review ## runtimeのplannerの経路<a id="runtimeのplannerの経路"></a>

[ADR-t1394-2](../../adr/2026-10-03-t1394-2-runtime-planner-route-interactive-or-headless.md)の決定1・2（goal 87、task 1396）。

> **予定（goal 92）**: [ADR-t1433-2](../../adr/2026-10-03-t1433-2-abolish-the-interactive-route.md)決定3で対話の経路を廃止し、[ADR-t1433-3](../../adr/2026-10-03-t1433-3-headless-wrappers-run-only-in-the-background.md)決定1・2でwrapperはbackgroundだけになる。下の「選ぶ欄」の`route`は受け付けて無視し（値に関わらず`headless`）、後で`dagq.toml`から消す。`planners.route`は過去の対話のplannerを読むために残し、新しい行は`headless`になる。「非対話のplanner」の`[headless] wrapper`によるworkspaceの中かbackgroundかの選択は無くなり、backgroundだけになる。下の記述は、goal 92の後続のtaskが実装するまでの今の姿である。

- **選ぶ欄**: `[roles.runtime_planner]`の`route = "interactive" | "headless"`（既定`interactive`。[Actor model](actor-model.md#runtimeのplannerの経路)）。supervisorはplannerを開くたび（reviseの`open_runtime_planner`、draftとfindingの`open_draft_planner`）に`PlannerLaunch::roles`から読み、`headless`なら行の`route`に残す（`launch_planner`。書けなければ行をerror付きで閉じる）。動いているplannerの経路は変えない。人が開くplannerは常に対話。`dagq doctor`の`roles.runtime_planner`が`route`と`route_source`を出す。
- **非対話のplanner**: plannerのディレクトリに`turns/`（[非対話のworker](headless-worker.md#run-dirのturns)と同じ`request-NNNNNN.json`・`.taken.json`・`exit`・`limits.json`・`turn-NNNNNN.jsonl` / `.err`）を置き、wrapperが非対話のworkerと同じ`Turns`（`TurnOwner::Planner`）で動く。初期prompt（`prompt.txt`）が最初のturn。`turn_started` / `turn_finished` / `turn_session_identified`と、supervisorが書く`turn_requested`はqueueのevent（`planner_id`付き）。reviseの配送（`plan_revise_sent`）、`planner_question`のanswer（`ask_delivered`）、Claudeが使えなかったturnの続き（`tend_planner_walls`、下の「使えないとき」）、`end_runtime_planners`と`release_runtime_planner`の`/exit`は、`Supervisor::send_to_planner`が次のturnの依頼（`what`は`revise` / `answer of ask <id>` / `provider retry`）と終了の依頼にし、`submit_input`・Stop hook・画面からのidleの推定を使わない。wrapperはworkspaceの中かbackgroundかを[ADR-t1404-1](../../adr/2026-10-03-t1404-1-headless-wrappers-run-as-detached-background-processes.md)の`[headless] wrapper`で選ぶ（backgroundのhandleは`workspace_id`に入り、`dagq submit`はplannerの記録からそのhandleを持ち主にする）。
- **状態**: `planner_view`は非対話のplannerで、wrapperがturnの終わりに書くidle markerが最後の入力（supervisorの入力の印を含む）より新しく、`turns/`に取られていない依頼が無ければ`idle`（`idle_since`はmarkerの時刻）、そうでなければ`working`（ただしmarkerのturnがClaudeのログイン切れ・利用上限・起動の失敗で終わっていれば、取られていない依頼が待っていても`idle`。wrapperはその依頼を`provider retry`の後まで取らないので、下の「使えないとき」の`tend_planner_walls`が見る。task 1596）、wrapperが死ねば`lost`。`question_wait`（自分の`planner_question`を待つ）の間は`/exit`しないのは対話と同じ。届けたanswerを読み終えたかは、idle markerの秒と配送を取った秒の比べでなく（秒の比べでは、同じ秒のうちに終わったturnの後も待ち続けて`/exit`されなかった）、そのanswerの依頼（`turn_requested`の`what`が`answer of ask <id>`）を取ったturnが終わり、そのturnがClaudeのログイン切れ・利用上限・起動の失敗（`failure`が`authentication` / `usage_limit` / `launch`）で失敗していなければ読み終えたとし、壁で失敗したturnだけでは読み終えたとせず、wrapperが次に取る`provider retry`のturn（そのanswerを載せる）が壁で失敗せずに終わるまで追う（`headless_answer_taken`、判断は`src/domain/turn.rs`の`request_read`。壁で失敗したturnの後にplannerを`/exit`すると、answerが読まれずに失われるため。task 1596）。依頼の記録が無いときは対話と同じ秒の比べ。`planner_unresponsive`（`subject: "planner"`）は`--planner-timeout`でなく、wrapperがturnを`[stall]`の上限（`turn_silence_secs`の沈黙か`turn_limit_secs`）で止めたとき（idle markerの`outcome`が`silent` / `timed_out`）に、plannerごとに1回出る（`tell_of_stopped_planner_turns`。payloadは対話の時間切れの欄に`route`・`turn`・`outcome`を足し、`last_activity`と`waited_secs`は持たない）。止めたturnでsessionは終わるので、plannerは`runtime_exited`で閉じられ、決めずに終わったplannerに数える。掃除がpassより先に行を閉じたときも、掃除が同じ知らせを出す（ADR-t1394-2決定3）。idleで仕事が終わらないまま期限を過ぎるものは、reviseを渡されたplannerのreviseの時間切れ（`planner_unresponsive`、proposalのもの）が見る。

## 予定: inboxからの依頼と非対話のplanner<a id="予定-inboxからの依頼と非対話のplanner"></a>

[ADR-t1394-1](../../adr/2026-10-03-t1394-1-abolish-person-planners-and-route-planning-through-inbox-requests.md)（goal 87）の予定のうち、**まだ実装していない**もの（依頼の記録から結末までは上の[inboxからの計画の依頼](#inboxからの計画の依頼)、非対話のplannerは上の[runtimeのplannerの経路](#runtimeのplannerの経路)）。綴りと数値は実装のtaskが決める仮のもので、実装したらこの節を今の姿に書き直し、上の節の人のplannerの記述を消す（廃止前から開いている人のplannerは下の1のとおり行を閉じた扱いにする）。runtimeのplannerはgoal 92の[ADR-t1433-2](../../adr/2026-10-03-t1433-2-abolish-the-interactive-route.md)・[ADR-t1433-3](../../adr/2026-10-03-t1433-3-headless-wrappers-run-only-in-the-background.md)で非対話とbackgroundだけになるので、この節もその形で書く。

### 流れ

1. `dagq plan`の拒否は実装した（上の`dagq plan`）。廃止の時点で開いている人のplanner（origin `person`）は、[ADR-t1433-2](../../adr/2026-10-03-t1433-2-abolish-the-interactive-route.md)決定5のとおり、新しいバイナリが行を閉じた扱いにして[ADR-t1300-1](../../adr/2026-10-02-t1300-1-runtime-closes-exited-person-planners-after-a-grace.md)決定2の`planner_closed`を残し（codeは仮）、そのworkspaceにはsendもcloseもしない（cmuxを呼ばない）。持ち主の居なくなったproposalへのreviseと`planner_question`のanswerは、持ち主のplannerが閉じているときの経路で、新しい非対話のplannerが受ける。残ったworkspaceは人が`DAGQ_ROLE`の無い自分のterminalで閉じる。人が`DAGQ_ROLE`の無いterminalで打つ`add` / `submit`は今までどおり通り、持ち主の居ないproposal（`owner_origin: person`、workspaceなし）のreviseはruntimeのplannerが受ける。
2. 人のplannerを前提にした行き先の読み替え: observerの古いdraft goal・goal closeの人の判断は、inboxがそのdraft・goalを参照にした依頼を記録するか、人が自分のterminalで決める。`draft_planner_exhausted`・`finding_planner_exhausted`・`dependency_stranded`のattention（`request a plan for the draft`・`request a plan for the finding`・`request a plan for the waiting tasks`）と`keep_draft`のdraftは、inboxがそのdraft・finding・taskを参照（`--ref task:N` / `--ref finding:N`）にした依頼を記録するか人が自分のterminalで決める案内に変えた（実装済み、[Draft planners](draft-planners.md)の4・5、[Finding planners](finding-planners.md)の8）。`keep_draft`のdraftには、この依頼の経路と並べて再検討の時刻の経路がある（実装済み、task 1540、[ADR-t1540-1](../../adr/2026-10-05-t1540-1-a-kept-draft-returns-to-runtime-planners-at-its-revisit-time.md)）: runtimeのplanner・人・inboxが`dagq revisit ID --at <時刻>`で時刻を付けたdraftは、その時刻にruntimeのplannerの対象に戻る（[Draft planners](draft-planners.md#再検討の時刻)）。時刻の無い`keep_draft`のdraftは今までどおり依頼を待つ。同じdraftに依頼と時刻の両方が来たら、`open`の依頼のplannerが先で、時刻はその後もdraftなら効く（上の3）。
3. `status`のinbox向けの欄（仮: `requests`）に、plannerを待っている`open`の依頼を出す（`--no-claude`の間に待っている依頼を人に見せるため。ADR-t1394-1のConsequences）。今は`dagq requests`で読む。
4. 開いているruntimeのplannerへの続きの依頼のCLI（`planner request`）は実装した（[ADR-t1533-1](../../adr/2026-10-03-t1533-1-follow-up-requests-go-to-headless-planners-by-planner-id-and-no-planner-close.md)、上の[続きの依頼と非対話のplannerのCLI](#続きの依頼と非対話のplannerのcli)）。宛先は生きている非対話のplannerだけで、対話のplannerには拒む。

## 予定: 人の答えだけを待つplannerの枠の解放

- 非対話のplannerが自分の未回答・未closeの`planner_question`を持ち、turnを終え、ほかに進められる仕事が無ければ、noteとdraftの編集を保存して終了の依頼を送る。wrapperの終了を確認して行を閉じる。未処理の続きの依頼・未読のanswer・providerの復旧待ちは終了の対象から外す。
- 終了の依頼後にはanswerを旧plannerへ届けず、askを残して新しいplannerへ届ける。生きた受取先への次のturnと、受取先が無いときの初期promptの経路は残し、終了と回答の競合でも未読のanswerを失わず二重配送しない。
- 新しいplannerには元の質問・answer、前のplannerのnote（決めたこと・決めかけ・未決の理由・次の判断）と編集済みdraft、対象と関連goalの最新の記録を初期promptで引き継ぐ。収まらない材料は読む方法を示す。旧sessionのresumeには依存しない。
- 依頼・draft・findingの回数上限では人だけの待ちによる終了を除く。answerを持つplannerは決めずに終わったときだけ数える。再検討のplannerにも待ちの除外を適用するが、通常の再検討の算入は残す。作業中の失敗・時間切れは質問の存在だけで除外しない。未回答のaskで通常の再起動を止める規則と、answerを上限を越えて運ぶ規則は残す。
- 閉じたplannerは応答しない生きたplannerの検出対象から外れる。「答えを待つあいだは数えない」の規則は残す。対話の経路・Spikeの調査中の計画の枠と猶予は変更しない。
