# `plan` / `planners`

[ADR-0044](../../adr/0044-findings-proposals-from-findings-and-quiet-observer.md)の決定1・6・12・13。plannerは常駐せず、proposalごとにオンデマンドのworkspaceを開く。use caseは`src/application/planner.rs`、entry pointは`compose::plan` / `compose::planners` / `compose::planner_session`。

- **記録**: planner 1つが`planners`表（schema v23、[persistence](../persistence.md)）の1行。`session_workspaces`はroleが主キーでplannerを1つしか持てないので使わない。行は`origin`（`person` / `runtime`）、runtimeが立てたときの`proposal_id`、workspaceのUUID（`workspace_id`、UNIQUE）、session wrapperの`wrapper_pid` / `agent_pid` / `heartbeat_at` / `exit_code` / `exited_at`、終わった印の`closed_at`と`error`を持つ。plannerのディレクトリは`<queue dir>/planners/<planner-id>/`で、初期prompt（`prompt.txt`）、wrapperとして動くバイナリの写し（`runner`。runの`runner`と同じく、ビルドし直しても動いているplannerは変わらない）、Claudeのsettings（`claude-settings.json`）・debug log（`claude.log`、`PLANNER_DEBUG_LOG`）・idle marker（`idle.json`）とその履歴（`idle.log`）、入力の印（`prompt-submit.json`）、supervisorが打った文の印（`supervisor-input.json`）、画面のidleの区間（`screen-idle.json`。[画面からのidleの推定](receipt-and-session-exit.md#画面からのidleの推定)）を置く。
- **`dagq plan [--plugin-dir PATH] [--repo PATH] [--cmux EXE] [--claude EXE]`**: cmux（`ping`）とClaude（`--version`）をpreflightし、`--plugin-dir`を絶対pathにして、人が開くplanner（`origin: person`）を1つ開く（`open_person_planner`）。何度打っても新しいworkspaceを開くので、plannerは複数同時に開ける。開き方（`open_planner`）: 行を作り、ディレクトリに残っている`idle.json`を消し（queue DBを作り直すとplannerのIDは1から振り直されるので、前のDBの同じIDのplannerが残したmarkerで新しいplannerが`idle`に見えないように。task 344）、promptと`runner`を書き、`cmux workspace create --name "[<repo>]planner#<id>" --description "dagq role=planner queue=<queue hash> planner=<id>" --env DAGQ_ROLE=planner --env DAGQ_QUEUE=<db> --env DAGQ_SESSION_KIND=<planner、runtimeが立てるものはruntime_planner> --env DAGQ_PLANNER_ORIGIN=<origin> --env DAGQ_PLANNER_ID=<id> --env DAGQ_LAUNCH=<launchのJSON> [--group <queueのgroup>] --command "<planner dir>/runner --db <db> planner-session --planner <id> --claude <resolved> [--plugin-dir PATH] [--model <model> --effort <effort>]" --focus false --cwd <repository root>`で作り、UUIDを行に書く。cmuxが作れなければ行を`error`付きで閉じてerrorで止まる。createが失敗を返してもcmuxが実際にはworkspaceを作っていることがある（createの時間切れ。planner#236、task 806）ので、失敗したときは`ActorExecutor`（`close_unrecorded`）が`WorkspaceBackend::workspaces_described`でdescription（`dagq role=planner queue=<queue hash> planner=<id>`。そのplannerだけを名指す）が一致するworkspaceを全windowの一覧から探して閉じ、閉じたか・閉じるのに失敗したかをerrorに書く（一覧が取れなければerrorはそのまま）。一覧の後に遅れて作られたworkspaceは、下のwrapperが自分で閉じる。UUIDを行に書けなかったとき（`planner_workspace_created`の失敗）も、そのworkspaceを閉じてから行をerror付きで閉じる。作った後に`cmux identify`がUUIDを返さなければ、cmuxのadapter（`create_named`。runの`create` / `create_resume`も同じ）がそのworkspaceを作成の返答のhandle（`workspace:N`）で`workspace close`し（UUIDが無いので後から見つけられず、孤児として残るため。task 344）、閉じたか・閉じるのにも失敗したかをerrorに書く。行はそのerrorで閉じる。色`Blue`とpill`dagq_role planner --icon map`を当て（失敗は`warnings`）、ピンは付けない。結果は`{"planner": {planners表の行}, "name", "dir", "warnings", "launch"}`。**model / effort**（[Actor model](actor-model.md)、ADR-0079の決定7、task 580）: 人のplannerはmain checkoutの`dagq.toml`の`[roles.planner]`（読めなければ`warnings`に足して既定で開く）、runtimeのplannerはsupervisorが読む`[roles.runtime_planner]`（`PlannerLaunch::roles`）で決め、表が無ければ`--model` / `--effort`を付けない。reviseのために開くruntimeのplanner（`open_runtime_planner`）はeffortを1段上げる。決めた`launch`（`ActorLaunch`）は結果と`DAGQ_LAUNCH`に入り、pluginのhookが記録するplannerの区間の`session_opened`の`launch`になる。`plan`は開く前に下記の**行の片付け**を1回行い（supervisorが居ないときの分。cmuxの一覧が取れなければ何も閉じず、`warnings`に足して開くのは続ける）、`planners`は行を閉じない。`submit`は`CMUX_WORKSPACE_ID`と`DAGQ_PLANNER_ORIGIN`からproposalの持ち主を決めるので、plannerが出したproposalはそのworkspaceのものになる。
- **runtimeが立てるplanner**: `open_runtime_planner(launch, proposal, tasks, reasons)`がproposalの存在を確かめ、`origin: runtime`・`proposal_id`付きの行で`[<repo>]planner#<id> - proposal <proposal-id>`を開く。初期promptは`runtime_planner_prompt`で、proposal、そのtask（ID・状態・title）、plan reviewの指摘（reasons）と記録を読むCLI（`prompt::RECORD_READING`、ADR-0044の決定22、task 420: `dagq events --full --task ID`と絞り込み（`--run` / `--goal` / `--kind` / `--since` / `--until`。`--kind`が無ければattentionだけなので、全種類は`--all`を足す）と`dagq timeline RUN`）と、verify・paths・evidenceを決める順（`prompt::repository_rules`。[Prompt](prompt.md#repositoryの規則を読む順)）を載せ、直して`dagq submit --proposal <id>`で出し直すこと、計画の意図を変える修正はinboxにaskして答えを待つことを指示する。`DAGQ_PLANNER_ORIGIN=runtime`で出し直すので、そのplannerがproposalの持ち主になる。supervisorはplan reviewのrevise（持ち主のplannerが生きていないとき）とreopenでこれを呼ぶ（[Plan review (supervisor)](plan-review.md#plan-review-supervisor)の9）。follow_upの経路はgoal 29の後続taskが足す。
- **session wrapper（`planner-session`、hidden）**: runの`session`と同じく、自分を`register_planner_wrapper`で登録し（1つのplannerに1回だけ。閉じたplannerは拒む）、`AgentProvider::planner_command`（Claudeでは`claude --debug-file <dir>/claude.log --add-dir <dir> --settings <dir>/claude-settings.json [--plugin-dir PATH] -- '<prompt>'`をrepository rootで。settingsはworkerと同じ`stop_hook_settings`で、`Stop` hookが`<dir>/idle.json`を書く。runtimeが立てたplanner（origin `runtime`）はworkerと同じく入力欄のサジェストを止める`promptSuggestionEnabled: false`も持ち（`runtime_session_settings`、[Agent provider lifecycle](../provider-lifecycle.md)）、人が開いたplannerは持たない。wrapperはoriginを`planners`の行から読んで`PlannerCommand`に渡す）でagentを起動し（argvに`--model` / `--effort`があれば`AgentProvider::select_model`で渡す）、`register_planner_agent`し、agentが終わるまで`wait_interval`ごとに`heartbeat_planner`し、終了コードを`planner_exited`で記録する。logは`<queue dir>/logs/planner-session-*.jsonl`。**登録を断られたwrapper**（task 806）: 閉じた行か、別のwrapperが登録済みの行で`register_planner_wrapper`が断ると、wrapperは断られたことをlog（`warn`）に書き、自分のworkspace（cmuxが渡す`CMUX_WORKSPACE_ID`）を行が記録していなければ（`workspace_id`が無いか別のもの）そのworkspaceを`cmux workspace close`で閉じてから（`application::session::wrapper_refused`）errorで終わる。createが失敗扱いになって行が閉じた後にcmuxが作ったworkspaceは、UUIDがどこにも無いので他に見つける手段が無いため。行が記録している自分のworkspace（同じplannerの2つ目のwrapperなど）は閉じない（そのplannerのものなので、終わらせる側に任せる）。行が読めなければ閉じない。閉じるcmuxはhiddenの`--cmux`（既定`cmux`、PATHで解決。launcherはargvに付けない）で、`CMUX_WORKSPACE_ID`が無ければ（cmuxの外）閉じずにlogだけ書く。
- **生存とidleの判定**（`planner_view`、`PlannerSession::state`）: workerと同じ材料で決める。閉じた行か、workspaceのUUIDが`cmux workspace list`に居なければ`closed`。workspaceかwrapperの登録がまだなら`opening`、行を作ってから120秒（`PLANNER_STARTUP_SECS`）たってもそのままなら`lost`（cmuxがwrapperを起動できなかった、開いたプロセスがworkspaceを記録する前に死んだ）。agentの終了が記録されていれば`exited`。wrapperのPIDが死んでいるかheartbeatが30秒（`HEARTBEAT_TIMEOUT_SECS`）より古ければ`lost`。それ以外は動いているsessionで、idle markerがplannerの最後の入力（`prompt-submit.json`、`supervisor-input.json`、行の`created_at`の遅い方）より新しければ、画面（`capture`）が作業中（`AgentSignals::working`）なら`working`、markerにbackgroundの作業が残っていなければ（`AgentSignals::idle_hook`）`idle`、残っていれば`working`。markerが無いか最後の入力より古ければ、画面からの推定（[画面からのidleの推定](receipt-and-session-exit.md#画面からのidleの推定)、ADR-t803-1）でidleなら`idle`、そうでなければ（captureの失敗を含む）`working`。`alive`は`opening` / `working` / `idle`。`idle_since`はidleのときのmarkerの書かれた時刻か、推定した区間の最初のcaptureの時刻（Unix秒）で、送った文面より後にidleになったかの比較に使える。推定でidleのときは`idle_inferred`（`source`・`marker`・`since`・`observed_secs`・`captures`）も持つ。supervisorの`planner_views`は区間を持ち、区間ごとに1回queueのevent `idle_inferred`を記録する。これでStop hookが印を書けなかったruntimeのplannerも、仕事を終えれば`end_runtime_planners`が`/exit`を送り、終われば行を閉じる。人が開いたplannerには今までどおり`/exit`を送らず、`state`だけが直る。
- **runtimeのplannerの時間切れ**（`tell_of_silent_planners`、`tend_planners`の各pass、task 805）: 画面からの推定も効かない（captureが失敗し続ける、画面が見慣れない状態）ときのbackstop。runtimeが立てたplanner（draft・finding・reviseのどれも）で、`alive`かつ`idle`でないもののうち、最後に動きが見えた時刻（`planner_last_activity`: 最後の入力（`prompt-submit.json`・`supervisor-input.json`・行の`created_at`の遅い方）と、idle markerの書かれた時刻（最後の入力より古いものも）の遅い方）から`--planner-timeout`（既定3600秒、`PLANNER_TIMEOUT`。reviseの時間切れと同じ値）を過ぎたものについて、inbox宛てのattentionを出す。推定でidleのplannerは`idle`なのでこの対象にならず、`/exit`で終わる。kindは新しく作らず`planner_unresponsive`を広げた（attentionは同じ`check the planner`で、人がすることもそのplannerのworkspaceを見ることで同じため）。reviseの`planner_unresponsive`とはpayloadの`subject: "planner"`で分かれ、queueのevent（task・goal・runに付かない）として`planner_id`・`origin`・`workspace_id`・`draft_task_id`・`finding_id`・`state`・`last_activity`・`waited_secs`・`reason`を持つ（proposalの`proposal_id`は持たない）。plannerごとに1回だけで（`planner_silent`が同じトランザクションで既存のeventを確かめる）、その後に動いても消さず、もう一度は出さない。`status`のattention（`silent_planners`）はそのplannerの行が閉じるまで出て（その後にreviseを渡されたplannerはreviseの時間切れに任せて外す）、draftのplannerならdraftのtaskに付く。attentionのeventなのでKPIの`attentions_per_landing`にも数えられる。plannerは閉じず`/exit`も送らない。reviseを渡されたplanner（`revise_planner_id`がそのplanner）はreviseの`planner_unresponsive`（出し直されないまま`revised_at` / `sent_at`から期限）が見るので対象から外し、reviseの振る舞いは変えない。自分の`planner_question`を待っているplanner（`waits_on_question`）は人を待っているので対象から外す。人が開いたplannerは対象にしない。testは`tests/it/planner_timeout.rs`（入力とmarkerが期限を延ばすこと、期限を過ぎると1回だけ出て`status`と`watch`に`check the planner`で出ること、`/exit`も閉じもしないこと、人のplannerには出ないこと、行が閉じるとattentionが消えること、findingのplannerにも`finding_id`付きで1回だけ出ること、markerが無く画面で推定のidleになったplannerは`/exit`され期限を過ぎても出ないこと）。
- **行の片付け**（`close_abandoned_planners`、`PlannerSession::abandoned`、goal 54の(1)）: 人が開いたものも含め、閉じていない行のうち、workspaceのUUIDが記録されていて、cmuxの全windowの一覧（`listed_workspace_ids`を1回。[Naming](naming.md#naming)）に居らず、wrapperが終わっている行を`close_planner`（`error`なし）で閉じる。閉じた行は`planners`に出なくなる。wrapperが終わっているとは、agentの終了が記録されている、wrapperのPIDが死んでいる、heartbeatが30秒（`HEARTBEAT_TIMEOUT_SECS`）より古い、のどれかで、wrapperがまだ登録されていない行は行を作ってから120秒（`PLANNER_STARTUP_SECS`）たったとき。一覧に居ないだけでは閉じない（wrapperが生きている行と、まだ起動の猶予の中の行は残す）。一覧が取れないときは何も閉じない（一時的な失敗で閉じない）。行は一覧の前に読むので、一覧の後に開いたworkspaceを消えたと取らない。workspaceは閉じない（一覧に居ないものだけが対象）。行うのはsupervisorのsweep（`sweep_ended_runs`と同じ間隔。失敗はlogだけ）と`plan`の実行時。runtimeのplannerは生きている間は従来どおり`end_runtime_planners`が`/exit`を頼んでworkspaceを閉じてから行を閉じ、片付けはsupervisorが止まっていた間にworkspaceとwrapperが消えた分も拾う。
- **`dagq planners [--all] [--cmux EXE]`**: 閉じていないplanner（`--all`で全部）を古い順に、行の各fieldに`state`・`alive`・`idle_since`・`dir`（画面から推定したidleなら`idle_inferred`も）を足して`{"planners": [...]}`で返す。読むだけで、observerとreviewerも打てる（`plan`と`planner-session`は拒む）。
- **`runner`の片付け**（task 696、goal 54の(3)）: plannerの`runner`はwrapperが動いている間しか使わない（plannerは同じディレクトリで開き直さない）。wrapper（`run_planner_session`）はagentの終了を記録した後（agentが起動できなかったときの127も）に自分の`runner`を消す（動いているプロセスのイメージは残るので、消しても走り続ける）。消せなかった分と、wrapperが終了を記録せずに死んだ分、この変更より前に残った分は、`remove_unused_planner_runners`（`PlannerSession::runner_unused`）が閉じた行も含む全行を見て消す: agentの終了が記録されている、wrapperのPIDが死んでいるかheartbeatが30秒より古い、wrapperが登録されないまま行を作ってから120秒たち行が閉じている（workspaceが開かなかったか、cmuxの一覧に居ない。開いたままのworkspaceは遅れて`runner`を実行しうるので残す）、のどれか。行が閉じているだけでは消さない（wrapperが生きている間は残す）。行とディレクトリの他のfileは残す。行うのは上の行の片付けと同じ回（supervisorのsweepと`plan`の実行時。失敗はsweepではlogだけ、`plan`では`warnings`）
- **test**: `tests/it/lifecycle_plan.rs`がfakeのcmuxで`plan`の記録・title・env・見た目・workspaceを作れなかったとき、前のDBが残した`idle.json`を開くときに消すこと（`a_new_planner_does_not_take_the_idle_marker_an_old_database_left`）、`plan`の行の片付け（`plan_closes_the_records_of_planners_whose_workspace_and_wrapper_are_gone`: wrapperが死んだか終わった行は閉じ、一覧に居る行・wrapperが生きている行と、一覧が取れないときは閉じない）、runtimeが立てるplanner、wrapperと状態の判定（wrapperが終了の後に自分の`runner`を消すことを含む）、`plan`の`runner`の片付け（終わったwrapperの分は消え、生きているwrapperと起動の猶予の中の分は残る）を、`tests/it/runtime_sweep.rs`の`the_sweep_removes_the_runners_of_planners_whose_wrapper_is_done`がsupervisorのsweepで、終わったか死んだwrapperの`runner`を消し、閉じた行でもwrapperが生きていれば残すことを、`tests/it/runtime_sweep.rs`の`the_sweep_closes_the_records_of_planners_whose_workspace_and_wrapper_are_gone`がsupervisorのsweepで人とruntimeのplannerの行が閉じ、一覧の失敗では閉じないことを、`tests/e2e.rs`の`plan_opens_planners_side_by_side_that_submit_go_idle_and_exit`が実cmuxとstubのClaudeで、2つのplannerを同時に開き、それぞれがproposalをsubmitしてidleになり、`/exit`で終わるまでを確かめる。`tests/it/planner_screen_idle.rs`が印の無いか古いplannerの画面からの推定を確かめる（[画面からのidleの推定](receipt-and-session-exit.md#画面からのidleの推定)）。identifyの失敗でworkspaceを閉じることは`src/infrastructure/adapters.rs`の`a_created_workspace_cmux_does_not_identify_is_closed`がfakeのcmuxの実行ファイルで確かめる。createが失敗を返してもworkspaceが作られていた場合と、閉じた行に対してwrapperが起動した場合は`tests/it/lifecycle_plan.rs`の`a_planner_workspace_made_although_its_create_failed_is_not_left_open`がfakeのcmux（`create_times_out`）で、descriptionで見つけて閉じ行がerror付きで閉じること、一覧の後に作られたworkspaceは断られたwrapperが閉じること、行が記録するworkspaceの2つ目のwrapperは閉じないことを確かめる。`src/application/actor_executor.rs`の`a_workspace_cmux_made_although_its_create_failed_is_closed`はrunの`create` / `create_resume`とplannerで閉じ、inbox（descriptionがqueueのもの）と他のdescriptionは閉じないことを確かめる。
