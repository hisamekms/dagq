# `install`

`dagq install [--from PATH | --release [VERSION]] [--to PATH] [--rollback] [--allow-breaking] [--handoff-timeout SECS] [--cmux EXE] [--claude EXE] [--codex EXE] [--plugin-dir PATH] [--skip-e2e]`は固定バイナリを入れ替えて、このqueueのsupervisorを引き継がせ、引き継いだsupervisorを見張る人の入口（ADR-0045の決定11・12・14、[ADR-0073](../../adr/0073-kind-additions-are-compatible.md)の決定13・14）。use caseは`src/application/install.rs`（置き換えと引き継ぎ）と`src/application/update.rs`の`install_watched`（その後の見張り。下の7）、配線は`src/compose.rs`の`OneShot::install`、binaryのビルド・起動・置き換えは`src/infrastructure/binaries.rs`（`Binaries` port）。queueを開く前に処理するので、queueがこのbinaryより古くても新しくても動く。

1. **元**: `--from`がfileならそのbinary、dirならそのcheckout、省略時はcwdのrepositoryのmain checkout（[Run environment](run-environment.md#main-checkoutの決め方)。無ければ`--from`を求めるerror）を`cargo build --release --locked -p dagq -p dagq-broker-client`でビルドする（`CARGO_TARGET_DIR`があればそこ、無ければ`<checkout>/target`の`release/dagq`と、隣の`release/dagq-broker-client`。workerのbrokerのclientはdagqと同じbuildで作って隣に置く。[ADR-t827-1](../../adr/2026-09-28-t827-1-broker-crates-binaries-and-version-alignment.md)決定5、[Broker](../broker.md#配布と版)）。`--rollback`は`<to>.previous`（無ければerror）。`--release [VERSION]`はcrates.ioのリリース（下の「リリースから」）。
   - **e2eの関門**（[ADR-t963-1](../../adr/2026-09-29-t963-1-e2e-required-by-diff-and-run-in-full-before-auto-update.md)決定1）: 元がcheckout（`--from <dir>`か省略時のmain checkout）で、そのcheckoutがdagqのソース（[Source repository](source-repository.md)）のとき、ビルドの後、2の確認の前に、そのcheckoutのビルドと同じtarget（人のshellの`CARGO_TARGET_DIR`があればそこ、無ければ`<checkout>/target`。e2eは人のshellのenvを引き継がないので、`install`がビルドしたbinaryの`<target>/release/dagq`からtargetを取って`e2e_gate::run`の`target_dir`に渡し、関門が`CARGO_TARGET_DIR`に置く。二度目のビルドをしない）で全部のe2e（`cargo test --locked --test e2e -- --ignored`）を[自動更新](auto-update.md#auto-update)と同じ`Binaries::e2e`（`src/infrastructure/e2e_gate.rs`）で流す: envは人のshellのenvを引き継がず（`env_clear`）、そのうち許す名前（資格情報を除く。`GH_TOKEN`・`SSH_AUTH_SOCK`などは渡らない。規則は[着地の前のe2e](landing-e2e.md)の「環境」）だけにそのcheckoutの`dagq.toml`の`[run.env]`と`DAGQ_E2E_CMUX=<--cmux>`と1回ごとの`TMPDIR=<queue dir>/update/e2e/<unix時刻>-<pid>`を重ね（logの冒頭に渡した名前を書き、値は書かない）、hostで1本ずつ流すlock（`<data dir>/e2e.lock`、自動更新の関門とruntimeがrunに流すe2eと共通。[ADR-t1233-2](../../adr/2026-10-02-t1233-2-e2e-runs-on-the-host-after-review-passes.md)決定4。他が流していれば空くまで待つ）を取り、`cmux ping`に答えなければ実cmuxを要るe2eを流さず（[ADR-t2105-1](../../adr/2026-10-08-t2105-1-e2e-gate-skips-cmux-e2e-only-when-cmux-does-not-answer.md)）、podmanを自動更新と同じく確かめて、上限つきで待っても繋がらなければpodmanに頼るe2e（`broker::`）を流さずに残りで判定する（[ADR-t1162-1](../../adr/2026-09-30-t1162-1-e2e-gate-skips-podman-e2e-only-when-podman-is-unreachable.md)。CLIが共通の`e2e_gate::podman_check`で`E2eSettings::podman`にhost全体の`host.toml`のpodman・machineの資源と`machine_lock_home`を渡す。読む設定は[自動更新](auto-update.md#auto-update)と同じ。隠しflagの`--e2e-command`を渡したときはpodmanを確かめない）。上限は隠しflagの`--e2e-timeout`（既定1800秒）、出力は`<queue dir>/logs/install-<unix時刻>.e2e.log`、後始末（そのe2eの`TMPDIR`の中のprocess、`DAGQ_QUEUE`がその中を指すworkspaceと使い捨てのqueueのhashのcmuxのgroup、`TMPDIR`。cmuxが答えないときは次の関門に残す）も自動更新と同じ。落ちたe2eの1回の流し直しと`.config/e2e-quarantine.toml`の印（[ADR-t1165-1](../../adr/2026-09-30-t1165-1-e2e-gate-reruns-failed-e2e-once-and-records-quarantined-failures.md)、書式と判定は[自動更新](auto-update.md#auto-update)）も自動更新と同じ（`e2e_verdict::judge`。流し直しのlogは`<queue dir>/logs/install-<unix時刻>.e2e.rerun.log`。印の続けての失敗は、queueがあれば自動更新の関門とruntimeがrunに流したe2eのevent（`e2e_gate_events`）から数え、queueが無いか開けなければ数えない。`install`の関門はeventを書かないので、数える元はそれらだけ）。落ちれば（流し直しでも落ちたtestに効いている印の無いものがある、上限切れ、始められない）何も置き換えずに、落ちたtestかその理由（流し直したなら流し直しでも落ちたtest・効かなかった印の理由・流し直しのlogのpathも）とlogのpathを載せたerrorで止まる（`--skip-e2e`を案内する）。人が明示したときだけ`--skip-e2e`で飛ばし、結果の`e2e`に`{"status":"skipped"}`を書く（通れば`{"status":"passed","secs","log"}`、podmanかcmuxに繋がらず流さなかったe2eがあれば`skipped`（`tests`・`reason`）を足す。自動更新の関門の欄の`flaky`・`quarantined`と、あれば`rerun`・`quarantine`も同じ形で足す）。`--from <binary file>`（自動更新の`approve_update`の`staged`のbinaryは、jobの関門を通ったもの）・`--rollback`・`--release`とdagqのソースでないcheckoutは関門を持たず、結果の`e2e`は`{"status":"not_applicable"}`。`E2eGate`（`Run` / `Skip` / `NotApplicable`）はCLI（`src/main.rs`）が決めて`InstallOptions::e2e`で渡す。隠しflagの`--e2e-command`はtestがe2eの代わりに流すshellのコマンド。testは`tests/it/lifecycle_install.rs`の`install_of_a_checkout_replaces_nothing_unless_its_e2e_passes`（fakeのe2eで、失敗・上限切れで何も置き換えないこと、`--skip-e2e`と、binaryの`not_applicable`、podmanのe2eを流さずに通った`skipped`が結果に出ること、flakyと印で通したtestが結果の`e2e`の`flaky`・`quarantined`・`rerun`に出ること、印の無い流し直しの失敗で何も置き換えないこと）。
     - **podmanのlockと失敗時の停止**: machineのhost全体のlock（`podman-machine.lock`）の待ちは30秒（`MACHINE_LOCK_LIMIT`。e2e実行の`--e2e-timeout`とは別）を上限とし、待ちきれなければ`broker::`を流さず残りで判定する。理由`timed out waiting for the machine lock after 30s`をlogと`E2eOutcome::skipped`に残す。確認から失敗時の後始末まで同じlockを保持し、自分でinit・startしたmachineに繋がらなければ`podman machine stop dagq`を打つ（stopの失敗は接続失敗の理由に追記する）。関門の前から動いていたmachineは接続を確かめるだけで、停止・再起動しない。
     - **期間限定で外したケース**（[ADR-t1582-1](../../adr/2026-10-04-t1582-1-temporarily-leave-broker-and-cmux-only-e2e-cases-out.md)）: この関門の「全部のe2e」からも、`#[cfg(any())]`で`tests/e2e.rs`の登録から外したcmux固有の1ケース`up_in_cmux_starts_a_supervisor_in_a_workspace_that_down_wait_stops_and_closes`（task 1443で削除）が抜ける。登録に無いので結果の`e2e`の`skipped`には出ない（上のpodmanに繋がらないときの`broker::`の省略とは別。brokerのケースは同じADRで外れた後、task 1451で登録に戻った。同じADRで外れた掃除（sweep）のケースはtask 1440が、plannerのケースはtask 1441が削除した）。終了条件はADRと[testの制約](../../development/testing.md#e2e)が持つ。
2. **確認**（決定12）: 元の`--version`でbuild識別子を読み、使い捨てのqueue（tmpdirの`--db`）で`init`と`list`が通ることを確かめる。通らなければ何も置き換えない。元の隣に`dagq-broker-client`があれば（`--rollback`では`<to>`の隣の`dagq-broker-client.previous`）、その`--version`が元のbuild識別子と同じことも確かめる（`install::Client::check`）。違えば（読めなければ）、dagqがclientと一緒に作ったもの（checkoutのbuild、自動更新のbuild、`--release`。`Source::Checkout`・`Source::Built`）ではdagqも含めて何も置き換えずにerrorで止まり、人が渡したbinary（`--from <file>`。前のbuildが`target/`に残したclientが隣にあることがある）と`--rollback`ではそのclientを置かずに（元にclientが無いものとして4で置き場のclientを退け）、結果の`client`の`ignored`（`path`・`reason`）に書く。元が`<to>`そのもの（`--release`で`<to>`がすでにその版）なら確かめない。引き継ぎを受けるliveな登録があるのに、元が`supervise --handoff-token`を知らない（`supervise --handoff-token probe --help`が通らない。引き継ぎより前のbinary）ときも、execしたsupervisorが引数で止まるので、何も置き換えずに`down --wait`と`up`を案内するerrorで止まる（`--rollback`で引き継ぎより前のbinaryに戻すときも同じ）。
3. **schema**: queueのDBがあれば元の`migrate --check`を読む。非互換のmigrationがあれば、`--allow-breaking`が無ければ何も置き換えずにerror、あればdrain（下記6）。元がqueueを開けず（floorより古い。非互換のmigrationの後の`--rollback`）、適用するものも無ければ、`backups/`を案内するerror。互換のmigrationがあれば元の`migrate`で適用する。
4. **置き換え**（決定11）: 元が`<to>`そのもの（`--release`で`<to>`がすでにその版だったとき）なら置き換えず（`.previous`もそのまま）、引き継ぎだけを行い、全員の引き継ぎが失敗しても戻さない。それ以外は 元を`<to>`と同じdirの一時file（`.<name>.install-<pid>`）にcopyして0755にし、`<to>`をhard linkで`.<name>.previous-<pid>`に残してから一時fileを`<to>`にrenameし、残したものを`<to>.previous`にrenameする。動いているプロセスは前のinodeを使い続けるので、上書きのcpで殺されることはない。`--rollback`は同じ手順で`<to>`と`.previous`が入れ替わる。戻したバイナリが未知の`DAGQ_ROLE`を拒まず新しいroleを知らないと（task 729より前）、新しいバイナリが起動して走り続けるjobが制限を受けない窓ができる（[Authorization](../authorization.md#固定バイナリを戻したときの窓)）。`<to>`の既定はこのbinary自身（`current_exe`）。clientは**dagqより先に**同じ手順で`<to>`の隣の`dagq-broker-client`に置き（`.previous`も残す）、次にdagqを置く。dagqを置けなければclientを戻す（前のclientが無かったときは新しいclientを消す）。置き場にclientが無かったときは、残っている`dagq-broker-client.previous`（前のdagqと組でない）を消し、後の`--rollback`が別のbuildのclientを組にしないようにする。元の隣にclientが無ければ（clientより前のbuild、clientの無いリリース）、`<to>`の隣のclientを`dagq-broker-client.previous`へ退ける（`Binaries::set_aside`）ので、別のbuildのclientがdagqの隣に残らない。`--rollback`はclientも`.previous`と入れ替える。結果の`client`は`{"target","outcome","previous"}`で、`outcome`は`replaced`・`set_aside`・`absent`（どちらにも無い）・`in_place`（元が`<to>`そのもの）。
5. **引き継ぎ**: liveな登録（PIDが生きていてheartbeatが30秒以内）のうち引き継ぎを受けられるものに`<to>`をexecさせ（`lifecycle::hand_off`、上限`--handoff-timeout`、既定1800秒。queueを見る間隔はhiddenの`--poll-ms`、既定500ミリ秒で、testが短くする。task 1048）、受けられないものは`not_handed_off`（`up`でdrainする）に載せる。停止要求でdrainに入ったsupervisor（`supervisor_draining`を記録したもの。`down`や別の`up`のdrainと重なったとき）は上限を待たずにその場で失敗にし、要求を取り消す（errorは`is stopping (a stop request wins over the handoff) and was not handed off`、`supervisors[]`の要素に`stopping: true`。task 1277、[Handoff](handoff.md#handoff)）。上限の時点で戻っていなかったsupervisorの取り消しが要求を見つけなければ（上限の直後にsupervisorがexec直前の条件付きUPDATEで要求を受け取って列を消した）、短い猶予（`lifecycle::HANDOFF_GRACE`）のあいだ見直し、新しいbuild識別子で戻れば成功に数える（task 715。詳細は[`up` / `down`](up-down.md)の引き継ぎ）。`hand_off`は最初の失敗で止まらず、引き継がせた全員の成功か失敗を待つ（[ADR-t632-1](../../adr/2026-09-27-t632-1-handoff-restores-only-when-every-supervisor-failed.md)）。fileは全員で1つなので、**全員が失敗したときだけ**`<to>.previous`を`<to>`に戻し（`restore`。4で置いた・退けたclientも戻し、`restored`の`client`に結果を書く）、その旨と全員の失敗の理由を添えたerror（`install::HandoffFailed`。文面はそのままで、supervisorごとの結果`supervisors`（`Handed::report`）と戻したかどうか`restored`（`{"restored":true,"version"}`か`{"restored":false,"reason"}`）を持ち、自動更新のjobが読む）で止まる。**一部だけが失敗したとき**は戻さず、`<N> of the <M> supervisors took the handoff to <version>, so it stays at <to>; …`で始まり、失敗したsupervisorの名前と理由、`down --force`と`up`（新しいbinaryで起動し直す）か`install --rollback`（全員を前のbinaryに戻す）を案内するerror（`install::KeptBinary`）で止まる。CLI（`src/main.rs`）はこのerrorのときも結果をstdoutに出してから、errorのJSONをstderrに出して終了コード1で終わる。結果は`{"outcome":"installed"|"partially_handed_off","target","version","previous","previous_version","migrated","kept","supervisors":[…],"not_handed_off":[…]}`で、`kept`は一部の失敗で新しいbinaryを残したときtrue。`supervisors`はsupervisorごとの結果（`lifecycle::Handed::report`）で、成功なら`{"token"（今のtoken。同じpidが登録し直せば新しいtoken）,"previous_token","pid","mode","workspace_id","version"（前のbuild識別子）}`、失敗なら`{"token","pid","mode","workspace_id","version","error"}`。queueが無ければ置き換えだけを行う。結果には1の`e2e`も載る。全員の失敗（`HandoffFailed`）と一部の失敗（`KeptBinary`）は、CLIでは7の`update_failed`の経路を通る（段は`install`と`handoff`）。
6. **drain**（`--allow-breaking`、決定14）: liveな登録があれば`down --wait`で止め、元の`migrate`（非互換なので`backups/`に複製してから適用）、置き換え、`<to> --db <db> up [--parallel <止めた登録のparallel>（その出どころが`flag`か、出どころの列より古いbinaryの登録なら）] [--in-cmux（止めた登録がin_cmuxなら）] [--auto-update（止めた登録のどれかがauto_updateなら）] [--max-waiting <止めた登録のmax_waiting>（記録があり、その出どころが`flag`か記録の無いとき。古いbinaryの登録はNoneで渡さない。出どころの列より古いbinaryの登録は既定の4でも渡す）] [--runtime-planners <止めた登録のruntime_planners>（記録があり、その出どころが`flag`のとき。task 941）] --cmux … [--claude …] [--codex …] [--plugin-dir …]`で起動し直す（`--claude`と`--codex`はsymlinkを辿らないpathで、与えたpathが無ければ名前でPATHから解決し直す。`--codex`が見つからなければ与えた値のまま渡す。[Provider executables](../provider-executables.md)）。`--auto-update`と`--max-waiting`と`--runtime-planners`は、起動し直しの引数（`--cmux`など）がすでに持っていれば重ねない。止めた登録の自動更新と待ちの上限とruntimeのplannerの上限が引き継がれるので、drainの後に`up --auto-update`を打ち直す必要はない。結果は`{"outcome":"installed",…,"migrated","drained","up"}`。drainは7の見張りの対象外: 前のbinaryは非互換のmigrationの後のDBを開けないので戻せず、supervisorの起動し直しは上の`up`が行う（その`up`の失敗はerrorで止まる）。
7. **見張り**（ADR-0073の決定13・14、task 1481）: 5で引き継がせたsupervisor（結果の`supervisors`のうち`error`の無いもの）のそれぞれが、新しいbuild識別子のまま、取り戻したときより後のheartbeatを期限（隠しflagの`--watch-timeout`、既定60秒で`update::WATCH_TIMEOUT`（CLIの既定もこの定数）。自動更新の見張りと同じ既定で、testが短くする）の内に書くのを待ち、確かめ終えるまで`install`は成功を返さない。同じpidが新しいbuild識別子で登録し直したものは`lifecycle::successor`で追う。判定・戻し・起動し直しは自動更新のjobの4・5（[Auto-update](auto-update.md#auto-update)）と同じ関数（`update::settle`の中の`watch`・`observe`・`restore`・`bring_back`）を通る: 全員が失敗すれば`.previous`が置き換えた前のbuild識別子と同じときだけ固定バイナリとclientを戻し（違えば戻さず、その理由を`restored`の`reason`とaskに書く）、一部だけなら戻さず（`kept: true`、ADR-t632-1）、失敗したsupervisorだけをそれぞれ戻す（前のbuildのままheartbeatするものはそのまま、固まったものはSIGTERM（10秒でSIGKILL）で止めて起動し直し、居なくなったものは起動し直し、modeの無いものは起動し直さない。起動し直しは`compose::restarter`で、in-cmuxは`install`の`--cmux`・`--claude`・`--codex`・`--plugin-dir`を渡した`up --in-cmux`、launchdは`KeepAlive`に任せる）。戻すときの元の登録（modeとworkspace、前のbuild識別子）は、`install::install`を呼ぶ前に読んだ登録の記録から取り、記録に無いtokenの登録（checkoutのビルドとe2eの関門の間に`up`やlaunchdが起動したもので、`install::install`は引き継ぎの直前のliveな登録を読むので引き継ぐ）は、引き継ぎの後に読み直した行に、`install`の結果がそのpidについて報せたbuild識別子・mode・workspaceを重ねて足す（`update::registered_since`。同じpidが新しいbuild識別子で登録し直した行はmodeを持たないため）。成功の結果には`watch`（supervisorごとの`{"token","pid","now"（今のtoken）,"heartbeat":true}`）が載る。queueが無い・liveなsupervisorが居ない（`supervisors`が空）・6のdrainのときは見張らず、`watch`は空か無い。
   - **inboxに知らせる**: 見張りの失敗（段`watch`）と5の引き継ぎの段の失敗（全員の`HandoffFailed`は段`install`、一部の`KeptBinary`は段`handoff`）は、`update_failed`のqueue eventを`source: "install"`で書き（`stage`・`error`・`restored`・`kept`・`supervisors`（`token`・`pid`・`now`・`error`・戻した結果の`supervisor`）・`version`・`ask_id`。`commit`は無く`log`はnull）、`update_failed`のask（`retry` / `skip`。新しいkindは作らず、`subject`を`install`、`ask_opened`の`source`を`install`にする）を開く。`open_update_ask`は`ask_opened`の`source`が同じ側の開いたaskだけを`superseded`で閉じるので、前の手動の`install`のaskは閉じ、自動更新・リリースのjobのaskとは互いに閉じ合わない（開いたaskの一意の索引が`subject`を含むので、jobのaskと並んで開ける）。問いは手動の`dagq install`であること、段、error、binaryと各supervisorの状態、人が手で打つ次の手（同じ`install`のやり直し、`install --rollback`、`down --force`と`up`）と、答えを適用するものが居ないことを書く。CLIは結果の代わりにこの`update_failed`のpayload（`outcome: "failed"`・`source: "install"`）をstdoutに出し、`update::InstallFailed`のerrorのJSONをstderrに出して終了コード1で終わる。5の前の失敗（ビルド・e2e・確認・schema・置き換え）は今までどおりerrorだけで、inboxには知らせない。

## リリースから（`--release`）

`--release [VERSION]`（[ADR-t618-1](../../adr/2026-09-27-t618-1-release-update-by-ask-from-crates-io.md)決定6、`--from`・`--rollback`とは併用できない）は、crates.ioのリリースを元にする人の入口で、supervisorの`approve_release`の答えが起動するjob（[Release update](release-update.md)の「入れ替えのjob」）と同じ置き場と`cargo install`を使う。supervisorが居ないときや、askを待たずに上げたいときに打つ。配線は`src/compose.rs`の`OneShot::install_release`。

- VERSIONは`X.Y.Z`だけを受ける（それ以外はcargoを打つ前にerror）。省略すると（`--release`だけ）sparse indexを`curl`で読み、yankedとpre-releaseを除いた最新にする（`application::release_update::resolve_version`）。
- `install::release_binary`: `<to>`の`--version`がすでにVERSIONならそのfileを元にし（cargoを打たない）、そうでなければ`cargo install --locked dagq@VERSION --root <queue dir>/update/release --target-dir <queue dir>/update/target`（`infrastructure::binaries::CargoInstaller`、出力は`<queue dir>/logs/install-release-VERSION.log`）の`<root>/bin/dagq`を元にする。cargoが見つからない・失敗したら何も置き換えずに`install release VERSION: …`のerror。dagqの後に同じ`--root`と`--target-dir`で`cargo install --locked dagq-broker-client@VERSION`も打ち、`<root>/bin/dagq-broker-client`をdagqの隣に置く（[ADR-t827-1](../../adr/2026-09-28-t827-1-broker-crates-binaries-and-version-alignment.md)決定8）。先に前のclientを消し、clientのinstallが失敗すれば（そのリリースのclientがcrates.ioに無いなど）clientを置かないので、4がdagqの隣のclientを退け、brokerは両方がそろうまで使われない（決定7）。隠しflagの`--cargo`はtestがstubを渡す。
- その後は上の2〜6と同じ（`Source::Binary`）。非互換のmigrationは`--allow-breaking`が無ければerror、あればdrain。結果は`install`の結果に`release`（VERSION）と`log`を足したもの。
- test: `tests/it/cli_install_release.rs`がstubの`cargo`で、失敗で置き換えないこと、成功で`--root`と`--target-dir`の引数（dagqとclientの2回）と置き換え（`.previous`）、clientの無いリリースでclientが`absent`になること、リリースでないVERSIONの拒否を確かめる。`tests/it/lifecycle_install_client.rs`がfileのbinaryと実物のrenameで、dagqとclientがclientから順に一緒に入れ替わり`--rollback`で両方が戻ること、dagqが作ったbuildでclientの版の違いとdagqの起動の失敗でどちらも置き換えないこと、人が渡したbinaryとrollbackでは版の違うclientを置かずに退けること、残った`.previous`のclientを前のdagqと組にしないこと、clientの無いdagqで前のclientを退けること、dagqを置けないときにclientを戻すことを確かめる。
