# Auto-update

[ADR-0045](../../adr/0045-build-identifier-explicit-migrate-schema-compat-handoff-and-auto-update.md)の決定13・17。`up --auto-update`のsupervisorは、runtimeを変えるcommitがmainに着地するたびに、queueのdirの下でそのcommitをビルドし、同じcheckoutで全部のe2eを流して通ったときだけ（[ADR-t963-1](../../adr/2026-09-29-t963-1-e2e-required-by-diff-and-run-in-full-before-auto-update.md)決定1）、[`install`](install.md#install)と同じ手順で固定バイナリを置き換えて自分を[引き継ぎ](handoff.md#handoff)で入れ替える。走っているsessionは止まらない。supervisor側は`src/application/supervise/update.rs`、ビルドから見張りまでのjobは`src/application/update.rs`（`run`）、CLIは隠しコマンド`dagq auto-update`、配線は`src/compose.rs`の`OneShot::auto_update`。

- **有効にする**: `up --auto-update`は、起動するsupervisorを`supervise --auto-update`で起動し（登録の直後に`supervisors.auto_update`を1にする。launchdの再起動でも同じ引数なので残る）、reuseや引き継ぎで残すliveな登録には`set_auto_update`で1を書く。`--auto-update`の無い`up`は同じ登録の`auto_update`を0にする。結果の`supervisor.auto_update`に出る。execの引き継ぎは登録の行を変えないので、設定は残る。この repository は`dagq.toml`を置かないので、設定ファイルではなく`up`のフラグにした（ADR-0045のAlternatives）。
- **きっかけ**（`auto_update_pass`）: supervisorはループの各passで、前に見てから`--update-interval`（既定30秒）経っていて、自分の登録の`auto_update`が1なら、mainを見る。停止要求の後、claimを止めた後、引き継ぎの要求を受けた後は見ない。
  1. まず`update_failed`のaskの答え（下記）を適用する。
  2. 自分が起動したjobが生きているか、jobが書いた最新の段（askの答えの`update_answered` / `update_retry`は飛ばす）が`update_started` / `update_built` / `update_restored`でそのjobのpidが生きていれば、何もしない（同時に1つ。execの後の新しいプロセスもDBの行で判定する）。execの前に起動したjobはexec後のプロセスの子のままで他に回収する者がいないので、そのpidを`waitpid(WNOHANG)`で回収してから生死を見る（`ProcessControl::reap`）。その行のjobが死んでいれば（kill、再起動）、どこまで進んだか分からないので自分ではやり直さず、`update_failed`（`stage: interrupted`）を書いて`update_failed`のaskを開く。
  3. mainのhead（`refs/heads/<branch>`）と、比べる元（`base`）を決める。`base`は最新の`update_started`のcommit、無ければ自分のbuild識別子が名乗るcommit（`X.Y.Z-dev+<commit>[.dirty]`の`<commit>`）、それも無ければ（リリースのビルド、`+unknown`）このプロセスが最初に見たmain。headが`base`と同じなら何もしない。
  4. `git diff --name-only <base> <head>`のどれかが`src/`・`migrations/`・`crates/`・`Cargo.toml`・`Cargo.lock`・`build.rs`・`rust-toolchain.toml`（`RUNTIME_PATHS`。`build.rs`はbuild識別子を埋め込む。`crates/`はbrokerのcrateで、`rust-toolchain.toml`はbrokerのimageのRustの版。ADR-t827-1決定4）なら、headのjobを起動する。変えていなければそのheadを覚えて見直さず、`automatic update: main's <head> builds nothing: it changes no runtime path`をheadごとに1回logに出す（testは固定のsleepの代わりにこの行を待つ。task 1048）。`base`をGitが知らない（別のcloneのビルド）ときは、headを1回ビルドして、それが次の`base`になる。`update_retry`（`retry`の答え）が最新の`update_started`より新しければ、差分を見ずにheadをビルドする。
  - supervisorの着地でも、人が手で打った`integrate`でも、mainが進めば同じように拾う。ビルド中に次の着地があっても積まず、jobが終わった後の最初の見直しで、そのときのheadを1回ビルドする。
- **job**（`dagq --db <db> auto-update --commit <head> --token <supervisor> --to <supervisorのbinary> --repo <checkout> --log <build log> --claude … --codex … [--cmux …] [--plugin-dir …] [--build-command …] [--e2e-command …] [--e2e-timeout …] [--poll-ms …]`。`--claude`と`--codex`はsupervisorの`Layout`の値で、jobがsupervisorを起動し直す`up`にも渡す）: supervisorが自分のbinary（`current_exe`）で起動する。setsidで新しいsessionとprocess groupに入れる（supervisorのexecにも、in-cmuxのworkspaceが閉じられることにも巻き込まれないため）。stdoutは`<queue dir>/logs/update-<unix時刻>-<commit 12桁>.json`（結果）、stderrは同じ名前の`.log`、ビルドの出力は`.build.log`、jobのtracingは`auto-update-*.jsonl`（どれも最後の書き込みから14日で消える。[Logs](logs.md#logs)）。hiddenの`--poll-ms`（既定500）は3の引き継ぎの待ちと4の見張りがqueueを見る間隔で、supervisorはhiddenの`supervise --update-poll-ms`を渡されたときだけそれを付ける（testが短くする。task 1048）。起動したら、supervisorが`update_started`（`pid`・`base`・`supervisor`・`version`・logのpath）を書く。
  1. **ビルド**: `<queue dir>/update/checkout`をheadに合わせる（無ければ`git worktree add --detach --force`、あれば`checkout --detach --force`と`clean -fdx`）。`CARGO_TARGET_DIR=<queue dir>/update/target`で`cargo build --release --locked -p dagq -p dagq-broker-client`を走らせる（workerのbrokerのclientも同じbuildで`release/dagq`の隣に作る。[ADR-t827-1](../../adr/2026-09-28-t827-1-broker-crates-binaries-and-version-alignment.md)決定5。`--update-build-command`で渡したshellのコマンドに置き換えられる。testが使う）。brokerのimageはここではbuildしない（brokerを起動するときにtagが無ければbuildする。決定6、[Broker](../broker.md#配布と版)）。人のmainのcheckoutと`target/`は使わない。成功すれば`update_built`。
     - **e2eの関門**（ADR-t963-1決定1、`e2e_gate`）: 続けて同じcheckoutで、`CARGO_TARGET_DIR=<queue dir>/update/target`のまま全部のe2e（`cargo test --locked --test e2e -- --ignored`。`--e2e-command`で渡したshellのコマンドに置き換えられる。testが使う）を流す。`Binaries::e2e`の実装は`src/infrastructure/e2e_gate.rs`。envはjobのprocessのenvを引き継がず（`env_clear`）、そのうち許す名前（資格情報を除く）だけにmain checkoutの`dagq.toml`の`[run.env]`（[Run environment](run-environment.md)。`${DAGQ_QUEUE_DIR}`はqueueのdir、`${DAGQ_RUN_DIR}`は`<queue dir>/update/e2e`）と、`DAGQ_E2E_CMUX=<--cmux>`と、1回ごとの`TMPDIR=<queue dir>/update/e2e/<unix時刻>-<pid>`を重ね、logの冒頭に渡した名前（値は書かない）を書く。許す名前・資格情報を除く規則・足りないときの見え方と`dagq install --rollback`での戻し方は、runのe2eと同じで[Review](review.md#着地の前のe2e)の「環境」が持つ。流す前に、hostで1本ずつ流すためのlock（[ADR-t1233-2](../../adr/2026-10-02-t1233-2-e2e-runs-on-the-host-after-review-passes.md)決定4。`E2eSettings::lock`、`<data dir>/e2e.lock`＝`install::e2e_lock_path`でqueueのdirの親。`flock`で、流し直しが終わるまで持つ）を取る。runtimeがreviewのpassの後に流すrunのe2e（[Review](review.md#着地の前のe2e)）と`install`の関門も同じlockを取るので、先に取ったものが流し、後のものは空くまで待つ（待った秒は`E2eOutcome::lock_wait_secs`）。続けて`cmux ping`を打ち、通らなければ（cmuxが無い・動いていない）e2eを始めずに失敗にする。続けてpodmanを確かめる（[ADR-t1162-1](../../adr/2026-09-30-t1162-1-e2e-gate-skips-podman-e2e-only-when-podman-is-unreachable.md)、`E2eSettings::podman`の`PodmanCheck`）: `tests/e2e/broker.rs`のfixtureと同じhost全体の`$XDG_CONFIG_HOME/dagq/host.toml`（未設定なら`~/.config/dagq/host.toml`）の`[broker] podman`とmachineの資源（`machine_cpus`・`machine_memory_mib`・`machine_disk_gib`）を使う（`e2e_gate::podman_check`）。fixtureは`XDG_DATA_HOME`だけを使い捨ての場所に変え、queueの`host.toml`を作らないので、更新対象queueの`host.toml`は読まない。設定が無ければ`PATH`の`podman`と既定の資源。brokerの用意と同じhost全体のlock（[Broker](../broker.md)の`machine_lock_home`）の中で`application::broker::connect`を呼ぶ。確認から失敗時の後始末まで同じlockを保持し、既に動いているmachineは`podman --connection dagq info`で接続を確かめるだけで、停止・再起動しない。動いていないmachineだけ`ensure_machine_steps`で用意してから`info`で接続を確かめる。どちらも接続が切れていれば`Reconnecting`の上限（`broker::RECONNECT`: 3秒おきに10回まで`info`を聞き、答えたらやり直す。やり直しは3回まで）で待つ。それでも繋がらなければ（`podman_missing`・`machine_busy`・`machine_failed`・`podman_failed`）、podmanに頼るe2e（`install::PODMAN_E2E`、今は`broker::`）を流さない: cargoに`--skip broker::`を足し、`--e2e-command`には`DAGQ_E2E_SKIP=broker::`（空白区切り）を渡し、e2eのlogに`== the e2e did not run broker:: because podman could not be reached: <理由>`の行を書き、`E2eOutcome::skipped`（`E2eSkip`の`tests`・`reason`）に残す。残りのe2eで判定する。cmuxの`ping`が通らないときは今までどおり始めずに失敗。`--e2e-command`でe2eを置き換えたとき（test）はbrokerのe2eが無いので、podmanを確かめない（`PodmanCheck`を`None`にし、hostのpodmanとlockに触れない）。出力は`logs/update-<unix時刻>-<commit 12桁>.e2e.log`（build logの`.build.log`を`.e2e.log`にした名前。他のlogと同じく14日で消える）。上限は`--e2e-timeout`（既定1800秒。supervisorには隠しflagの`--update-e2e-timeout`と`--update-e2e-command`があり、jobにそのまま渡す）で、超えたらprocess groupにSIGTERMを送り、leader（cargoかshell）が終わる（`try_wait`でreapして見る。zombieを生きていると見ない）か10秒たったところでgroupにSIGKILLを送って落ちた扱いにする（`stop_group`。SIGTERMで終わるleaderは10秒を待たない）。落ちたtestはlogの`test <name> ... FAILED`の行から読む。
     - **podmanのlockと失敗時の停止**: machineのhost全体のlock（`podman-machine.lock`）の待ちは30秒（`MACHINE_LOCK_LIMIT`。e2e実行の`--e2e-timeout`とは別）を上限とし、待ちきれなければ`broker::`を流さず残りで判定する。理由`timed out waiting for the machine lock after 30s`をlogと`E2eOutcome::skipped`に残す。確認から失敗時の後始末まで同じlockを保持し、自分でinit・startしたmachineに繋がらなければ`podman machine stop dagq`を打つ（stopの失敗は接続失敗の理由に追記する）。関門の前から動いていたmachineは接続を確かめるだけで、停止・再起動しない。
     - **期間限定で外したケース**（[ADR-t1582-1](../../adr/2026-10-04-t1582-1-temporarily-leave-broker-and-cmux-only-e2e-cases-out.md)）: 関門の「全部のe2e」から、`#[cfg(any())]`で登録から外したcmux固有の3ケースが抜ける。`the_sweep_closes_workspaces_left_in_any_window_after_their_fixture_dir_is_gone`（task 1440で削除）、`planner::the_runtime_opens_planners_side_by_side_that_submit_go_idle_and_exit`（task 1441で削除か非対話への置換で復帰）、`up_in_cmux_starts_a_supervisor_in_a_workspace_that_down_wait_stops_and_closes`（task 1443で削除）。登録に無いので`update_e2e_passed`の`skipped`には出ない（上のpodmanに繋がらないときの`broker::`の省略とは別。brokerのケースは同じADRで外れた後、task 1451で登録に戻った）。一覧と規則は[testの制約](../../development/testing.md#e2e)。
     - **後始末**: 通っても落ちても、そのe2eの`TMPDIR`を使い捨ての場所として片付ける。command lineの引数にその`TMPDIR`の中のpathを持つprocess（e2eが起動したsupervisorやstubのagent。時間切れで止めたときに残る）をSIGTERM（3秒でSIGKILL）で止める。続けて全windowのworkspaceを一覧し、`cmux workspace env <id> --json`の`DAGQ_QUEUE`または`E2E_SHARED`がその`TMPDIR`の中を指すworkspaceをunpinして閉じる。fixtureが自分のdirを消した後に残ったworkspaceも拾い、本番のdata homeや別の関門を指すものは対象外にする。queueのhashは、残ったfixtureの`<TMPDIR>/<fixture>/data/dagq/<hash>`と、その`TMPDIR`内を指す`DAGQ_QUEUE`の両方から取り、そのhashをexternal IDに持つgroupだけを`cmux workspace-group delete <id> --close-workspaces`で消す。`[dagq-e2e]`の名前ではworkerの手元のe2eと区別できないので、名前では選ばない。`E2E_SHARED`だけが一致しても別のqueueのgroupは消さない。
       - 全windowの一覧を取れなければcmuxのものは閉じず、次の関門に任せる。一覧の後に閉じられてenvを読めないworkspaceは、もう無いものとして飛ばす。workspaceを閉じる前にhashを`TMPDIR/.cleanup-queue-hashes.json`に保存するので、groupの削除だけが失敗しても次回に拾える。後始末に成功したら`TMPDIR`を消し、失敗したら残す。次の関門が始まる前に`<queue dir>/update/e2e`の下の残りを同じ手順で片付ける（名前の`<pid>`のprocessが生きているdir、つまり並んで走る`install`の関門のものは片付けない）。e2eが終わった後もそのprocess groupに残ったもの（stubの`sleep`など）はSIGKILLで止める。何をしたかは`cleanup`（`processes`・`workspaces`（閉じたworkspaceのID）・`groups`・`removed`・`errors`）に残す。
     - **流し直し**（[ADR-t1165-1](../../adr/2026-09-30-t1165-1-e2e-gate-reruns-failed-e2e-once-and-records-quarantined-failures.md)決定1、`e2e_gate::run`）: e2eが落ち、上限切れでなく、logに`test <name> ... FAILED`の行とlibtestのまとめの`test result: FAILED`の行があれば（`within`の上限で途中でexitしたe2eは結果の無いtestを残すので、まとめの行が無ければ流し直さない）、落ちたtestだけを同じcheckout・同じenv・同じ`CARGO_TARGET_DIR`で名前で絞って1回だけ流し直す（`cargo test --locked --test e2e -- --ignored --exact <name>…`。podmanで外したtestは落ちたtestに入らず、`--exact`は`--skip`も完全一致にするので`--skip`は付けない。`--e2e-command`には`DAGQ_E2E_RERUN=<name>…`（空白区切り）を渡して同じコマンドを流す）。上限は1回目とは別に同じ長さ（`--e2e-timeout`。e2eの実行部は最長でその2倍かかる）、後始末は1回目と同じで、`TMPDIR`は`<queue dir>/update/e2e/<unix時刻>.rerun-<pid>`。出力は1回目のlogの`.log`を`.rerun.log`にした`logs/update-<unix時刻>-<commit 12桁>.e2e.rerun.log`（`E2eSettings::rerun_log`）。流し直しで`test <name> ... ok`と出たtestだけが通ったとし、それ以外（`FAILED`や結果の出ないtest、上限切れと始められない（`error`）ときは流し直した全部）を流し直しでも落ちたtestとする（`E2eOutcome::rerun`の`E2eRerun`）。流し直しの上限切れと始められないときは印に依らず関門は落ちる。流し直しで通ったtestは不安定（flaky）とする。
     - **印**（決定2・3、`domain::e2e_quarantine`）: 関門が流すcheckoutの`.config/e2e-quarantine.toml`（`e2e_quarantine::FILE`。無ければ印は無い）を読む。走っている旧バイナリが読む`dagq.toml`には置かない。書式は`[[test]]`の配列で、どれも必須の`name`（cargoが出すe2eのtestの名前。`tests/e2e/`の下のmoduleのtestは`broker::…`のようにmoduleのpathを含む）・`reason`（文字列）・`task`（直すtaskのID、正の整数）・`until`（期限の日付`YYYY-MM-DD`。TOMLの日付か文字列。hostのlocalの日付でその日の終わりまで効く。offsetは`E2eSettings::utc_offset_secs`）を持つ。`#`のcommentと`"…"`（`\"`・`\\`・`\n`・`\t`）・`'…'`の文字列を読み、知らない表・key、欠けたkey、同じkeyや同じ`name`の重複は読めないファイルとする。

       ```toml
       [[test]]
       name = "up_in_cmux_starts_a_supervisor_in_a_workspace_that_down_wait_stops_and_closes"
       reason = "down --wait の workspace がときどき閉じない"
       task = 1120
       until = 2026-10-15
       ```

       `scripts/check-e2e-quarantine.sh`（CIが実行し、印を変えるtaskのverifyに付ける）がcommitの時点でこのファイルを検査する: 上の書式（`[[test]]`だけ、4つのkeyが1つずつ、`task`は正の整数、`until`は実在する日付）、`name`の重複、`name`のtestが`tests/e2e.rs`（moduleのpathを含む名前は`tests/e2e/<module>.rs`か`tests/e2e/<module>/`）に`#[test]`のfnとしてあること、印が`LIMIT`（3本）以下であることを見て、違反を名前か行つきで出してexit 1にする。期限切れの印は関門が効かせないだけなので警告を出してexit 0。ファイルが無ければexit 0。印の付け外しの規則は[testの制約](../../development/testing.md#e2eの印)が持つ。

       流し直しでも落ちたtestが全て効いている印を持てば関門は通り、そのtestは印で通した（quarantined）とする。印の無いtestが1つでも流し直しで落ちれば落ちる。効かない印: `until`を過ぎた印（`expired`）、印が上限`e2e_quarantine::LIMIT`（3本）を超えるファイルの全部の印（`over_limit`）、印の付いたtestが今回を含めて`e2e_quarantine::FAILURES_IN_A_ROW`（3回）続けて流し直しでも落ちた印（`failed_in_a_row`）。読めないファイルでは印を1つも効かせない。続けての失敗は、直前までの関門のevent（queueの`e2e_gate_events`の新しい順に最大`e2e_verdict::HISTORY`（200）件。runtimeがrunに流すe2eの`run_e2e_finished`（`outcome: passed`）と`run_e2e_failed`も関門として合わせて数える。ADR-t1233-2決定5）の`update_e2e_passed`と`stage: e2e`の`update_failed`（とrunのそれら）を新しい方から見て、`rerun.failed`にそのtestがある関門を数える（`e2e_verdict::failures_in_a_row`）。`rerun`があってそのtestが無い関門と、`rerun`の無い`update_e2e_passed`で数えるのをやめ、`rerun`の無い`update_failed`（上限切れ・始められない・古いruntimeの記録）と、`rerun`の`timed_out`がtrueか`error`のある関門（流し直しがtestについて何も言っていない）は飛ばす。印の有無に依らず数えるので、関門を落とした後もそのtestが流し直しで通るまで落ち続ける。判定は`application::e2e_verdict::judge`（自動更新のjobと`install`と、runtimeがrunに流すe2eが共有する。runのe2eは印をrunのworktreeではなくlanding branchの着地したcommitのtreeから読み、runが変えたtestと直すtaskの印を外す。[Review](review.md#着地の前のe2e)）。落ちたときの`error`と`update_failed`のaskの問いには、落ちたtest、流し直しでも落ちたtest、flaky・quarantinedのtest、印が効かなかったtestとその理由（`<name>: its mark expired after <until>`・`<name>: it failed the rerun of 3 gates in a row …`）とファイルの理由（`.config/e2e-quarantine.toml has 4 marks, more than 3`・`.config/e2e-quarantine.toml could not be read: …`）、1回目と流し直しのlogのpathが載る。

## dagqのソースのrepositoryだけ

リリースのバイナリ（`X.Y.Z`）で動く外部のprojectの更新は、source buildではなくcrates.ioのリリースの検知とaskで行う（[Release update](release-update.md)、ADR-t618-1）。jobの確認から見張りまでは同じ`put_in_place`（`src/application/update.rs`）を通る。

`up --auto-update`のsource buildは、queueのrepositoryがdagqのソースのときだけ動く（[ADR-t614-1](../../adr/2026-09-27-t614-1-dagq-source-only-features-by-one-check.md)）。ソースでないrepositoryでは`up --auto-update`がerrorで止まり、自動更新の設定を持つsupervisorもbuildに進まない。判定と対象の一覧は[Source repository](source-repository.md)にある。`up`はpreflightで`--auto-update`とソースでないrepositoryの組み合わせを`--auto-update builds dagq from the repository's sources, and <checkout> is not dagq's source (...); leave --auto-update off and update dagq with `cargo install dagq`, or with `dagq install --from <binary or checkout>`; the supervisor was not started`で止める（`lifecycle::auto_update_refused`）。登録の`auto_update`が真のsupervisorは、見る回ごとに判定し、ソースでなければ`update_failed`のaskの答えの適用もjobの起動もせずに戻り、ソースでなくなった最初の回だけ警告をlogに出す。続けてそのときのmainのheadを読み、`automatic update: main's <head> builds nothing: the repository is not dagq's source`をheadごとに1回出す（task 1048）。
