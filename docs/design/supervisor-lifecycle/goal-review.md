# Goal review (supervisor)

execの[引き継ぎ](handoff.md)を待つあいだに終わったjobと、`prepare_handoff`の時点で終わっていたjobは、捨てずに回収してverdictを適用する（task 1425。新しいjobは始めない）。走っていて止めたjobは、引き継いだsupervisorが最初のpassに入る前に自分のtokenの未完了行を`interrupted`（error: `stopped for the supervisor handoff`）で閉じる。候補が無くても閉じ、transcriptをtransactionの前に`read_before`で読んで既存のclose経路で区間の`session_closed`（`reason: job_finished`、model / effortを含む）を記録する。他のtokenの行は触らない。候補が残れば以後のpassでreviewをやり直し、interruptedはattemptに数えない（task 1087）。

[ADR-0047](../../adr/0047-irregularities-in-three-layers-recovery-job-ask-reasons-and-goal-review.md)の決定43（task 375）。所属taskがすべて終わったopenのgoalを、supervisorが起動するheadlessのgoal review jobがacceptanceと照合し、そのverdictと人のanswerをruntimeが適用する。use caseは`src/application/supervise/goal_review.rs`、storeは`src/infrastructure/goal_reviews.rs`（port `GoalReviewStore`）、verdict・answer・起動の条件の型は`src/domain/goal_review.rs`、promptは`prompt::goal_review_prompt`。plan reviewと同じくrun slotは使わず、loopの各passで進める（`goal_review_pass`。`--once`のloopは走っているgoal reviewを待つ）。drain中（`stop`、provisioningの失敗）は新しいgoal reviewを始めない（走っているjobとanswerの適用は続ける）。exec の引き継ぎを待つあいだも`goal_review_pass(false)`で終わったjobを回収して適用し、`prepare_handoff`は終わったjobを先に回収してから走っているjobだけを止め、その未完了の行は次のプロセスが`interrupted`で閉じて取り直す（task 1425）。

1. **記録**（schema v42、`migrations/0042_goal_reviews.sql`、compatible）: jobは`goal_reviews`の1行（`goal_id`、`attempt`、`supervisor_token`、`fingerprint`、`dir`、`started_at`、`finished_at`、`outcome` = `achieved` / `gaps` / `ask` / `failed` / `interrupted`、`verdict`のJSON、`error`、`ask_id`、`rearmed_at`）。互換のmigrationは外部キーとunique indexを持てないので、同時に1つは`begin_goal_review`が`BEGIN IMMEDIATE`の中で生きているsupervisorの未完了の行が無いことを確かめてから行を書くことで守る（queue全体で1つ。plan reviewとは別に数える）。行の無いsupervisorの未完了の行は`interrupted`で閉じる。eventはgoalに記録する（`run_events.goal_id`）。askのkindに`approve_goal`を足した（kindにmigrationは要らない）。jobのpromptと出力はqueueの`goal-reviews/<行のID>/`（`prompt.txt`、`review.out`、`review.err`）。
2. **起動の条件**（`goal_review_candidates`、ID順の先頭を取る）: goalが`open`で閉じておらず、所属taskが1件以上あり、すべて`completed`か`canceled`で`completed`が1件以上（`goal_review::tasks_done`。`draft` / `submitted`のtask、つまりruntimeのplannerの待ち・`keep_draft`で残ったdraft・閉じていない`planner_question`の対象は、これで除かれる）、元goalがこのgoalのfollow_up（所属は問わない）に所属の判断が済まないもの（`completed` / `canceled`でなく、判断が無い・undecided・要再確認・requiredなのにgoalの外。[Follow-up membership judgements](../follow-up-membership.md)の「閉じる条件」、ADR-t1504-2決定8）が無く、goalのreviewが開いた`approve_goal`のaskで閉じていないものが無く、前回のgoal review（`interrupted`を除く最新の行）の後に入力が変わっている。out_of_scopeと判断して別のgoalへ移したfollow_upの未完了は起動を妨げない。所属taskの条件を満たし、follow_upの所属の判断だけで起動しないgoalは、`status`のattentionに`goal_follow_ups_unsettled`（`next: request a plan for the follow-ups of goal G`、止めているfollow_upのtask IDと理由の分類`unjudged` / `undecided` / `needs_recheck` / `required_outside`）として1件出る。runtimeのplannerが扱う途中の判断の無いdraft、`draft_planner_exhausted`のdraft、closeされていないaskのあるtaskはそれぞれの項目に任せて数えず、6の`goal_review_failed`で人を待つgoalには出さない。判断が記録されれば消える（[`status`](status.md)のattentionの一覧、task 1660）。入力は`fingerprint`（`goal_review::review_fingerprint`。taskのIDとstatusをID順に並べた文字列に、acceptanceの版が1でなければ`;acceptance:<版>`を、元goalがこのgoalのfollow_upがあれば`;follow_ups:`とその`<task>:<最後の判断の行のid>-<分類>`（判断が無ければ`-`）をtask順に足したもの。どちらも無いgoalは所属taskだけの今までの文字列のまま。follow_upのある（終わったものを含む）goalとacceptanceの版が1でないgoalは、この形になった後に一度取り直される）で比べ、同じなら起動しない。follow_upの登録、判断の記録・訂正、acceptanceの変更は入力を変える。goalの外のfollow_upのstatusは入れない（範囲外の作業が進んでもreviewを無効にしない。終わったかは閉じる条件が見る）。人の`goal review ID`（`rearm_goal_review`）は最新の行に`rearmed_at`を書き、状態が同じでも起動させる（`goal_review_rearmed`）。openでないgoalには打てない（`goal_review::rearmable`）。取るかどうかは副作用の無い`goal_review::reviewable`、失敗の後に人を待つかは`goal_review::waits_for_a_person`が決め、storeは行から読んだ値を渡す。
3. **起動**（`start_goal_review`）: `[roles.goal_review]`から起動の`launch`を決め（[Actor model](actor-model.md)。表が無ければ今までと同じくmodel / effortを渡さない）、`goal_review_started`（`goal_review_id`、`attempt`、`dir`、`tasks`（fingerprint）、`gaps_in_a_row`、`session_id`、`cwd`、`launch`）を書き、jobをactor executor（[Roles](roles.md#actorの起動actorexecutor)）の`HeadlessProgram::Job`（`repo_root`、権限の意図`GOAL_REVIEW_ACCESS`＝`read_files_and_queue_cli`。Claude Codeは`--allowedTools Read Grep Glob Bash(dagq:*)`に訳す。[Agent provider lifecycle](../provider-lifecycle.md#headless-jobのinterface)）で起動する。`session_id`は`begin_goal_review`が行と同じトランザクションで作るUUIDで、jobにそのまま渡す（ADR-0048の決定4、Claude Codeには`--session-id`）。`cwd`はjobを起動したrepositoryのcheckout、`launch`は`{"role": "goal_review", "provider": "claude", "model", "effort", "source"}`（task 1062）。jobの区間（kind `goal_review`）は`goal_review_started`で開き、同じ`goal_review_id`の`goal_review_finished` / `goal_review_failed`で閉じ（`job_finished`）、行を`interrupted`で閉じたとき（supervisorが居ない行は`inferred`、goalかtaskが変わったときは`job_finished`）にも閉じる。区間のeventはgoalの最初のtask（approve_goalのaskと同じ）に記録し、payloadに`goal_id`・`goal_ids`（`[goal_id]`。`stats --goal`の絞り込み）・`goal_review_id`・`launch`を持つ。`session_closed`はtranscriptから読んだ実際の`model` / `effort`を持つ（[Agent provider lifecycle](../provider-lifecycle.md#claude-sessionの区間)）。task 1062より前のgoal reviewは`session_id`も`launch`も無く、区間も無い。envは`actor_env`の`DAGQ_ROLE=goal-review-job`・`DAGQ_ACTOR_ID=goal-review-job:<goal id>:<attempt>`と、queue serviceのsocketとjobのtokenのfile（`DAGQ_QUEUE`は渡さず、jobの`dagq`はクライアントモードでserviceに送る。[Queue service](../queue-service.md#クライアントモード)。CLIは読み取りだけを許す。[Roles](roles.md#actors)）。時間の上限はreviewの`review_timeout`。起動できなければ下の6の失敗にする。
   - **provider**（[ADR-t1063-1](../../adr/2026-09-29-t1063-1-headless-job-provider-per-role-with-intent-permissions.md)、task 1065）: 行き先は`PlanningState::goal_review_route`が`starting`のpassごとに、supervisorの状態を値で渡した副作用の無い`goal_review_route_of`（providerの控えは`provider_held_of`、使えない理由は`job_unusable_of`、失敗したjobの壁と控えは`job_failure_route`）で決める。`[roles.goal_review]`に`provider`が無ければ今までどおりClaudeで、Claudeの控えのaskが開いている間は起動しない。`provider`があれば`domain::actor_model::job_route`で、そのproviderが使えれば（supervisorにagentがあり、`Supervisor::provider_held`が控えを言わない）そこで、使えなければもう一方のprovider（goal reviewはClaudeでもCodexでも動く）が使えればそこで（launchに`switched_from`・`switch_reason`。modelとeffortは渡さない）、どちらも使えなければ起動しない。`[provider_fallback] jobs = false`（[ADR-t1857-1](../../adr/2026-10-06-t1857-1-provider-fallback-can-be-turned-off-for-workers-and-jobs.md)、task 1858）のときは、使えない理由（実行ファイルが無い・起動できない・認証・利用上限）ではもう一方で起動せず、控えが解けるのを待って同じproviderで起動する（`--no-claude`ではClaudeを書いた役割も今どおりCodexで起動する。[Provider lifecycle](../provider-lifecycle.md#使えないproviderからの切り替え)の「切り替えを止める設定」）。Codexのjobは`Ports::codex_jobs`（supervisorが見つけて`--version`の通ったCodex）で`codex exec --json --skip-git-repo-check --sandbox read-only -C <repo_root> [-m <model>] [-c model_reasoning_effort="<effort>"]`として組み（promptはargvでなくstdin。task 1560。[Agent provider lifecycle](../provider-lifecycle.md#headless-jobのinterface)の「promptの渡し方」）、executorが`--sandbox read-only`を、`:read-only`を継いでqueue serviceのsocketだけを許すpermission profile `dagq_job`の`-c`に置き換えて起動する（[Agent provider lifecycle](../provider-lifecycle.md#codexのheadless-job)、[Queue service](../queue-service.md#codexのsandboxからの到達adr-t1233-5決定4)）。envは同じ`actor_env`で、sandboxの中の`dagq`も`goal-review-job`のroleで読むだけ。Codexのjobは`session_id`を受け取らないので、`goal_review_started`の`session_id`はnullで、`launch`は`{"role": "goal_review", "provider": "codex", "model", "effort", "source"}`。`headless_jobs.provider`も行き先のprovider
4. **入力**（`goal_review_material`）: goalのtitle・description・acceptance・constraints・doc、goalのfollow_up（`goal show`の`follow_up_memberships`: 元goalかgoalの所属のfollow_upごとの今の所属・status・材料・深さ・判断の履歴（分類・項目・理由・証拠・判定時と今の版・`needs_recheck`））、所属taskのそれぞれのid・title・status・description・acceptance・`duplicate_of`（重複でcancelした先）、`integrated`のrunがあればその`run_id`・`result_commit`とreceiptの`summary`・`tests` / `e2e` / `subagent_review`の`status`と`evidence_or_reason`・`follow_ups`（読めなければ`(receipt unavailable)`）、goalのevent（`observation`（note）、`goal_updated`、`goal_decided`、`goal_review_rearmed`）、前回までのgoal review（`goal_reviews`: 行ごとのattempt・outcome・verdict・error）、`gaps`が続いた回数。jobはmain checkoutの文書とsource、`dagq show` / `dagq goal show --full` / `dagq findings` / `dagq events --goal` / `dagq search`で残りを読む。 promptの渡し方・節ごとと全体の上限・省いたことの明示・byte数の記録は[Prompt](prompt.md#headlessのjobのprompt)の「headlessのjobのprompt」の節が持つ（[ADR-t1566-1](../../adr/2026-10-03-t1566-1-headless-job-prompts-carry-decision-material-within-limits.md)。ADR-0047決定43の入力の列挙をamendsした）。今はstdinで渡し（task 1560。[Agent provider lifecycle](../provider-lifecycle.md#headless-jobのinterface)の「promptの渡し方」）、全体と節ごとの上限を持つ（task 1571。`goal_review_prompt`）: 全体`GOAL_REVIEW_PROMPT_LIMIT`（200,000 byte、言語の指示を含む）、goal（必須。超えたら長い欄から切り、`over_limit`に書く）、所属task（着地したtaskを新しい順に、続けて残りを新しい順に選び、1件ずつも切る。省いたtaskはID・title・status・着地したかの要約の行にして、件数と`dagq show ID --full`・`dagq events --full --task ID --kind integration_receipt`を書く）、follow_up・note・前回のreview（新しい順）。値と理由は[Prompt](prompt.md#goal-reviewrunのreview復旧jobruntimeのplannerの上限)、読むコマンドは`prompt::GOAL_REVIEW_READS`。切った項目は`cut`に省いたbyte数と読み方を持つ。promptのbyte数は6・下の`goal_review_finished` / `goal_review_failed`の`prompt_bytes`（plan reviewと同じ形）に記録する。promptは、out_of_scopeと判断したfollow_upを達成の判定に含めず（その作業を待たず、gapにもしない）、requiredと判断したものは所属taskと同じく判定に含めるよう指示する（ADR-t1504-2）。
5. **verdict**（`GoalReviewVerdict`、stdoutの最後のJSON object）: `{"verdict": "achieved" | "gaps" | "ask", "criteria": [{"criterion", "met", "evidence": [...]}], "gaps": [{"title", "description", "criterion"}], "summary", "question", "options": [...], "reason_category": "scope" | "discard"}`。`gaps`はgapが1件以上で、titleが空でないこと（満たさなければ失敗）。runtimeは`goal_review::decide`で、同じgoalで`achieved` / `gaps` / `ask`のうち直近から続いた`gaps`の数（`gaps_in_a_row`。storeが行のoutcomeを新しい順に読み、`goal_review::gaps_in_a_row`が数える）が`MAX_GOAL_GAPS`（3）以上の`gaps`を`ask`に変える（`overridden`に理由）。適用（`finish_goal_review`）は1トランザクションで、jobの行がまだ自分のもので、goalがopenのままで、2のfingerprint（所属task・acceptanceの版・follow_upとその判断）が起動時と同じで、まだ2の条件（所属taskがすべて終わり、follow_upの所属の判断が済んでいる）を満たすことを再検査し、崩れていれば`interrupted`（`the goal or its tasks changed during its review`）で閉じて何もしない（`interrupted`は前回に数えないので、条件がそろえば取り直す）。reviewの間のfollow_upの登録、判断の記録・訂正、acceptanceの変更の後のverdictはこれで使われない。検査はtransactionの中のqueueの状態だけで行うので、execの引き継ぎで回収したverdict（task 1425）も、supervisorの再起動の後も、同じ`finish_goal_review`で同じ結果になる。
   - **achieved**: `goal close --verdict achieved`と同じ`goal::close`と`goal::check_follow_ups`でgoalを閉じる（`close_goal_in`）。`goal_closed`のpayloadに`by: "goal_review"`、`goal_review_id`、`reason`（verdictの`summary`）を足す。
   - **gaps**: 各gapを、そのgoalの`draft`のtaskとして登録する（title、descriptionに`Missing for the goal's acceptance: <criterion>`を足したもの、acceptanceは空、contextは`goal_gap: goal review <行のID> of goal <ID> found this missing`）。`draft_origins`に出どころ`goal_gap`と材料`{"goal_id", "goal_review_id", "criterion", "summary"}`を書くので、以後は[Draft planners](draft-planners.md)の経路でruntimeのplannerが採否を決める。goalは開けたまま。draftがある間は2の条件を満たさず、draftが終われば（採用されて着地する、cancelされる）状態が変わって再び起動する。
   - **ask**: inbox宛ての`approve_goal`のaskを、goalの最初のtask（IDの最小）について作る（runは無い）。`reason_category`はverdictの`discard`ならそれ、ほかは`scope`。questionは`Goal <ID>: <question（空ならsummary）>`に、`overridden`の理由、`met: false`の項目、verdictのgapのtitleを足したもの。optionsは`GOAL_OPTIONS`（`achieved` / `abandoned` / `gaps` / `keep_open`）にverdictの`options`を重ならないように足す。askのIDを行の`ask_id`に書く。作ったaskは誰にも通知を送らず、inboxは`watch --role inbox`の`ask_opened`で受ける。
   - どのverdictも`goal_review_finished`（`goal_review_id`、`attempt`、`verdict`、`decision`、`overridden`、`criteria`、`summary`、`gaps`、`gap_tasks`（登録したdraftのID）、`ask_id`、`duration_secs`、`prompt_bytes`（4。task 1571））を記録する。Codexのjobは加えて`session_id`（`thread.started`のthreadのid）・`model`（threadのrolloutのjobの開始以降の`turn_context`の`model`）・読めなければ`model_unknown`（理由）を持つ（`AgentProvider::job_session`、`JobSession::record`）。verdictはproviderによらず、providerの実装が取り出した最終の返答のtext（Codexは最後の`agent_message`）を同じ`GoalReviewVerdict::parse`と同じ`finish_goal_review`の再検査で適用する。ADR-0047の決定43の「`criteria`を`goal_reviewed`のpayloadに記録」は、このeventの`criteria`で持つ。
6. **失敗**（非0の終了、時間切れ、JSONが無い・形が合わない、起動できない）: goalを動かさず、行を`failed`にして`goal_review_failed`（`code: job_failed`、`goal_review_id`、`attempt`、`error`、`duration_secs`、`reason_category: recovery_failed`、promptを書いた後なら`prompt_bytes`（4。task 1571））を記録する。2のfingerprintが同じなので、2の入力が変わる（所属taskの状態の変化、follow_upの登録、所属の判断の記録・訂正、acceptanceの変更）か人が`goal review ID`を打つまで起動しない。そのあいだ`goal_review_holds`がそのgoalを返し、`status`（inbox）のattentionに`kind: goal_review_failed`、`next: goal review by hand`、`reason_category: recovery_failed`、goalの最初のtaskとして出る（`last_error`は`goal <ID>: <error>`）。人はgoalを`goal close`で閉じるか、plannerでtaskを足すか、`goal review ID`で取り直させる。
   - **使えないprovider**（ADR-t1063-1の決定4・5、task 1065）: `[roles.goal_review]`に`provider`を書いたときだけ。jobの起動の失敗（`job_start_failure`: `executable_missing` / `launch_failed`。引数・envの大きさによる`E2BIG`と、promptをstdinに渡す一時ファイルを用意できない`StdinUnprepared`は、jobの入力かsupervisorの環境の問題として`other`にし、providerを控えずにそのjobの一般の失敗にする。task 1560）か、verdictの無い失敗のjobの出力の分類（`Supervisor::job_failure`: `authentication` / `usage_limit` / `launch_failed`）がproviderを使えないと言えば、Claudeの認証・利用上限は今までどおり控えのaskを開いてjobを`affected`に足し、それ以外（Codexのどれも、Claudeの起動の失敗）は`hold_provider`で`ProviderHold`に控える（`provider_held`、`run_id`はnull）。その上で`goal_review_failed`に`provider_unusable`（`{"provider", "reason"}`）を足し、行を`failed`でなく`interrupted`で閉じる。`interrupted`の行は2の「前回のgoal review」に数えないので、goalはすぐ候補に戻り、次のpassで3の行き先（もう一方のprovider、両方控えられていれば起動しない。`[provider_fallback] jobs = false`なら控えが解けるまで起動せず、解けた後に同じprovider）で起動し直す（新しい行、同じ`attempt`）。offでも失敗の分類・控え（控えるのは失敗したproviderだけ）・Claudeの控えのaskは同じで、`job_failure_route`は控えるかだけを`provider`を書いたことで決める。`goal review by hand`のattentionにもならない（`status`は`goal_review_holds`が`interrupted`の行を返さず、`watch` / `events`は`event_attention`が`provider_unusable`を持つ`goal_review_failed`をattentionにしない）。起動の失敗のうちjob自身の用意（directory、promptの組み立てと書き込み）の失敗はproviderの判定に使わず、一般の失敗にする。利用上限の控えの解ける時刻は、失敗の文とjobのstdout（Codexの`turn.failed`）から読む。一般の失敗（非0の終了、時間切れ、verdictが読めない、modelの誤り）は切り替えず、上のとおり`failed`で人を待つ。`provider`を書かないgoal reviewは今までどおりで、Claudeの壁ではaskに足され、`failed`で閉じる（askの`done`がrearmする）
   - Codexのjobの`goal_review_failed`も、読めれば`session_id`・`model`・`model_unknown`を持つ

## taskの再計画による置換元（予定・未実装）

[taskの再計画](task-replanning.md#goal-reviewとgoal-close予定未実装)は、置換元の`replaced`を再置換先も辿った全ての葉が`completed`か`canceled`になったときだけ終了条件上の解決済みとして扱う予定の契約を持つ。置換元はcompletedの件数に加えず、子の着地と元条件の対応をgoal reviewの入力に載せる。起動・achievedの適用・`approve_goal`のanswer・`goal close --verdict achieved`は同じ系統の再検査を行い、fingerprintには置換関係と条件対応の版も含める。既存のfollow-upの所属判断などは維持する。ADR-t1521-2決定5がADR-0047決定8・43をamendsするもので、現行の2・4・5の実装はまだこの置換を扱わない。
