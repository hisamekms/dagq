# Goal review (supervisor)

[ADR-0047](../../adr/0047-irregularities-in-three-layers-recovery-job-ask-reasons-and-goal-review.md)の決定43（task 375）。所属taskがすべて終わったopenのgoalを、supervisorが起動するheadlessのgoal review jobがacceptanceと照合し、そのverdictと人のanswerをruntimeが適用する。use caseは`src/application/supervise/goal_review.rs`、storeは`src/infrastructure/goal_reviews.rs`（port `GoalReviewStore`）、verdict・answer・起動の条件の型は`src/domain/goal_review.rs`、promptは`prompt::goal_review_prompt`。plan reviewと同じくrun slotは使わず、loopの各passで進める（`goal_review_pass`。`--once`のloopは走っているgoal reviewを待つ）。drain中（`stop`、provisioningの失敗）は新しいgoal reviewを始めない（走っているjobとanswerの適用は続ける）。exec の引き継ぎ（`prepare_handoff`）はjobを止め、未完了の行は次のプロセスが`interrupted`で閉じて取り直す。

1. **記録**（schema v42、`migrations/0042_goal_reviews.sql`、compatible）: jobは`goal_reviews`の1行（`goal_id`、`attempt`、`supervisor_token`、`fingerprint`、`dir`、`started_at`、`finished_at`、`outcome` = `achieved` / `gaps` / `ask` / `failed` / `interrupted`、`verdict`のJSON、`error`、`ask_id`、`rearmed_at`）。互換のmigrationは外部キーとunique indexを持てないので、同時に1つは`begin_goal_review`が`BEGIN IMMEDIATE`の中で生きているsupervisorの未完了の行が無いことを確かめてから行を書くことで守る（queue全体で1つ。plan reviewとは別に数える）。行の無いsupervisorの未完了の行は`interrupted`で閉じる。eventはgoalに記録する（`run_events.goal_id`）。askのkindに`approve_goal`を足した（kindにmigrationは要らない）。jobのpromptと出力はqueueの`goal-reviews/<行のID>/`（`prompt.txt`、`review.out`、`review.err`）。
2. **起動の条件**（`goal_review_candidates`、ID順の先頭を取る）: goalが`open`で閉じておらず、所属taskが1件以上あり、すべて`completed`か`canceled`で`completed`が1件以上（`goal_review::tasks_done`。`draft` / `submitted`のtask、つまりruntimeのplannerの待ち・`keep_draft`で残ったdraft・閉じていない`planner_question`の対象は、これで除かれる）、goalのreviewが開いた`approve_goal`のaskで閉じていないものが無く、前回のgoal review（`interrupted`を除く最新の行）の後に所属taskの状態が変わっている。状態は`fingerprint`（taskのIDとstatusをID順に並べた文字列）で比べ、同じなら起動しない。人の`goal review ID`（`rearm_goal_review`）は最新の行に`rearmed_at`を書き、状態が同じでも起動させる（`goal_review_rearmed`）。openでないgoalには打てない。
3. **起動**（`start_goal_review`）: `goal_review_started`（`goal_review_id`、`attempt`、`dir`、`tasks`（fingerprint）、`gaps_in_a_row`）を書き、jobを`reviewer.headless_command(repo_root, prompt, PLAN_REVIEW_TOOLS)`（Read / Grep / Glob / `Bash(dagq:*)`）で起動する。envはreview jobと同じ`job_env`（`DAGQ_ROLE=reviewer`。CLIは読み取りだけを許す）。時間の上限はreviewの`review_timeout`。起動できなければ下の6の失敗にする。
4. **入力**（`goal_review_material`）: goalのtitle・description・acceptance・constraints・doc、所属taskのそれぞれのid・title・status・description・acceptance・`duplicate_of`（重複でcancelした先）、`integrated`のrunがあればその`run_id`・`result_commit`とreceiptの`summary`・`tests` / `e2e` / `subagent_review`の`status`と`evidence_or_reason`・`follow_ups`（読めなければ`(receipt unavailable)`）、goalのevent（`observation`（note）、`goal_updated`、`goal_decided`、`goal_review_rearmed`）、前回までのgoal review（`goal_reviews`: 行ごとのattempt・outcome・verdict・error）、`gaps`が続いた回数。jobはmain checkoutの文書とsource、`dagq show` / `dagq goal show --full` / `dagq findings` / `dagq events --goal` / `dagq search`で残りを読む。
5. **verdict**（`GoalReviewVerdict`、stdoutの最後のJSON object）: `{"verdict": "achieved" | "gaps" | "ask", "criteria": [{"criterion", "met", "evidence": [...]}], "gaps": [{"title", "description", "criterion"}], "summary", "question", "options": [...], "reason_category": "scope" | "discard"}`。`gaps`はgapが1件以上で、titleが空でないこと（満たさなければ失敗）。runtimeは`goal_review::decide`で、同じgoalで`achieved` / `gaps` / `ask`のうち直近から続いた`gaps`の数（`gaps_in_a_row`）が`MAX_GOAL_GAPS`（3）以上の`gaps`を`ask`に変える（`overridden`に理由）。適用（`finish_goal_review`）は1トランザクションで、jobの行がまだ自分のもので、goalがopenのままで、所属taskのfingerprintが起動時と同じで、まだすべて終わっていることを再検査し、崩れていれば`interrupted`（`the goal or its tasks changed during its review`）で閉じて何もしない（次の起動を待つ）。
   - **achieved**: `goal close --verdict achieved`と同じ`goal::close`でgoalを閉じる（`close_goal_in`）。`goal_closed`のpayloadに`by: "goal_review"`、`goal_review_id`、`reason`（verdictの`summary`）を足す。
   - **gaps**: 各gapを、そのgoalの`draft`のtaskとして登録する（title、descriptionに`Missing for the goal's acceptance: <criterion>`を足したもの、acceptanceは空、contextは`goal_gap: goal review <行のID> of goal <ID> found this missing`）。`draft_origins`に出どころ`goal_gap`と材料`{"goal_id", "goal_review_id", "criterion", "summary"}`を書くので、以後は[Draft planners](draft-planners.md)の経路でruntimeのplannerが採否を決める。goalは開けたまま。draftがある間は2の条件を満たさず、draftが終われば（採用されて着地する、cancelされる）状態が変わって再び起動する。
   - **ask**: inbox宛ての`approve_goal`のaskを、goalの最初のtask（IDの最小）について作る（runは無い）。`reason_category`はverdictの`discard`ならそれ、ほかは`scope`。questionは`Goal <ID>: <question（空ならsummary）>`に、`overridden`の理由、`met: false`の項目、verdictのgapのtitleを足したもの。optionsは`GOAL_OPTIONS`（`achieved` / `abandoned` / `gaps` / `keep_open`）にverdictの`options`を重ならないように足す。askのIDを行の`ask_id`に書く。作ったaskはplan reviewと同じくinboxに通知する。
   - どのverdictも`goal_review_finished`（`goal_review_id`、`attempt`、`verdict`、`decision`、`overridden`、`criteria`、`summary`、`gaps`、`gap_tasks`（登録したdraftのID）、`ask_id`、`duration_secs`）を記録する。ADR-0047の決定43の「`criteria`を`goal_reviewed`のpayloadに記録」は、このeventの`criteria`で持つ。
6. **失敗**（非0の終了、時間切れ、JSONが無い・形が合わない、起動できない）: goalを動かさず、行を`failed`にして`goal_review_failed`（`code: job_failed`、`goal_review_id`、`attempt`、`error`、`duration_secs`、`reason_category: recovery_failed`）を記録する。2のfingerprintが同じなので、所属taskの状態が変わるか人が`goal review ID`を打つまで起動しない。そのあいだ`goal_review_holds`がそのgoalを返し、`status`（inbox）のattentionに`kind: goal_review_failed`、`next: goal review by hand`、`reason_category: recovery_failed`、goalの最初のtaskとして出る（`last_error`は`goal <ID>: <error>`）。人はgoalを`goal close`で閉じるか、plannerでtaskを足すか、`goal review ID`で取り直させる。
7. **answer**（`goal_answers` → `decide_goal`、1トランザクション）: `GoalAnswer::parse`で`achieved` / `abandoned` / `keep_open` / `gaps` / `gaps: <足りないもの>`を読む。適用できるのは、goalが閉じておらず、`achieved`は所属taskがすべて終わり、`abandoned`は`in_progress`が無く、`gaps`はreviewのverdictにgapがあるとき（`gaps: <text>`はtextの1行目（100文字まで）をtitle、全文をdescriptionにした1件のgap）。適用するとaskを閉じ、`goal_decided`（`ask_id`、`goal_review_id`、`answer`、`decision`、`verdict`（閉じたとき）、`gap_tasks`）を記録する。`achieved` / `abandoned`はgoalを閉じ（`goal_closed`に`by: "person"`、`ask_id`、`goal_review_id`）、`gaps`は5と同じ手順でdraftを登録し、`keep_open`は何もしない（2のfingerprintが同じなので、所属taskの状態が変わるまで起動しない）。goalが先に閉じていたらaskを閉じ、`ask_closed`（`ask_id`、`kind`。task 568）だけを記録する。適用できないanswer（verdictが足した独自のoption、書き足しの自由文、条件の崩れた`achieved`など）は閉じずに残し、inboxの人が読んで`ask close`する。`goal_answers`は答えた時点の`ask_answered`が`runtime_delivers: true`のaskだけを返すので、inboxに渡したanswerを後で条件がそろってからruntimeが適用することはない。`keep_open`はgoalの行の`rearmed_at`を消す（askの前に打たれた`goal review ID`で直ちに取り直さないため）。`ask_answered`の`runtime_delivers`と`status`のattention（`applying the answer of ask N (runtime)`）は同じ判定（`goal_answer_applies` / `applies_goal_answer`）で決まる。
8. **plannerの役割**: plannerはgoalの完了を見てcloseする役を持たない（ADR-0047の決定16の最後の項）。`goal close`は人の判断（人が開いたplannerでの対話、askのanswer）のために残る。

testは`tests/it/goal_review.rs`（plan reviewのstub providerがverdictを出す。achieved・gapsとその後の再起動・4回目のgapsのask・askのanswer（`gaps` / `keep_open` / `abandoned` / 適用しないoption）・失敗と`goal review ID`・起動しないgoal）と、`src/domain/goal_review.rs`・`src/application/supervise/goal_review.rs`のunit test。runtimeの他のtestが使う`TestReviewer`（`tests/it/runtime_support`）はgoal reviewを起動させず失敗にするので、goalのtaskを着地させるtestではgoalは開いたまま残る。
